# v0.4 canvas-mvp — spec

**Branch:** `v0.4/canvas-mvp` · **Direction doc:** `docs/canvas-vision.md` (reviewers: check
§Future contracts below against it) · **Evidence:** `docs/research/2026-06-12-canvas-spike-results.md`
(measured, binding) + `docs/research/2026-06-11-canvas-architecture-synthesis-v2.md` (synthesis).

## Goal

A second, peer view of the same notes: an infinite pannable/zoomable 2D surface where notes appear
as live DOM cards the user places and arranges by hand. Curated (starts empty), manual-first, with
the architecture seams that make the far-zoom dot tier, the dock shell, and threads the natural
next steps rather than rewrites.

## Non-goals (v0.4)

Explicitly out, all recorded with direction in `docs/canvas-vision.md`: user-facing title/dot
tiers · edge creation/interaction (display only) · force/auto layout of any kind · switchable
arrangements UI (#96) · multiple canvases UI · threads/nested canvases · channels/multiple feeds ·
PDFs · canvas layers · ink on canvas · persisted undo/redo tree · right dock, tab strips with ≥2
tabs, tab dragging · collapsed shelf strip · minimap (ruled out permanently — dot tier takes the
job) · saved workspaces · canvas accessibility mirror (the feed remains the accessible path;
revisit post-MVP) · touch/pen input.

## Product decisions (locked in brainstorm 2026-06-12/13)

1. Entry door: Feed|Canvas segmented toggle (top bar), two peer full-window stage views. `⌘1`
   feed, `⌘2` canvas. Canvas keeps its camera between visits (persisted per canvas).
2. One canvas. `canvas_id = 'root'` everywhere; opaque TEXT key; **no canvases table** (vision
   principle 3).
3. Curated start: empty until the user places notes. No auto-seeding ever at card tier.
4. Placement debt is visible (status bar "N unplaced ●"), placement itself is deliberate.
5. A canvas card is the live note (one row, two projections). The ▦ chip marks placedness in
   feed/picker/shelf surfaces; clicking a ▦ chip jumps to the card.
6. `content-visibility` is banned on canvas surfaces (spike: 11–15 fps, actively harmful under
   animated transforms).

## §1 Schema (migration `0003_canvas.sql`)

```sql
-- v0.4 canvas. Layouts are view-state: positions live here, never on notes.
-- canvas_id/arrangement_id are opaque text keys, constant in v0.4
-- ('root'/'manual') — see docs/canvas-vision.md principles 3 & 4.
CREATE TABLE node_layouts (
  canvas_id      TEXT    NOT NULL,
  arrangement_id TEXT    NOT NULL DEFAULT 'manual',
  note_id        TEXT    NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  x              REAL,            -- NULL = on the shelf (queued, unplaced)
  y              REAL,
  created_at     INTEGER NOT NULL,  -- when the row appeared (shelved or placed)
  placed_at      INTEGER,           -- first time x/y were set; NULL while shelved
  updated_at     INTEGER NOT NULL,
  PRIMARY KEY (canvas_id, arrangement_id, note_id),
  CHECK ((x IS NULL) = (y IS NULL))
);
-- no extra canvas index: the PK already serves the (canvas_id, arrangement_id) prefix

CREATE TABLE canvas_state (
  canvas_id  TEXT    PRIMARY KEY,
  camera_x   REAL    NOT NULL DEFAULT 0,
  camera_y   REAL    NOT NULL DEFAULT 0,
  zoom       REAL    NOT NULL DEFAULT 1,
  updated_at INTEGER NOT NULL
);
```

- **Shelf membership = layout row with `x IS NULL`.** Placing sets `x`,`y`,`placed_at`. Removing
  from canvas deletes the row. "N unplaced" = `COUNT(*) WHERE x IS NULL`.
- World coordinates: `x`,`y` are the card's top-left in world space (unbounded REAL). Zoom is a
  pure camera property — never stored per node.
- Soft-delete interplay: all canvas queries join `notes` and filter `deleted_at IS NULL`. The
  "delete note" verb (soft delete) must also delete the note's layout rows in the same
  transaction — a layout row for a soft-deleted note is a bug, not a tombstone. FK CASCADE covers
  hard deletes only.
- Timestamps INTEGER epoch-ms, matching 0001/0002 convention.

## §2 IPC surface (Zod at the boundary, like 0002's media channels)

All channels validated main-side with Zod; renderer access via preload `window.api.canvas.*`.
**Every** layout channel takes `canvasId` AND `arrangementId` (callers pass the constants — the
constants live in ONE shared module, `src/shared/canvas.ts`: `ROOT_CANVAS_ID = 'root'`,
`MANUAL_ARRANGEMENT_ID = 'manual'`). Write channels re-check note liveness
(`deleted_at IS NULL`) inside their transaction and skip dead notes.

| channel | args (all + `canvasId`, `arrangementId`) | returns | notes |
|---|---|---|---|
| `canvas:listLayouts` | — | all layout rows (placed + shelved), live notes only | one query; renderer splits placed/shelved |
| `canvas:edges` | — | `[{fromNoteId, toNoteId, edgeType}]` for links whose BOTH endpoints are placed here | resolves `to_slug` → live note id main-side; read-only (§11) |
| `canvas:shelveNote` | `{noteId}` | ok | INSERT OR IGNORE (no-op if row exists, placed or shelved) |
| `canvas:placeNote` | `{noteId, x, y}` | ok | upsert: shelved→placed or fresh place; sets `placed_at` if currently NULL |
| `canvas:moveNotes` | `{moves: [{noteId, x, y}]}` | ok | one transaction (group drag, nudge); move-semantics over existing placed rows |
| `canvas:unplaceNotes` | `{noteIds: []}` | ok | x/y/`placed_at` → NULL (back to shelf); used by undo-of-place-from-shelf |
| `canvas:restoreLayouts` | `{rows: [{noteId, x, y, createdAt, placedAt}]}` | ok | full-row upsert preserving timestamps; used by undo-of-remove; one transaction |
| `canvas:removeNotes` | `{noteIds: []}` | ok | deletes rows; one transaction |
| `canvas:getState` / `canvas:setState` | camera | camera | keyed by `canvasId` only; debounced renderer-side (below) |
| `canvas:recentOnCanvas` | `{limit}` | `[{noteId, kind: 'edited'\|'placed'\|'created', at}]` | see recency rule below |

**Recency rule:** `at = max(notes.updated_at, placed_at)`. `kind = 'created'` iff the note was
born on this canvas and not edited since — detectable because the §7 creation transaction stamps
`notes.created_at`, `notes.updated_at`, and `placed_at` with the **same** millisecond value;
otherwise `'edited'` if `updated_at` is the max, else `'placed'`.

Persistence cadence (research §5, binding): never write per drag-frame. In-memory + transform
during drag; **flush on drop**, on view switch away from canvas, and on app quit. Camera writes
debounced ≥500 ms and flushed on the same three events.

## §3 Stage view: world transform, culling, cards

- **Layer sandwich** (one shared world transform, top to bottom): DOM card layer (absolutely
  positioned children of a single transformed container) → canvas-2D **underlay** (edges now,
  dev-dots now, title/dot tiers + ink later). Underlay redraws via rAF, dirty-flagged: redraw on
  camera change, drag frames, layout/link data change; otherwise idle.
- **Camera:** `{x, y, zoom}`; zoom about the cursor; user zoom clamped to **[0.5, 2.0]** in v0.4
  — the floor sits exactly on the title-tier threshold (§12) so normal use can never leave card
  tier; the dev LOD flag may unclamp below it. The container uses
  `transform: translate(...) scale(...)`; individual cards are positioned with `translate` only.
- **Gestures** (research §6 trap — decided here): wheel = **zoom** about cursor · space-drag or
  middle-button-drag = pan · trackpad: pinch = zoom, two-finger scroll = pan · `⇧`+wheel = pan
  horizontal. No gesture leaks to the feed (separate stage views).
- **Culling:** rbush R-tree over placed-card world rects, queried with the viewport inflated by
  **one viewport-size margin** on each side; only intersecting cards mount as React components.
  Index updates on place/move/remove/drag-frame (rbush supports update-in-place via
  remove+insert; the plan verifies the exact API via context7 before coding).
- **Cards:** fixed width **360 px** at 1:1; natural height clamped to **max 280 px** with a
  bottom fade; full markdown + KaTeX, same renderer component the feed uses. **Card body data
  path (pinned):** cards read a per-note react-query key `['note', id]`, served by a `notes:get
  {id}` channel (added this milestone if absent) and seeded from the `['notes']` list cache when
  the note is in it — the feed's list is capped at the newest 500, so older placed notes MUST
  fetch individually. The note-save path invalidates both `['notes']` and `['note', id]`, which
  is what makes feed↔canvas edits converge. Selected = accent ring + soft halo (the v21 focus
  treatment). No resize handles. Z-order: cards stack by `placed_at` ascending (older below);
  the dragged/selected card renders temporarily on top (transient, not persisted — if z-order
  ever becomes data, that's the vision §Canvas layers tripwire). At rest at zoom ≠ 100% cards
  are CSS-scaled and we accept Chromium's settle re-raster (spike operator pass saw no blur
  artifacts; revisit only if dogfooding complains — vision principle 5's "1:1 at rest" reads as
  "no *persistent* transform-induced blur", not "zoom is forbidden to rest off 100%").
- **Mount-churn amortization (the spike's NEAR-PASS consequence — this is the spec's call):**
  **motion-LOD.** While the camera is in motion (pan/zoom velocity above a small threshold),
  newly entering cards mount as a cheap placeholder (title line + body-shaped skeleton, no
  markdown/KaTeX work); on camera settle (~120 ms idle), placeholders upgrade to full cards.
  Additionally, re-entering cards avoid re-parsing via a mounted keep-alive LRU of recently
  exited cards (`display: none`, never `content-visibility`) — react-markdown re-parses on every
  mount, so element-level `(note id, updated_at)` caching cannot survive unmount; full parse-level
  caching is deferred unless the §3 gates fail (amended 2026-06-13 with Plan 2, was: "memoized per
  (note id, updated_at) so re-entering cards never re-parse"). Idle-time prebuild is NOT in scope
  (revisit if gates fail).
- **Title derivation (one helper, used everywhere):** notes have no title field. A shared
  `noteTitle(note)` helper — first non-empty body line, markdown syntax stripped, clamped to
  ~80 chars, fallback to slug — is the ONLY source for: the motion-LOD placeholder's title line,
  picker rows (§5), shelf rows (§4), the placement banner (§6), and the recent popover (§14).
- **Card editing:** double-click a card enters in-place edit using the same floating-composer
  mechanism as creation (§7), pre-filled; `↵` commits (normal save path: revisions, links,
  FTS), `esc` reverts. (DOM input on DOM cards — no IME/overlay problem by construction.)

### Performance gates (from the spike, re-measured in-app on reference hardware)

Measured by a Playwright-Electron harness script (adapted from `scripts/spike-canvas/`; NOT a
lefthook gate — ABI; run manually + in CI where feasible) on a seeded 500-note board, scripted
pan/zoom sweep. **Protocol pinned** (the spike's watched run measured 51 fps vs 56 unattended —
the gate flips on conditions, so conditions are part of the gate): unattended idle machine,
display awake (verify printed vsync p50 ≈ 16.7 ms first — spike trap), 3 runs, gates judged on
the median run by mean fps. The harness is the milestone's one sneaky-big work item — it gets
its own plan batch, with the cut line "seeded board + one scripted sweep + frame stats"; smoke
flows ride in it only if free:

- mean ≥ 55 fps · zero frames > 100 ms · p95 ≤ 33.4 ms (2 vsyncs) during churn · p95 ≤ 18 ms
  steady-state camera motion with no card mounts.
- Dev dot tier with synthetic 10k points: p95 ≤ 18 ms (spike: passes flawlessly).
- React reconciliation rides on the spike's vanilla-DOM floor: if gates fail, suspect reconcile
  cost first (profile before redesigning — React Compiler is already on).

## §4 Shelf (placement queue)

- Feed verbs: hover affordance **"▦+"** on each bubble + context-menu **"→ shelf"** — adds to
  shelf, stays in feed (no view switch). On an already-on-canvas note both are replaced by the ▦
  jump affordance (§9).
- Shelf lives as the only pane in the embryo left dock (§10). Content, two quiet groups:
  **"to place (N)"** — rows with `x IS NULL`, newest first; **"recently placed"** — last 10 rows
  with `x IS NOT NULL`, by `placed_at` desc. (An undo-reshelved row has `placed_at` nulled by
  `canvas:unplaceNotes`, so it cleanly re-enters "to place" and leaves "recently placed".)
- Row interactions by view × row state (wireframes A3–A5):

  | | unplaced row | placed row |
  |---|---|---|
  | **canvas view** | drag out → card ghosts at real size, drops where released · click → go to the note: switches stage to feed, scrolls + flash | click → **jump**: viewport pans/zooms to card, ring flashes · drag → **move** the existing card, ~300 ms hold guard before the drag engages; `esc` mid-drag cancels, snaps home |
  | **feed view** | click → scrolls feed to the note + flash | click → switches stage to canvas + jump |

  Row *dragging* exists only on the canvas view (there is no drop target on the feed); rows that
  switch stages on click get no ellipsis marker — the honesty rule (§6) applies to menu verbs,
  and rows behave like search hits.
- Status bar "N unplaced ●" (count of `x IS NULL` rows) opens/focuses the shelf. Indicator absent
  at N = 0.

## §5 `/` picker (place from within the canvas)

- `/` (canvas focused, no selection-editing active) opens a small picker **at the cursor
  position** — the position IS the intended drop point. Reuses the existing search machinery
  (FTS) scoped to live notes.
- Rows: type glyph + title + ▦ chip when already placed. `↵` places the highlighted note at the
  picker's anchor point and closes. **`⇧↵` places and keeps the picker open** (seeding a board;
  subsequent drops offset by a small cascade so cards don't stack exactly). Picking a ▦ row does
  NOT duplicate — it jumps to the existing card (ring flash). `esc` closes.
- Footer hint line: `↵ place here · ⇧↵ place + keep picker · esc`.

## §6 One-shot placement mode (from the feed)

- Context-menu verb **"place on canvas…"** (the ellipsis is the honesty: this one switches
  views). Stage transitions feed→canvas with the slide animation (feed exits left, canvas enters
  right→left; Motion drives the two stage containers' transforms — ADR 0019 guardrail holds: no
  `layout`/`layoutId` projection inside the virtualized feed).
- In the mode: banner top-center `placing "«title»" — click to drop · esc to cancel`; the card
  ghosts **at real size** on the cursor; pan/zoom still work mid-placement. Click commits (place,
  ring flash, mode ends, user stays on canvas). `esc` cancels: nothing is written, the user stays
  on canvas (no jarring bounce-back), banner dismisses.
- If the note is already placed, the feed never offers this verb (it offers the ▦ jump instead).

## §7 Creating a note on the canvas

- Double-click empty surface → floating composer card at that point (same composer component as
  the feed: multiline, and the composer's actual promotion rule — **`?` promotes claim→question;
  there is no q/c/s promotion in this codebase** (that was the v21 prototype's heuristic; the
  wireframe copy saying otherwise is superseded here). Placeholder: `type — ? still promotes`.
  Right-click → "new note here" is the discoverable twin.
- `↵` commits: normal note-creation path (the note appears in the feed timeline like any capture,
  carrying the ▦ chip) + a placed layout row at the card's position — one transaction, and
  `notes.created_at`, `notes.updated_at`, `placed_at` get the **same** millisecond value (the
  §2 recency rule depends on this). `esc` with nothing typed: the card evaporates, no residue.
  Capture cost must stay ≤ ~1.5 s end-to-end.

## §8 Arranging

- **Drag to move:** pickup affordance = shadow + 1° tilt, nothing else. **No snapping, no grid**
  at this tier — spatial memory wants exact spots. `⇧` while dragging = axis lock. Position
  flushes on drop (§2 cadence).
- **Marquee:** drag on empty surface = rubber-band select. `⇧`/`⌘`-click toggles a card in/out of
  the selection.
- **Group drag:** relative offsets preserved; origin ghosts fade as the drop commits. One undo
  entry, one IPC transaction.
- **Nudge:** arrow keys move the selection 8 px (world units) per press; flushed debounced.
- **Selection bar** (E3, modified): floating quiet bar near the selection: `N selected ·
  remove from canvas · delete note…`. **remove from canvas** (also `⌫`/`⌦`) deletes layout rows
  only — the note stays in the feed untouched. **delete note…** soft-deletes the note(s)
  everywhere and requires a confirm step (the one destructive verb on this surface; native
  confirm dialog is acceptable at v0.4).

## §9 Feed-side traces

- Bubbles of placed notes show a small **▦ on canvas** chip (D2). Click → switch to canvas +
  jump-to-card (pan, ring flash). The chip is the cross-cutting "did I already put this on the
  board?" answer; the same ▦ renders in picker rows and shelf rows.

## §10 Embryo dock shell

- `Pane` interface in `src/renderer/src/panes/` — data-driven registry from day one:
  `{ id: string; title: string; homeDock: 'left' | 'right'; render: () => ReactNode }`.
  v0.4 registers exactly one pane (Shelf, homeDock left) and renders exactly one dock (left).
- One pane ⇒ **no tab strip** — just the quiet header with the pane title and a close ×
  (constrained-tiling rule: the word "tab" hasn't been earned until ≥2 panes; vision §Dock
  shell governs where this grows).
- Dock: fixed side, resizable 220–400 px by edge drag; open/closed + width are in-memory
  view-state (not persisted in v0.4). Opens via the status-bar unplaced indicator or a single
  quiet outline toggle at top-right. No right dock, no tab dragging, no second pane — those are
  the v0.x dock-shell milestone's.
- The dock coexists with both stage views (feed and canvas) — it is window chrome, not canvas
  chrome; on the feed view the shelf works as a reading list of queued notes (clicking a row
  scrolls the feed to that note).

## §11 Read-only edges (underlay)

- For every `links` row whose endpoints are BOTH placed on this canvas (resolve `to_slug` →
  live note id by direct slug match, consistent with `backlinks()` — alias-tier resolution via
  `note_aliases` is deliberately deferred for both surfaces, see the alias-aware-edges issue),
  draw a quiet line on the underlay beneath the cards:
  anchored center-to-center, clipped at card bounds (for culled/unmounted endpoints use the
  last-measured height from the renderer's size cache, estimate 140 px if never mounted).
  Styled by `edge_type` from design tokens:
  `reference` = thin solid at low opacity; `comment-on` = thin dashed at low opacity (exact
  tokens at implementation, v21 restraint).
- Edges follow live during drag (underlay redraws per drag frame — spike headroom is ample).
  No hit-testing, no hover, no creation in v0.4. (Creation is deferred AND has a known trap
  recorded in vision §Edge work: `replaceLinksForNote` wipes `'reference'` rows on save —
  canvas-created edges must not be `'reference'`.)
- Dangling links (unresolved slug, unplaced endpoint, soft-deleted note) draw nothing.

## §12 LOD seam + dev-flag dot tier

- `src/renderer/src/canvas/lod.ts` — the single source of tier truth:
  `type LodTier = 'card' | 'title' | 'dot'` ·
  `TIER_THRESHOLDS = { title: 0.5, dot: 0.15 }` (zoom < 0.5 → title, < 0.15 → dot) ·
  `tierForZoom(zoom): LodTier`. v0.4 builds renderers for `card` only; thresholds are
  load-bearing constants for the semantic-zoom milestone (vision §Semantic zoom), and the
  semantic-consistency invariant (visible at a tier ⇒ visible at all deeper tiers) is recorded
  there.
- In normal use the zoom clamp ([0.5, 2.0], §3) keeps the app inside card tier.
- **Dev-tools HUD** (v0.2.4 surface) gains a "LOD" section: *force tier* override
  (auto/card/dot), *unclamp zoom*, *synthetic 10k dots* toggle. Dot rendering = the spike's
  renderer adapted: notes drawn as ~3 px discs from a `Float32Array` of world positions on the
  underlay, cards unmounted while the dot tier is forced. Proves the full tier switch
  (enum → unmount cards → underlay draws) end-to-end on real data. Not user-reachable without
  the HUD.

## §13 Spatial undo

- Renderer in-memory stack (per window, dies on close — vision §Full undo holds the future),
  max 100 entries, redo cleared on new op. `⌘Z`/`⇧⌘Z` when canvas is focused. Entirely separate
  from any content/text undo.
- Entry = `{ op: 'place' | 'move' | 'remove', items: [{noteId, from, to}] }` where `from`/`to`
  are `{x,y}` | `'shelf'` | `'absent'` (`'shelf'`→ `canvas:unplaceNotes`; restoring `'absent'`
  rows → `canvas:restoreLayouts` with preserved timestamps). Covered: place (from shelf → undo
  reshelves; from picker/one-shot/create → undo removes the row; for a created note the note
  itself stays — only the layout is undone), move/group-move/nudge (coalesce nudge bursts within
  ~500 ms), remove (undo restores rows with prior positions). NOT covered: delete-note (it has a
  confirm), camera, shelf add/order, note content. **Liveness guard:** if an entry's note has
  been deleted since, the entry is silently discarded and the stack advances (the IPC layer
  re-checks liveness anyway — §2 — so a stale undo can never resurrect layout rows for a dead
  note).

## §14 Chrome: status bar, zero state, orientation

- **Status bar** — new app-wide bottom strip (one hairline, v21-quiet). On the feed view it
  carries only the window-level `N unplaced ●` indicator (so a "→ shelf" from the feed is
  immediately acknowledged and the shelf is reachable without switching views); otherwise empty
  there (future home of app-wide status, P1). On canvas, left→right:
  `24 notes` (placed count) · zoom pill `87% · fit · 1:1` — per the blessed wireframe: the %
  readout click-resets to 100% AND `1:1` (shown only when zoom ≠ 100%) does the same; the
  redundancy is intentional (readout-click is the power shortcut, `1:1` the labeled affordance).
  `fit` frames all cards (no-op at zero). Pill fades to 40% opacity when idle · `recent ▴`
  popover trigger · right edge: `3 unplaced ●` (opens shelf; hidden at 0).
- **Recent popover** (`⌘J` or the trigger; A6): opens upward, dock-menu style; lists ~8 notes on
  this canvas by recency with kind labels (`edited · 2m`, `placed · yesterday`,
  `created here · 1h` — from `canvas:recentOnCanvas`). `↵`/click jumps (pan + ring flash), `esc`
  closes, `⌘J` toggles. Ephemeral surface for "what was I just touching" — deliberately never
  grows into navigation; the dot tier takes the spatial-overview job later.
- **Zero state** (first-run): centered **in the viewport** (follows the camera, not world
  origin), shown while the canvas has zero placed cards. Copy, verbatim:
  `nothing here yet.` / `this canvas only shows what you place on it.` / `double-click to write
  something here,` / `or press / to bring a note over from the feed`. Never appears again once a
  card exists (it keys off placed-count, not a stored flag; shelved-only notes don't dismiss it).
- **Centroid arrow** (G2): when ≥1 card exists but zero cards intersect the viewport, a single
  quiet pill `↖ back to your notes` (arrow oriented toward the placed-cards centroid) appears;
  click = zoom-to-fit. Otherwise this surface stays empty. No minimap, ever.
