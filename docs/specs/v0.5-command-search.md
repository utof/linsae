# v0.5 command-search — spec

**Branch:** `v0.5/command-search` · **Builds on:** v0.1 (`⌘K` FTS palette, `search.ts`, `notes_fts`), v0.4.1 (`fuzzy.ts`, the canvas pickers). **Supersedes** the v0.1 hardcoded `⌘K` palette. **Source research:** `local_files/130-fuzzy-search-research.md` (saved verbatim; obsolete once this spec lands).

## Goal

Turn the single hardcoded `⌘K` FTS palette into a proper **command-and-search surface**: a generalized **command palette** plus two focused search doors — **fuzzy title quick-switch** and **full-text content search** — each backed by a **recency/frecency** default, with content search ranking **title hits first**. Introduce the app's first **settings store** and first **client-state store** (zustand) along the way.

This delivers the reframe from issue #130 (the research showed the literal "fuzzy the feed search" both regresses content search and has no title to point at): **keep FTS for content, add fuzzy for jump-by-title, and stop the silent 500-note cap from hiding older notes.**

## Non-goals (v0.5)

- **Global undo** — a separate major milestone (generalize the canvas spatial-undo stack into a unified main-side operation log; client-state undo libs are the wrong layer since linsae's source of truth is SQLite+files). v0.5 must not break the existing spatial-undo stack and the command palette must leave room to expose Undo/Redo as commands later, but it builds none of it.
- **Drizzle ORM** (#140) — deferred; v0.5 stays raw SQL (and the FTS work would not benefit from Drizzle regardless).
- **Alias-matching in the switcher** — `note_aliases` resolution is the #129/#98 effort (postponed past v0.5; see §15). The ⌘O switcher matches **titles only** in v0.5, built so adding alias candidates later is additive.
- **Typo tolerance** (`recieve`→`receive`) — the expensive fork (`spellfix1` is not bundled in better-sqlite3; trigram is substring, not edit-distance; subsequence requires in-order chars). Out of scope; its own decision.
- **No new commands beyond a small base set** — the registry is *built* dynamic/contextual (so canvas/feed can register their own commands), but v0.5 ships only an initial set (the two search surfaces + a few existing actions). A large command catalog is later work.

## Product decisions (locked)

1. **Three keyboard doors.** `⌘K` = command palette (a list of commands, each showing its hotkey). `⌘O` = search by **title** (fuzzy subsequence → jump to note). `⌘P` = search by **content** (FTS). The old `⌘K`-is-FTS behavior moves to **⌘P**.
2. **The command registry is dynamic + context-dependent.** Different contexts (canvas vs feed vs focused-note) contribute different commands. This is genuinely mutable, app-global **client** state → a **zustand** store (the codebase's first client-state lib; ADR). Contexts register/unregister commands on mount/context-change.
3. **Empty state = recent/frecent** for **both** ⌘O and ⌘P. An empty switcher/search shows your most-relevant notes; typing narrows.
4. **Access = `openThread` ∪ `edit` ∪ `jumpTo`.** A note's access bumps on any of: opening its thread view, saving an edit, or jumping to it. Access state is **DB-only app state** (a `note_access` table) — **not** written to the markdown files, **not** reconciled from disk (same category as canvas layouts).
5. **Frecency is a setting.** "recent" = `last_accessed_at DESC`; "frecent" = zoxide-style `frequency × recency-bucket multiplier` with aging decay. A setting toggles them; **default = frecent**.
6. **First settings store.** A SQLite `app_settings(key, value)` table + IPC + react-query. First setting: `notes.recencyMode = 'recent' | 'frecent'`. **#129 (postponed) will reuse this exact store** for its propagate-vs-alias toggle.
7. **Title is NOT a new column — reuse the existing `slug`.** `slug` and a display title share their root (first non-empty body line, heading marker stripped); they diverge only at the end (`slug` normalizes lower+collapse for identity; the **display** title strips inline markdown + keeps case). So: (a) the shared "title-line" extraction moves to **`src/shared/`** and feeds `slugFromBody`, the display-title derivation, AND the renderer's `noteTitle` (one source → no drift, no persisted column); (b) **FTS content-search indexes the existing `slug` column** for `bm25()` title-weighting — the FTS tokenizer lowercases + ignores punctuation, so indexing `slug` is functionally identical to indexing a fresh title column, and `slug` is already populated + `NOT NULL`, so there is **no new column and no JS backfill**. Plus a `prefix=` index for word-start matching. (Caveat: `slug` is frozen on edit until #129 — decision 7 §6/§15.)
8. **Stack:** react-query (all DB state incl. settings/access/frecency) · **+ zustand** (command registry + palette UI state) · raw SQL incl. all FTS · `react-hotkeys-hook`. No Drizzle.

## §1 Data model (additive migrations only)

Two additions + one FTS recreate. No new column on `notes`. No edits to shipped migrations.

### §1.1 FTS slug-weighting + prefix (migration `00NN_fts_slug_prefix.sql`)
Today `notes_fts` is external-content `fts5(body, content='notes', content_rowid='rowid')` with the `notes_ai/ad/au` triggers inserting `(rowid, body)` and the `'delete'` form passing `old` values (`0001_init.sql:61-74`). Adding a column to a populated external-content FTS5 table is not an `ALTER`; the documented path is **DROP + recreate + repopulate**, which the migration does:
- Drop `notes_fts` + the three triggers; recreate:
  - `CREATE VIRTUAL TABLE notes_fts USING fts5(slug, body, content='notes', content_rowid='rowid', prefix='2 3');`
  - `notes_ai`: `INSERT INTO notes_fts(rowid, slug, body) VALUES (new.rowid, new.slug, new.body);`
  - `notes_ad`/`notes_au`: the `'delete'` command must pass the **old** column values: `INSERT INTO notes_fts(notes_fts, rowid, slug, body) VALUES('delete', old.rowid, old.slug, old.body);` (then re-insert `new` for `au`).
  - `INSERT INTO notes_fts(notes_fts) VALUES('rebuild');` — **stays in the migration SQL**: it reads `slug`+`body` from `notes`, both already populated + `NOT NULL`, so there is **no NULL-title / backfill-ordering problem** (the risk a title column would have introduced). The rebuild repopulates the index from existing rows.
- **No `notes` column change, no JS backfill.** `slug` already exists, is `NOT NULL`, and is written on every save (`save-note.ts`), so the `notes_au` trigger keeps the FTS `slug` column current automatically.
- **Content-search query** (`search.ts`) gains `bm25(notes_fts, <slugWeight>, <bodyWeight>)` ranking (slug weighted heavier so title-word hits rank first) and `prefix` matching (§6). Results render **title + snippet** — the title is the **display** title derived on read (§2), NOT the slug.

### §1.2 `note_access` (DB-only access log; migration `00NN_note_access.sql`)
```sql
CREATE TABLE note_access (
  note_id          TEXT    PRIMARY KEY REFERENCES notes(id) ON DELETE CASCADE,
  last_accessed_at INTEGER NOT NULL,
  frequency        INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_note_access_recency ON note_access(last_accessed_at);
```
- One row per accessed note. An access (§7) does `INSERT INTO note_access(note_id, last_accessed_at, frequency) VALUES(?, ?, 1) ON CONFLICT(note_id) DO UPDATE SET last_accessed_at = excluded.last_accessed_at, frequency = frequency + 1`.
- **Not reconciled** — purely app state, like layouts. Survives with the DB; absent from the markdown files. `ON DELETE CASCADE` drops it with the note.

### §1.3 `app_settings` (first settings store; migration `00NN_app_settings.sql`)
```sql
CREATE TABLE app_settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```
- Key/value (value = JSON-encoded). First key: `notes.recencyMode` (`'recent'|'frecent'`, default `'frecent'` when absent). **Reused by #129** (e.g. `rename.propagateOnRename`).

## §2 Shared title-line extraction (`src/shared/note-title.ts`) — reuse, don't duplicate

- `slugFromBody` (`src/main/text/slug.ts`) and the renderer's `noteTitle` (`src/renderer/src/lib/note-title.ts`) both parse the **same first step**: first non-empty body line, strip the leading `#+\s*` heading marker. Extract that step into **`src/shared/note-title.ts`** (the cross-process boundary — `src/shared/` is already imported by both main and renderer, e.g. `zod-schemas`, `canvas`):
  - `titleLine(body): string` — the shared extraction (first non-empty line, strip `#` marker).
  - `deriveTitle(body): string` — display title = `titleLine` then strip inline markdown (`**`, `_`, task checkboxes — the #105 cases) + **keep original case**.
  - `slugFromBody` becomes `normalizeSlug(titleLine(body))` (lower + collapse). slug keeps raw markdown chars (unchanged behavior); only the *extraction* is shared.
- **Display title is derived on read — no persisted column.** Both the renderer's `noteTitle` and the main-side `notes:listTitles` (§3) call `deriveTitle` from the same shared module → **no drift** and **no schema change**. The renderer keeps deriving for full Notes it already holds (canvas pickers); the lean switcher gets its titles from `notes:listTitles`.
- This is strictly less work than a persisted column: no `title` column, no `Note`-type field, no main-side `Note`-construction edits, no backfill — just one extracted shared function and the FTS recreate (§1.1).

## §4 Command palette (`⌘K`)

- **Dynamic registry in a zustand store** (`useCommandStore`): `register(command)` / `unregister(id)`; `commands` selector. A `Command` = `{ id, label, hint?: string (hotkey), group?, run: () => void, when?: () => boolean }`. Contexts (canvas, feed, focused-note) register their commands on mount / context change and unregister on unmount — this is why it is a store, not a static array (decision 2).
- **`⌘K`** opens a `cmdk` palette listing the currently-registered commands (filtered by `when`), fuzzy-filtered **by `fuzzy.ts`** over `label` (consistent with the other doors; `shouldFilter={false}`), each row showing `label` + its `hint`. Enter runs `command.run()` + closes.
- **Base command set (v0.5):** "Search by title (⌘O)", "Search by content (⌘P)", plus a few existing global actions already wired in App (e.g. New note, Toggle shelf, Recent ⌘J, Open settings) registered as commands. This proves the registry; the catalog grows later.
- **Hotkeys** (`react-hotkeys-hook`, app root): `⌘K`/`⌘O`/`⌘P` open their surfaces; they set a single `activePalette` ∈ `{none, command, title, content}` (one open at a time). The palette open-state may live in the same zustand store or local App state — plan's call; it is small either way.
- **Forward-compat (global undo):** the registry is the natural home for future "Undo"/"Redo" commands; keep `Command.run` synchronous-or-async-agnostic so an undo command slots in without a registry change.

## §5 ⌘O — title quick-switcher

- A `cmdk` surface (mirrors the canvas `Picker.tsx` shape: `shouldFilter={false}`, controlled `value`, `<mark>` highlight via the shared highlighter, Enter selects). Candidates = `notes:listTitles` → `{id, title}` → `fuzzyMatch(query, candidates)` (reuse `fuzzy.ts` + its `matched` highlight). **Uncapped** (whole vault).
- **Empty query → recent/frecent** (`notes:recent`), not a hint and not all-notes.
- **Enter → jump to the note**, mirroring the current `⌘K` select → App navigation. NOTE App has **two** jump verbs: `setFocusedId` (feed focus — what the current `⌘K` `onJump` is actually wired to, `App.tsx:787`) and `onJumpToCard` (canvas pan + flash, `App.tsx:478`). The plan decides which ⌘O reuses (feed-focus for a feed-context switch; canvas-jump for a placed card) — read the wiring, don't invent a new verb. The jump **counts as an access** (`kind: jump`, §7).
- Trim-aware empty gate (a whitespace-only query shows recent, not all — the v0.4.2 `/`-picker lesson; `fuzzyMatch` trims internally so the gate must use `query.trim()`).

## §6 ⌘P — content search (FTS, upgraded)

- The existing `CommandPalette` FTS surface, **re-bound to ⌘P**. Upgrades:
  - **`bm25` slug-weighting** — `ORDER BY bm25(notes_fts, <slugWeight>, <bodyWeight>) ASC` so notes whose **slug** (= title words) matches rank above body-only matches. Weights tuned in the plan (e.g. slug 10×, body 1×). Lower bm25 = better → ASC.
  - **`prefix` matching** — `prefix='2 3'` index (§1.1) + a query builder that, **per token**, phrase-escapes the token (`"annot"`) and appends the prefix `*` **OUTSIDE** the quotes (`"annot"*`) so `annot` finds `annotation`. (Critical, verified against the FTS5 docs: `*` is a special prefix char only *outside* double-quotes — a `*` inside quotes goes to the tokenizer and won't prefix-match. So escape-then-append **per token**, NOT wrap-the-whole-phrase-then-append.) Keep the `try/catch → []` FTS-syntax safety (`search.ts:58-76`); never surface a raw FTS parse error. Decision for the plan: prefix the **last** token only (search-as-you-type) vs every token.
  - **Rows show title + snippet** — the display title (`deriveTitle`, §2) is added to each result (the SELECT already reads `body`; derive the title alongside the snippet). Better than today's snippet-only rows.
  - **Empty query → recent/frecent** (`notes:recent`), replacing today's "type to search" hint.
- **Frozen-slug caveat (decision 7):** `slug` is frozen on edit (`save-note.ts:148` — the #129 gap), so the FTS title-*weight* follows the frozen slug until #129 makes slug update on rename. The **displayed** title (`deriveTitle`, live from body) is always current; only the rank-boost may use the old title words. Minor, self-resolving when #129 lands (§15).
- Keep `shouldFilter={false}` + the `snippet()` `dangerouslySetInnerHTML` + its documented CSP/sandbox threat model (`CommandPalette.tsx:15-26`). DOMPurify remains a separate deferred follow-up.

## §7 Recency + frecency

- **Access events** (decision 4): instrument the three existing entry points to bump `note_access` (§1.2):
  - `openThread(id)` (App.tsx:402) → `kind: open`.
  - note **save** (the `saveNote` update path, `save-note.ts:223`) → `kind: edit`.
  - `setJumpTo`/`onJumpToCard`/`setFocusedId` jumps (incl. the ⌘O jump, recent/shelf jumps) → `kind: jump`.
- **"recent"** = `note_access ORDER BY last_accessed_at DESC LIMIT n` (notes with no access row fall after; optionally union with `updated_at` so brand-new notes appear).
- **"frecent"** (zoxide model): score `= frequency × bucket(age)` where `age = now − last_accessed_at` and bucket ≈ `<1h → 4`, `<1d → 2`, `<1w → 0.5`, else `0.25`; with **aging**: when `Σ frequency` exceeds a cap, multiply all by a decay (e.g. 0.9) and drop sub-1 rows. Computed in SQL or main-side over `note_access`. The plan pins the constants (cite zoxide).
- **Pure scoring is unit-tested** (a `frecencyScore(frequency, lastAccessed, now)` pure function with fixtures) — same testability posture as `fuzzy.ts`.
- **Setting** `notes.recencyMode` (§1.3) toggles which ranking `notes:recent` uses; default frecent.
