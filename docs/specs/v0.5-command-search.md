# v0.5 command-search — spec

**Branch:** `v0.5/command-search` · **Builds on:** v0.1 (`⌘K` FTS palette, `search.ts`, `notes_fts`), v0.4.1 (`fuzzy.ts`, the canvas pickers). **Supersedes** the v0.1 hardcoded `⌘K` palette. **Source research:** `local_files/130-fuzzy-search-research.md` (saved verbatim; obsolete once this spec lands).

## Goal

Turn the single hardcoded `⌘K` FTS palette into a proper **command-and-search surface**: a generalized **command palette** plus two focused search doors — **fuzzy title quick-switch** and **full-text content search** — each backed by a **recency/frecency** default and an **indexed title** so content search ranks title hits first. Introduce the app's first **settings store** and first **client-state store** (zustand) along the way.

This delivers the reframe from issue #130 (the research showed the literal "fuzzy the feed search" both regresses content search and has no title column to point at): **keep FTS for content, add fuzzy for jump-by-title, and stop the silent 500-note cap from hiding older notes.**

## Non-goals (v0.5)

- **Global undo** — a separate major milestone (generalize the canvas spatial-undo stack into a unified main-side operation log; client-state undo libs are the wrong layer since linsae's source of truth is SQLite+files). v0.5 must not break the existing spatial-undo stack and the command palette must leave room to expose Undo/Redo as commands later, but it builds none of it.
- **Drizzle ORM** (#140) — deferred; v0.5 stays raw SQL (and the FTS work would not benefit from Drizzle regardless).
- **Alias-matching in the switcher** — `note_aliases` resolution is the #129/#98 effort; the ⌘O switcher matches **titles only** in v0.5. The switcher is built so adding alias candidates later is additive.
- **Typo tolerance** (`recieve`→`receive`) — the expensive fork (`spellfix1` is not bundled in better-sqlite3; trigram is substring, not edit-distance; subsequence requires in-order chars). Out of scope; its own decision.
- **No new commands beyond a small base set** — the registry is *built* dynamic/contextual (so canvas/feed can register their own commands), but v0.5 ships only an initial set (the two search surfaces + a few existing actions). A large command catalog is later work.

## Product decisions (locked)

1. **Three keyboard doors.** `⌘K` = command palette (a list of commands, each showing its hotkey). `⌘O` = search by **title** (fuzzy subsequence → jump to note). `⌘P` = search by **content** (FTS). The old `⌘K`-is-FTS behavior moves to **⌘P**.
2. **The command registry is dynamic + context-dependent.** Different contexts (canvas vs feed vs focused-note) contribute different commands. This is genuinely mutable, app-global **client** state → held in a **zustand** store (the codebase's first client-state lib; ADR). Contexts register/unregister commands on mount/context-change.
3. **Empty state = recent/frecent** for **both** ⌘O and ⌘P. An empty switcher/search shows your most-relevant notes; typing narrows.
4. **Access = `openThread` ∪ `edit` ∪ `jumpTo`.** A note's access bumps on any of: opening its thread view, saving an edit, or jumping to it. Access state is **DB-only app state** (a `note_access` table) — **not** written to the markdown files, **not** reconciled from disk (same category as canvas layouts).
5. **Frecency is a setting.** "recent" = `last_accessed_at DESC`; "frecent" = zoxide-style `frequency × recency-bucket multiplier` with aging decay. A setting toggles them; **default = frecent**.
6. **First settings store.** A SQLite `app_settings(key, value)` table + IPC + react-query. First setting: `notes.recencyMode = 'recent' | 'frecent'`. **#129 (v0.6) reuses this exact store** for its propagate-vs-alias toggle.
7. **Persisted, indexed title.** A `title` column on `notes`, derived on save by a **shared main-side `deriveTitle`** (the canonical source; the renderer consumes `note.title`, eliminating the renderer/main drift risk). `notes_fts` indexes `title` so content search gets `bm25()` **title-weighting**; a `prefix=` index adds word-start matching.
8. **Stack:** react-query (all DB state incl. settings/access/frecency) · **+ zustand** (command registry + palette UI state) · raw SQL incl. all FTS · `react-hotkeys-hook`. No Drizzle.

## §1 Data model (additive migrations only)

Three additions, all in a new migration set after `0003`. No edits to shipped migrations.

### §1.1 `title` column + FTS title-weighting (migration `0004_note_title.sql` + backfill)
- `ALTER TABLE notes ADD COLUMN title TEXT;` (nullable; backfilled). On every save and reconcile, `title = deriveTitle(body)` (§2).
- **Recreate `notes_fts` with a title column.** Today it is external-content `fts5(body, content='notes', content_rowid='rowid')` with `notes_ai/ad/au` triggers inserting `(rowid, body)` (`0001_init.sql:61-74`). The migration drops `notes_fts` + the three triggers and recreates:
  - `CREATE VIRTUAL TABLE notes_fts USING fts5(title, body, content='notes', content_rowid='rowid', prefix='2 3');`
  - `notes_ai`: `INSERT INTO notes_fts(rowid, title, body) VALUES (new.rowid, new.title, new.body);`
  - `notes_ad`/`notes_au`: the `'delete'` command must pass the **old** column values: `INSERT INTO notes_fts(notes_fts, rowid, title, body) VALUES('delete', old.rowid, old.title, old.body);` (then re-insert `new` for `au`).
  - **No `'rebuild'` in the migration SQL** — it runs in JS *after* the title backfill (below), because the migration runner is SQL-only and completes before any JS, so a SQL `'rebuild'` would index NULL titles.
- **Backfill + rebuild (JS, at the `index.ts:171→174` seam).** `runMigrations(db)` (`migrate.ts:46-74`) is **SQL-only** and runs at `index.ts:171`, *before* `reconcile` at `:174` — there is no JS hook inside it. So the structural migration above does schema/triggers ONLY; add a `backfillTitles(db)` step at that seam (right after `runMigrations`, beside `reconcile`): idempotent `UPDATE notes SET title = deriveTitle(body) WHERE title IS NULL`, **then** `db.prepare("INSERT INTO notes_fts(notes_fts) VALUES('rebuild')").run()`. **Ordering is load-bearing for FTS integrity:** a `'rebuild'` over NULL titles indexes NULLs, and the recreated `'delete'` triggers (which pass `old.title`) would then fail to match those NULL-indexed entries on a later edit/delete → orphaned FTS rows / index drift. Backfill first, rebuild second, both in JS. The backfill is JS (not SQL) because `deriveTitle`'s first-line/markdown-strip can't be replicated cleanly in SQL; the `WHERE title IS NULL` guard makes it idempotent across boots.
- **Content-search query** (`search.ts`) gains: `bm25(notes_fts, <titleWeight>, <bodyWeight>)` ranking (title weighted heavier so title hits rank first) and `prefix` matching via `term*` (the query builder appends `*` to user tokens, still phrase-escaping each token to stay FTS-syntax-safe — see §6). Results SELECT `n.title` so rows render **title + snippet**.

### §1.2 `note_access` (DB-only access log; migration `0005_note_access.sql`)
```sql
CREATE TABLE note_access (
  note_id        TEXT    PRIMARY KEY REFERENCES notes(id) ON DELETE CASCADE,
  last_accessed_at INTEGER NOT NULL,
  frequency      INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_note_access_recency ON note_access(last_accessed_at);
```
- One row per accessed note. An access (§7) does `INSERT INTO note_access(note_id, last_accessed_at, frequency) VALUES(?, ?, 1) ON CONFLICT(note_id) DO UPDATE SET last_accessed_at = excluded.last_accessed_at, frequency = frequency + 1`.
- **Not reconciled** — purely app state, like layouts. Survives with the DB; absent from the markdown files. `ON DELETE CASCADE` drops it with the note.

### §1.3 `app_settings` (first settings store; migration `0006_app_settings.sql`)
```sql
CREATE TABLE app_settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```
- Key/value (value = JSON-encoded). First key: `notes.recencyMode` (`'recent'|'frecent'`, default `'frecent'` when absent). **Reused by #129** (e.g. `rename.propagateOnRename`).

> Migration numbering is illustrative — use the next free `000N_*.sql` after the current max (`ls src/main/db/migrations/`). The three may be one migration file or three; the plan decides.

## §2 Shared title derivation (`deriveTitle`)

- Today `noteTitle()` lives **renderer-side** (`src/renderer/src/lib/note-title.ts`) — a first-non-empty-line + markdown-strip (heading marker, emphasis; see #105). The persisted `title` column must be computed **main-side**, so the canonical derivation moves to **`src/main/text/note-title.ts`** (next to `slug.ts`, which is already main-side and derives the slug from the same first line).
- **The stored `title` becomes canonical.** `saveNote` and `reconcile` set `notes.title = deriveTitle(body)` whenever body changes (alongside the existing `slug` derivation). The renderer **consumes `note.title`** (added to the `Note` type) instead of re-deriving — eliminating drift between the FTS-indexed title, the switcher candidate, and what cards/pickers display.
- **Renderer migration:** existing `noteTitle(note)` consumers (~6 sites: `Picker.tsx`, `EdgeTargetPicker.tsx`, `RecentPopover.tsx`, `ShelfPane.tsx`, `NoteCard.tsx`, `App.tsx`) switch to `note.title`. The renderer `noteTitle` is retired or kept only as a fallback for not-yet-saved drafts (where no row/`title` exists yet) — the plan decides whether a thin fallback stays.
- **Main-side enabling work (without it `note.title` is silently `undefined`):** adding `title` to the `Note` type is typed-additive, but every site that *builds* a `Note` must SELECT/include it — `getNote`/`listNotes` (`notes.ts:68,112`, explicit column lists → add `n.title`), the hand-built note literal in `search.ts:79-87` (`title: r.title`), and any Note-returning query in `resolver.ts`/`links.ts`/`reconcile.ts`. The plan enumerates these. The renderer/main import boundary stays clean — the renderer only reads a string field, no main import.
- `deriveTitle` and `slugFromBody` share the "first non-empty line" parse; the plan may extract that shared step. Both must agree on what the "title line" is.

## §4 Command palette (`⌘K`)

- **Dynamic registry in a zustand store** (`useCommandStore`): `register(command)` / `unregister(id)`; `commands` selector. A `Command` = `{ id, label, hint?: string (hotkey), group?, run: () => void, when?: () => boolean }`. Contexts (canvas, feed, focused-note) register their commands on mount / context change and unregister on unmount — this is why it is a store, not a static array (decision 2).
- **`⌘K`** opens a `cmdk` palette listing the currently-registered commands (filtered by `when`), fuzzy-filtered **by `fuzzy.ts`** over `label` (consistent with the other doors; `shouldFilter={false}`), each row showing `label` + its `hint`. Enter runs `command.run()` + closes.
- **Base command set (v0.5):** "Search by title (⌘O)", "Search by content (⌘P)", plus a few existing global actions already wired in App (e.g. New note, Toggle shelf, Recent ⌘J, Open settings) registered as commands. This proves the registry; the catalog grows later.
- **Hotkeys** (`react-hotkeys-hook`, app root): `⌘K`/`⌘O`/`⌘P` open their surfaces; they set a single `activePalette` ∈ `{none, command, title, content}` (one open at a time). The palette UI open-state may live in the same zustand store or local App state — plan's call; it is small either way.
- **Forward-compat (global undo):** the registry is the natural home for future "Undo"/"Redo" commands; keep `Command.run` synchronous-or-async-agnostic so an undo command slots in without a registry change.

## §5 ⌘O — title quick-switcher

- A `cmdk` surface (mirrors the canvas `Picker.tsx` shape: `shouldFilter={false}`, controlled `value`, `<mark>` highlight via the shared highlighter, Enter selects). Candidates = `notes:listTitles` → `{id, title}` → `fuzzyMatch(query, candidates)` (reuse `fuzzy.ts` + its `matched` highlight). **Uncapped** (whole vault).
- **Empty query → recent/frecent** (`notes:recent`), not a hint and not all-notes.
- **Enter → jump to the note**, mirroring the current `⌘K` select → App navigation. NOTE App has **two** jump verbs: `setFocusedId` (feed focus — what the current `⌘K` `onJump` is actually wired to, `App.tsx:787`) and `onJumpToCard` (canvas pan + flash, `App.tsx:478`). The plan decides which ⌘O reuses (feed-focus for a feed-context switch; canvas-jump for a placed card) — read the wiring, don't invent a new verb. The jump **counts as an access** (`kind: jump`, §7).
- Trim-aware empty gate (a whitespace-only query shows recent, not all — the lesson from the v0.4.2 `/`-picker fix; `fuzzyMatch` trims internally so the gate must use `query.trim()`).

## §6 ⌘P — content search (FTS, upgraded)

- The existing `CommandPalette` FTS surface, **re-bound to ⌘P**. Upgrades:
  - **`bm25` title-weighting** — `ORDER BY bm25(notes_fts, <titleWeight>, <bodyWeight>) ASC` so notes whose **title** matches rank above body-only matches. Weights tuned in the plan (e.g. title 10×, body 1×).
  - **`prefix` matching** — `prefix='2 3'` index (§1.1) + a query builder that, **per token**, phrase-escapes the token (`"annot"`) and appends the prefix `*` **OUTSIDE** the quotes (`"annot"*`) so `annot` finds `annotation`. (Critical, verified against the FTS5 docs: `*` is a special prefix char only *outside* double-quotes — a `*` inside quotes goes to the tokenizer and won't prefix-match. So escape-then-append **per token**, NOT wrap-the-whole-phrase-then-append.) Keep the `try/catch → []` FTS-syntax safety (`search.ts:58-76`); never surface a raw FTS parse error. Decision for the plan: prefix the **last** token only (search-as-you-type) vs every token.
  - **Rows show title + snippet** (now that `n.title` is selectable) — better than today's snippet-only rows.
  - **Empty query → recent/frecent** (`notes:recent`), replacing today's "type to search" hint.
- Keep `shouldFilter={false}` + the `snippet()` `dangerouslySetInnerHTML` + its documented CSP/sandbox threat model (`CommandPalette.tsx:15-26`). DOMPurify remains a separate deferred follow-up (out of scope; note it).

## §7 Recency + frecency

- **Access events** (decision 4): instrument the three existing entry points to bump `note_access` (§1.2):
  - `openThread(id)` (App.tsx:402) → `kind: open`.
  - note **save** (the `saveNote` update path) → `kind: edit`.
  - `setJumpTo({id})` / the ⌘O jump / recent/shelf jumps → `kind: jump`.
- **"recent"** = `note_access ORDER BY last_accessed_at DESC LIMIT n` (notes with no access row fall after; optionally union with `updated_at` so brand-new notes appear).
- **"frecent"** (zoxide model): score `= frequency × bucket(age)` where `age = now − last_accessed_at` and bucket ≈ `<1h → 4`, `<1d → 2`, `<1w → 0.5`, else `0.25`; with **aging**: when `Σ frequency` exceeds a cap, multiply all by a decay (e.g. 0.9) and drop sub-1 rows. Computed in SQL or main-side over `note_access`. The plan pins the constants (cite zoxide).
- **Pure scoring is unit-tested** (a `frecencyScore(frequency, lastAccessed, now)` pure function with fixtures) — same testability posture as `fuzzy.ts`.
- **Setting** `notes.recencyMode` (§1.3) toggles which ranking `notes:recent` uses; default frecent.
