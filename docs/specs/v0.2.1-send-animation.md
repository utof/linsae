# v0.2.1 — iMessage-style send animation (rolling feed)

*Spec. Branch `v0.2.1/ux-animation-fixes`. Sibling of the v0.1.3 expand/collapse
morph (ADR 0007) — reuses its rAF + easing + reduced-motion patterns. Revised
after fresh-Opus spec review (round 1): ghost is a note-bubble clone, not a
composer clone; target uses the note's height + handles short/empty feeds.*

## Goal

When the user sends a note from the create-mode Composer, a **ghost clone** of
the resulting **note bubble** lifts off from the composer's position and flies
up to where the new note lands at the bottom of the feed, fading out as the real
note pops in beneath it. iMessage's "the bubble leaves the composer" feel.

Scope decided with the user (2026-06-03):
- **Ghost flies, note pops in** (v1) — NOT grow-to-make-room. The real note
  appears at full height via the normal mutation refetch; the ghost is a
  transient flourish flying *over* the gap, not coupled to a height morph.
- **Rolling feed only.** Thread capture composer is a deliberate follow-up
  (→ issue, per CLAUDE.md deferral discipline), same staging as the date pills.

## Why a ghost clone (not animate the real new bubble)

The feed is virtualized (`@tanstack/react-virtual`, `anchorTo:'end'`) and the
note is created **async** (`createMut` → IPC → better-sqlite3 → query
invalidate → refetch). At the frame the user hits send, the destination note
does not exist in the DOM; when it does, it lives inside a `transform:
translateY(...)` virtual-item wrapper. Animating the *real* item would (a) stall
until the async create resolves, killing the "instant liftoff," and (b) fight
the virtualizer's own transform. A transient `position:fixed` ghost — portaled
to `document.body` — **decouples the animation from IPC/DB latency and the
virtualizer entirely.** → ADR 0018.

**Containing-block safety (verified in review):** the ghost is `position:fixed`,
so a transformed ancestor would become its containing block and break the
viewport-relative coords that `getBoundingClientRect()` returns — the exact bug
`ContextMenu.tsx` already escapes by portaling to `document.body`. The app shell
(`html`/`body`/`#root`/`WindowFrame`/`<main>`) carries no
`transform`/`filter`/`will-change`/`perspective`/`contain`, so the fixed coords
are viewport-relative. The ghost inherits ContextMenu's portal-to-body safety; a
brief code comment guards against a future `transform` landing on `#root`.

## What the ghost looks like

A **presentational note-bubble**, NOT a composer-card clone. It matches the
destination `NoteBubble` box (maxWidth 560, border-radius 14, the bubble's
padding, no composer shadow / send-button gutter) and renders the same body via
the shared `Markdown` component for content fidelity. Static and
non-interactive (no hover toolbar / context menu / expand row). This is the I1
fix: cloning the bubble — not the wider composer card — makes the *landing*
pixel-match the real note, where the eye ends up; the small width/shape snap at
*liftoff* happens over the composer, which is simultaneously clearing and
remounting, so it reads as the bubble leaving the composer.

## Mechanism

1. **At submit** (`Composer.submit`, **synchronous, before the mutation**),
   snapshot the composer card's `getBoundingClientRect()` (liftoff anchor) and
   the body text + mode. The snapshot is captured before `onSuccess` can remount
   the composer (the remount is driven by `successCount`), so there is no
   start-rect race.
2. **Measure the ghost.** Render the presentational bubble (off-paint / at the
   liftoff anchor) and read its `getBoundingClientRect()` → `noteH`, `noteW`.
3. **Target rect.** Where the new note lands at the feed bottom, covering both
   feed sizes (pure geometry, testable — see Verification):
   - tall feed (content ≥ viewport, bottom-pinned): `targetTop =
     scrollerRect.bottom − noteH − FEED_BOTTOM_GAP`.
   - short feed (content < viewport, top-aligned under `anchorTo:'end'`):
     `targetTop = scrollerRect.top + min(getTotalSize()+noteH, clientHeight) −
     noteH − FEED_BOTTOM_GAP`.
   - `targetLeft = feedContentLeft` (the centered column's left edge; the bubble
     is left-aligned, so its left matches a real note's left).
4. **Scroll state.** Own-send pins to bottom: if the feed is not already
   bottom-pinned, scroll it to bottom first so the landing slot is on-screen.
5. **Play.** One rAF clock tweens the ghost's `transform: translate(dx,dy)` from
   liftoff anchor → target with a **spring-overshoot** ease
   (`cubic-bezier(0.34,1.56,0.64,1)` — the scrollbar-thumb / resize-handle
   token). Overshoot is allowed here: the ghost is a `transform` on a fixed div
   with no clip and no scroll coupling, so it cannot resurrect ADR 0007's
   empty-box (whose monotonic constraint was about a clip box exceeding its
   content inside a scroll-anchored item). Opacity fades the ghost out over the
   last ~40% so it dissolves into the real note popped in beneath it. The fade
   also masks any few-px vertical target error.
6. **Composer clears instantly.** Existing behavior: `onSuccess` bumps
   `successCount` → key change → composer remounts with `initialBody=''`.

### First-send / no-feed edge

If no `<Feed>` is mounted yet (the very first note — App renders a "nothing yet"
placeholder, not `<Feed>`), there is no scroller/last-item to target. v1: skip
the fly and let the note appear (optional gentle fade-in). Not worth special
geometry for the once-per-lifetime empty state.

## Timing / failure

- **Optimistic launch.** The ghost flies at submit, not on `onSuccess` — local
  IPC+SQLite is fast, but a several-ms stutter would still read as lag.
- **If `createMut` rejects** (e.g. duplicate-slug): the ghost still completes its
  flight and fades (a harmless flourish); the existing red-error composer state
  (`submitError`) is the source of truth. No recall/undo animation — out of
  scope.

## Reduced motion

`prefers-reduced-motion: reduce` → **no ghost, no fly.** The note simply appears
(current behavior). Mirror `useExpandCollapseMorph`'s reduced-motion branch.

## Tuning hooks (reuse)

- `window.__morphSlow` (dev-only, GH #49, already wired in `env.d.ts` +
  `useExpandCollapseMorph`) also stretches this tween Nx for at-8× feel tuning
  without prod builds.
- `import.meta.env.DEV` gates the slow-mo; tree-shakes to the constant in prod.

## Verification (no manual screenshots)

The harness is the **arbiter of whether async reconcile-to-real-item is needed**:
build the simple computed-target version, measure the real landing drift, and
add reconcile only if the drift is visible past the fade.

Fork `scripts/morph-harness.mjs` → `scripts/send-harness.mjs`:
- launch the built app in a throwaway profile, seed a few notes, scroll to
  bottom; tag the ghost `data-testid="send-ghost"`,
- start a per-rAF sampler recording the ghost's `getBoundingClientRect()` +
  computed opacity each frame; type → Enter,
- **assert from numbers, not pixels:**
  - vertical travel is monotonic-ish from `composerRect.top` → `targetTop`
    (one overshoot reversal near the end is allowed — it's a spring),
  - landing: the ghost's final rect ≈ the real `[data-index]` last note's rect
    (this is the drift measurement that decides reconcile),
  - ends with the ghost removed from the DOM **and** a real `[data-index]` note
    present.
  - (frame-interval ≈16ms is a soft 60fps sanity check only — unlike the morph
    harness there is no `flushSync`/virtualizer stall source here, so it is not a
    primary assertion.)
- Filmstrip screenshots are a backstop.

Prereq (manual, user-owned ABI step): `pnpm rebuild:electron && pnpm exec
electron-vite build` before running the harness.

## Unit / component tests

- **Pure geometry module** (sibling of `expandCollapseMorph.ts`): takes rects +
  sizes as **inputs**, returns target rect / per-`t` translate+opacity. No DOM
  reads, so node-env Vitest exercises it without layout (like `lerp` /
  `bottomAnchorScrollTop`). Cover tall vs short feed target, opacity curve.
- **Component test** (RTL + happy-dom): submit renders a `send-ghost` portal
  node; reduced-motion mock → no ghost; ghost removed after the tween. happy-dom
  has no layout/rAF timing, so assert mount/unmount + the reduced-motion branch
  only — trajectory is the harness's job.

## Out of scope (→ issues)

- Thread capture composer send animation.
- Grow-to-make-room (new note grows 0→full as ghost lands).
- Failed-send recall/undo animation.
- Async reconcile-to-real-item (add only if the harness shows visible drift).
