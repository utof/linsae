# v0.2 — YouTube annotation (pinned-player video threads)

## Context

linsae is a single rolling feed where **everything is a note**. v0.1 froze a
schema (`0001_init.sql`) in which a note already carries `source_kind` /
`source_locator` (TEXT, nullable — `0001_init.sql:13-14`), edges live in
`links(from_note_id, to_slug, edge_type)` with `edge_type` defaulting to
`'reference'` (`0001_init.sql:26-31`), `NoteType = 'claim' | 'question' |
'source'` (`src/shared/types.ts:5`, `src/shared/zod-schemas.ts:32`), and
`notes_fts` indexes `body` via triggers (`0001_init.sql:61-74`).

v0.2 adds the ability to **watch a YouTube video inside linsae and annotate it**:
notes anchored to a video timestamp, and screenshots of the frame. A video is
just a note (`type='source'`); its annotations are ordinary notes linked back to
it. The UX was designed in `v21-design-system/v21-youtube-view-handoff/`
(`ThreadView.jsx`, `MediaFeedNote.jsx`, `README.md`) — that decision log is
authoritative for visuals and is not re-litigated here.

The visual companion to this spec is those two JSX prototypes. This spec is the
single authoritative contract for the **data model, IPC surface, and behavior**;
the implementation plan decomposes it into batches that all reference the
contracts defined here (one spec avoids cross-batch interface drift).

## Scope

**v0.2.0 — this spec.** URL → video-note; the pinned-player ThreadView; text
notes anchored to a timestamp (freeze-on-focus, no auto-pause); `⌘⇧C` capture →
a screenshot-note whose frame fills the bubble (**no drawing markup**); the
video-order rail + capture-order feed + sort toggle; scrubber markers; oEmbed
titles. All batches land on branch `phase/v0.2-youtube-annotation`.

**v0.2.x — carved out (own design pass + own spec).** The annotation **drawing
editor**: perfect-freehand strokes, text overlay, color swatches, the
`<hash>.svg` sidecar, open-editor-on-capture, and the Esc "discard / keep as
orphan" prompt. The `attachments.overlay_path` column and the `'clip'` kind are
provisioned now (see Data model) so that milestone needs no further migration.

## Goals

- A YouTube URL pasted into the composer becomes a first-class video-note that
  renders as a feed card (`MediaFeedNote`) and opens into a thread.
- Inside a video thread, a note inherits the current playback position as an
  editable timestamp anchor with a single interaction; a screenshot is one
  keystroke (`⌘⇧C`).
- The thread reads two ways from the same notes: **video time** (the rail, the
  distinctive view, default) and **capture time** (the ordinary chronological
  feed), switched by one toggle.
- Every anchored note is discoverable on both the vertical rail and the player
  scrubber; "where the playhead is now" is always reachable (follow / jump pill).
- Screenshot bytes are written atomically, deduplicated by content hash, and the
  caption text is full-text searchable with no new FTS wiring.
- No schema change to the frozen `0001` tables; v0.2 is additive only.

## Non-goals

- **Drawing on screenshots** (pen/text/swatch markup, SVG sidecar) — deferred to
  v0.2.x with its own design pass. v0.2.0 screenshots are immutable PNGs.
- **Local-file video** playback — the `Player` interface is defined so a future
  `LocalPlayer` is purely additive, but no local impl ships now.
- **Mind-map / graph canvas / spatial (VR) views** — see *Forward direction*;
  v0.2 must not block them but builds none of them.
- **Visual-regression (Playwright `toHaveScreenshot`)** of these surfaces —
  remains deferred per CLAUDE.md; one Playwright **Electron smoke** test is in
  scope only because `capturePage` cannot run under jsdom.
- **YouTube playlists, search, or auth** — a single video by ID/URL only.

## Forward direction (informational — explains *why* the shapes below are media-agnostic; builds nothing)

The frozen schema is already a **property graph**: `notes` are nodes,
`links(from_note_id, to_slug, edge_type)` are typed edges. The intended long-term
arc (mind-map graph view; later a spatial/VR "mind palace"; MarginNote-style
PDF+map note-taking) is expected to survive a possible future framework rewrite
because it keeps this same node/edge core. Two principles constrain v0.2 so it
stays compatible:

1. **Spatial position is view-state, not note identity.** When a canvas/VR view
   arrives, node positions belong in their own table
   (`node_layouts(note_id, canvas_id, x, y, z, …)`) — one note can appear in many
   canvases at different positions. v0.2 adds no positional columns to `notes`.
2. **"What external thing a note is bound to" is one reusable concept.** A video
   timestamp today, a PDF page+rect tomorrow, a VR anchor later — all the same
   idea, all carried by the existing `source_locator` JSON. Hence the anchor is
   stored there (below), not in a YouTube-specific column.

## Data model

### `notes` — unchanged (no migration)

- **Video-note:** `type='source'`, `source_kind='youtube'`,
  `source_locator = {"media":"youtube","video_id":"<11-char id>"}` (JSON TEXT).
  Its title/body come from oEmbed + user edits; `slug` is its identity per
  ADR 0002.
- **Comment-note (text or screenshot):** an ordinary note (`type='claim'` or
  `'question'`), `source_kind='youtube'`,
  `source_locator = {"media":"youtube","video_id":"<id>","t":<seconds, REAL>}`.
  The caption / prose is the note `body` → indexed by `notes_fts` for free.
  A comment-note with no timestamp anchor omits `t` (it "floats to the bottom"
  of the rail per the handoff). Its **`type`** is set by the existing composer
  mode (defaults `'claim'`; `'question'` possible) and is rendered **neutrally**
  in-thread (no colored chip — handoff visual language); `MediaFeedNote`'s
  open-question count is the number of linked comment-notes with `type='question'`
  in the open state, reusing v0.1 question/status semantics (no new concept here).

**Anchor rationale:** `t` lives in `source_locator` JSON, reusing an existing
column, because it generalizes to non-YouTube media (see *Forward direction*) and
adds no premature schema. The rail orders by `json_extract(source_locator,'$.t')`;
at single-user scale this needs no index. If profiling ever demands one, an
expression index `CREATE INDEX … ON notes(json_extract(source_locator,'$.t'))`
is a non-destructive later add.

### `links` — unchanged (no migration)

A comment-note links to its video-note as **data, not schema**:
`links(from_note_id = comment.id, to_slug = video.slug, edge_type = 'comment-on')`.
This is the threading primitive and plays with the existing wikilink resolver
(slugs per ADR 0002). No `parent_note_id` column (see ADR 0010).

### `0002_video_threads.sql` — additive only

```sql
-- v0.2 schema. 0001_init.sql is frozen and untouched. Additive only.

-- Cached video metadata, populated via YouTube oEmbed on first embed.
-- title is denormalised so "screenshots from videos titled X" is one indexed
-- LIKE with no network call.
CREATE TABLE video_sources (
  video_id      TEXT PRIMARY KEY,           -- 11-char YouTube id (future: local uuid)
  source_kind   TEXT NOT NULL,              -- 'youtube' | 'local'
  title         TEXT,
  channel       TEXT,
  thumbnail_url TEXT,
  duration_sec  INTEGER,                    -- nullable; oEmbed omits duration
  fetched_at    INTEGER NOT NULL,
  CHECK (source_kind IN ('youtube', 'local'))
);
CREATE INDEX idx_video_sources_title ON video_sources(title);

-- Captured frames (v0.2.0) and, later, drawn overlays + clips (v0.2.x).
-- note_id NULL = orphan (captured but not yet attached to a comment-note).
CREATE TABLE attachments (
  id                 TEXT PRIMARY KEY,       -- uuidv7
  note_id            TEXT,                   -- nullable FK; NULL = orphan
  kind               TEXT NOT NULL,          -- 'screenshot' (v0.2.0) | 'clip' (future)
  base_sha256        TEXT NOT NULL,          -- hash of the immutable PNG bytes
  base_path          TEXT NOT NULL,          -- absolute path under userData/attachments/…
  overlay_path       TEXT,                   -- v0.2.x: path to <hash>.svg sidecar; NULL until drawn
  video_id           TEXT,                   -- denormalised; joins to video_sources
  time_seconds       REAL,                   -- playback time the frame was captured at
  width_px           INTEGER NOT NULL,       -- physical pixels in the PNG
  height_px          INTEGER NOT NULL,
  device_pixel_ratio REAL    NOT NULL DEFAULT 1,
  created_at         INTEGER NOT NULL,
  deleted_at         INTEGER,
  CHECK (kind IN ('screenshot', 'clip')),    -- 'clip' provisioned now; CHECK is costly to alter later
  FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE SET NULL
);
CREATE INDEX idx_attachments_note_id     ON attachments(note_id)     WHERE deleted_at IS NULL;
CREATE INDEX idx_attachments_video_id    ON attachments(video_id)    WHERE deleted_at IS NULL;
CREATE INDEX idx_attachments_base_sha256 ON attachments(base_sha256) WHERE deleted_at IS NULL;
CREATE INDEX idx_attachments_orphans     ON attachments(created_at)  WHERE note_id IS NULL AND deleted_at IS NULL;
```

`overlay_path` (nullable) and `'clip'` in the `kind` CHECK are intentionally
provisioned now though unused in v0.2.0: a nullable column is a trivial later
add, but a CHECK constraint needs a full table rebuild to change in SQLite, so
the foreseeable enum value is baked in once (decided in Fork #2).

## Surfaces & components

### `MediaFeedNote` — a video in the feed
Per handoff (`MediaFeedNote.jsx`): variant A "integrated bottom row" (Telegram
pattern); plain dark 16:9 thumbnail with duration; title + `channel · duration`;
**wall-clock + view count bottom-right inside the note** (not in the callout);
last row = accent **"open video notes"** button + note count + open-question
count (amber) + chevron → opens ThreadView. No "VIDEO" type tag. Renders for
notes with `type='source'` and `source_kind='youtube'`.

### `ThreadView` — one video's annotation thread
Per handoff (`ThreadView.jsx`). Layout: slim top bar (back + title); pinned
player; scrolling thread; pinned composer. One centered content column; the time
+ rail line live in the **left gutter**; notes are flush to the column. Two
renderings switched by the **sort pill** (mode glyph, not asc/desc), default
**video time**:

- **Video-order (rail):** notes ordered by `t`. Per-note `Dot` + `Time` in the
  gutter; **same-pause cluster** = tight stack under one dot/one timestamp (no
  bracket, no indent); **collapsed dead-air** = three dots with the rail line
  **broken** behind them, gap height **logarithmic** (`round(20 + 9·ln(1+min))`);
  the **playhead** is an accent marker on the rail. **Timestamp-free notes float
  to the bottom** under a hairline "thread notes · no timestamp" divider (NOT a
  top bucket — handoff `README:49`).
- **Capture-order (feed):** the ordinary chronological feed; wall-clock time
  bottom-right inside each note; the `@video` chip still shows what it's about.

Visual language (handoff): notes are **neutral** — no type colors / labels /
status chips in the thread; **accent (Figma blue) marks only what is CURRENT**
(playhead, active note, follow, focus). Screenshot notes: the **frame fills the
bubble** at 16:9, caption below. The rail **line** is kept for now but flagged as
the most likely clutter; "no line" (dots + timestamps only) is the live
alternative — this is a visual-only later toggle, not a v0.2.0 blocker.

### Player subsystem
- **Library:** `youtube-player` (gajus, MIT) — a thin Promise wrapper over the
  IFrame Player API. Held in a **module-level singleton**
  (`src/renderer/yt/playerSingleton.ts`); the `<iframe>` is mounted to a DOM node
  held outside React's reconciliation tree so React 19 StrictMode's double-mount
  destroys React state, not the detached player. The singleton guards
  `if (instance) return instance`.
- **Embed correctness:** load the renderer over the `app://` custom protocol
  (not `file://`), set the iframe `referrerpolicy="strict-origin-when-cross-origin"`,
  use `host: 'https://www.youtube-nocookie.com'` and `enablejsapi=1`. Together
  these avoid YouTube Error 153 (the failure that rules out Tauri's
  `tauri://localhost`). See ADR 0008.
- **Custom transport bar:** linsae renders its own play/pause + scrubber +
  speed + follow toggle (`controls=0` on the embed). Owning the scrubber is what
  lets it carry **markers** (ticks at every `t` anchor) without drawing over
  YouTube chrome.
- **`Player` interface** (`src/shared/player.ts`) is defined now with one
  (YouTube) impl; no `LocalPlayer` stub (see ADR 0012 / Non-goals).

### Capture subsystem
- **Renderer:** read the iframe `getBoundingClientRect()` (CSS px / DIP), clamp
  to the viewport, call `youtube.capture({ rect })`.
- **Main:** `webContents.capturePage(rect)` (rect is DIP; the returned
  `NativeImage` is physical-pixel sized = `rect × scaleFactor`) → `toPNG()` →
  `sha256(bytes)` → write atomically (`tmp` + `fsync` + `rename`) to
  `userData/attachments/<yyyy>/<mm>/<sha256>.png`. If the hash file already
  exists, skip the write. Insert an `attachments` row and return the path **plus
  capture metadata** (`sha256`, `width`, `height`, `devicePixelRatio`) so the
  renderer can render the pending chip immediately — never the raw Buffer (large
  IPC payloads / forces re-hashing). See ADR 0009.
- **Frame-ready (only when a capture follows a *programmatic seek*):**
  `seekAndSettle(t)` = `seekTo(t,true)` → await `onStateChange === PLAYING` → two
  `requestAnimationFrame` round-trips, then capture (best-effort; YouTube
  specifies no frame-painted callback). The v0.2.0 `⌘⇧C` path captures the
  **current** frame and skips this; `seekAndSettle` is the documented recipe for
  any future "capture at a navigated timestamp" path.

## Key flows

### Add a video
Paste a YouTube URL into the main composer → a URL→`video_id` parser detects it →
create a note `type='source'`, `source_kind='youtube'`,
`source_locator={media:'youtube',video_id}` → fire `youtube.fetchOEmbed` →
upsert `video_sources` (title, channel, thumbnail). The feed shows `MediaFeedNote`.

### Text note while watching (revised interaction — supersedes the earlier "pause-on-type")
The composer shows an `@chip` timestamp:
- **Composer unfocused AND empty:** the chip **live-tracks** playback.
- **Composer focused, OR it holds draft text:** the chip **freezes** at the
  playback position as of focus ("stop wherever"). The composer **never
  auto-pauses** — the user pauses with Space *before* focusing (Space inside the
  focused input types a space, as normal text entry).
- **Esc:** unfocus the composer → chip resumes live-tracking (even after the
  draft was typed then deleted).
- **Click the chip:** manual `mm:ss` / `h:mm:ss` entry.
- **Submit (Enter):** create a comment-note (`body` = text), `source_locator`
  carries the frozen `t`, and a `comment-on` link to the video-note. A dot
  appears on the rail and a tick on the scrubber.

### Screenshot (no editor in v0.2.0)
`⌘⇧C` → `seekAndSettle` is unnecessary for the *current* frame, so capture the
current paused/playing frame at `getCurrentTime()` → frame lands as a **pending
attachment chip** in the composer alongside the `@chip` → optional caption →
Enter posts a screenshot comment-note (frame fills the bubble). The PNG is on
disk (deduped) the moment it is captured; the `attachments` row starts with
`note_id = NULL` (orphan) and is set to the new note's id on post. If the user
clears the composer without posting, the attachment stays an orphan (no editor
to bail from in v0.2.0).

### Navigation & follow
- Click a rail dot **or** a scrubber tick → `seekTo` that `t` + scroll the
  matching note into view + flash it (accent).
- **Follow on** (transport icon, default on): when the playhead crosses an
  anchor, highlight + auto-scroll its note. **Follow off + playhead off-screen:**
  a "jump to now · mm:ss" pill appears above the composer (handoff logic in
  `ThreadView.jsx:284-297`).
- List → video is never automatic (scrolling notes must not yank playback).

## IPC contracts (Zod-validated at the boundary, per CLAUDE.md)

`src/shared/api.ts` (renderer-facing `window.api`), all main handlers validate
input with Zod before use:

```ts
interface YouTubeApi {
  capture(args: { rect: { x: number; y: number; width: number; height: number } }):
    Promise<{ path: string; sha256: string; width: number; height: number; devicePixelRatio: number }>;
  fetchOEmbed(args: { videoId: string }):
    Promise<{ title: string; author_name: string; author_url: string; thumbnail_url: string }>;
}
interface AttachmentsApi {
  list(filter: { orphans?: boolean; videoId?: string; titleLike?: string; noteId?: string }): Promise<Attachment[]>;
  attachToNote(args: { attachmentId: string; noteId: string }): Promise<void>;
}
interface VideoSourcesApi {
  upsert(args: { videoId: string; sourceKind: 'youtube' | 'local' }): Promise<void>;
  get(args: { videoId: string }): Promise<{ title: string | null; channel: string | null } | null>;
}
```

`saveOverlay` / `loadOverlay` are **not** part of v0.2.0 — they arrive with the
v0.2.x editor. Types (`Attachment`, `Player`, `PlayerLocator`) live in
`src/shared/` mirroring the existing `types.ts` / `zod-schemas.ts` split.

## Markdown: `remark-yt-timestamps`

An in-tree remark plugin (`src/renderer/src/lib/remark-yt-timestamps.ts`),
mirroring the existing `remark-wikilinks.ts`. Matches, in order:

| Form        | Example   | Note               |
|-------------|-----------|--------------------|
| `@H:MM:SS`  | `@1:02:33`| hours-long videos  |
| `@MM:SS`    | `@1:23`   | the common case    |
| `@t=…`      | `@t=1m23s`| URL-style, paste-compatible |

Renders `<a class="yt-ts" data-seconds="83">@1:23</a>`; a delegated click handler
resolves the thread's current video and calls `playerSingleton.seekTo(83, true)`.
These inline links are *secondary* references — they seek but do **not** change a
note's primary anchor (which is the single `t` in `source_locator`; one dot per
note). The wikilink-shaped `[[yt|1:23]]` form is rejected (collides with slugs —
ADR 0011).

- **Integration (Vitest, real disk + real SQLite in `mkdtempSync`):**

- **Electron smoke (one `@playwright/test` Electron spec):** load a fixed video,

## ADRs to write

- **0008 — YouTube embed strategy:** `youtube-player` singleton mounted outside
  React; `app://` shell + `youtube-nocookie` host + `referrerpolicy` to avoid
  Error 153; vendoring fallback (package ~3 yrs stale). Alternatives:
  `react-youtube` (couples to the React tree), `lite-youtube-embed` (facade, not
  persistent control), raw IFrame API.
- **0009 — Screenshot capture:** main-process `webContents.capturePage` (DIP rect
  in, physical-px image out) + atomic write (tmp/fsync/rename) + SHA-256 dedup;
  return path, not Buffer. Alternative `html2canvas` rejected (cannot read
  cross-origin iframe pixels).
- **0010 — Threading as `links` data:** `edge_type='comment-on'` instead of a
  `parent_note_id` column on `notes`. Keeps the node/edge graph flat (see
  *Forward direction*).
- **0011 — `remark-yt-timestamps` syntax:** `@`-prefixed forms; reject
  `[[yt|1:23]]` (slug-namespace collision).
- **0012 — `Player` interface now, no `LocalPlayer` stub:** a bounded-context
  seam (driven by `source_kind`), not speculative abstraction.

## Risks

- **`youtube-player` abandonment** (last publish ~3 yrs). Mitigate: it is ~600
  LoC; vendor it into `src/renderer/yt/` under its MIT header if the IFrame API
  shifts. The IFrame API itself is stable since 2012.
- **Wayland `capturePage` parity** — Wayland's capture path differs from
  X11/macOS/Windows and is unverified for iframe-rect captures on Electron's
  bundled Chromium. Mitigate: a first-launch self-test (capture a known rect,
  assert `width === rect.width × scaleFactor`); on failure, warn and degrade.
  Detect via `process.platform === 'linux' && XDG_SESSION_TYPE === 'wayland'`.
- **Error 153 in a `file://` build** — mitigated by the `app://` shell + iframe
  `referrerpolicy` (ADR 0008); the Tauri `tauri://localhost` failure is the
  cautionary precedent.
- **oEmbed unavailability / private video** — `fetchOEmbed` must fail soft: the
  video-note still works with the raw id as a fallback title; `video_sources`
  row is written with `title = NULL` and retried opportunistically.
- **Milestone size** — mitigated at the plan layer: backend-first batches
  (schema/capture/IPC are integration-testable with no UI) sequenced before the
  player and rail UI; split the *plan* (not the spec) if it stops being coherent.

## Build sequence (informational — the plan details these as batches)

1. `0002` migration + `attachments`/`video_sources` query wrappers + capture IPC
   + atomic-write + dedup. Integration-testable, **no UI**.
2. Player singleton (`youtube-player`, `app://`/nocookie/referrerpolicy) + custom
   transport bar.
3. ThreadView: video-order rail + capture-order feed + sort toggle + anchorless
   bucket + clusters + log gaps.
4. Composer interactions (freeze-on-focus chip, manual chip entry, `⌘⇧C` →
   pending frame → post) + `remark-yt-timestamps`.
5. Scrubber markers + follow / jump-to-now pill + rail↔playhead sync.
6. `MediaFeedNote` wired into the feed; URL→video-note on paste.
