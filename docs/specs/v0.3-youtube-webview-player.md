# v0.3 — Webview-backed YouTube player (clean watch-page embed)

- **Status:** Draft (spec) — revised after one adversarial Opus review (findings folded in; residual nits → gh issues).
- **Supersedes:** the v0.2 IFrame player engine and **ADR 0015** (Vidstack-over-IFrame + cover). ADR 0015 §5 named this change the "escalation path (only if needed)" and required re-opening the decision first — this spec is that re-opening. A new **ADR 0016** records it.
- **Keeps:** the `Player` interface contract (**ADR 0012**), the loopback HTTP shell origin (**ADR 0008**), and the existing screenshot pipeline (`win.webContents.capturePage(rect)`, **ADR 0009**) — unchanged.
- **Adapts (MIT):** `aidenlx/media-extended` v3. MIT © 2024 AidenLx, PKM-er — notice travels with substantially-copied files (§13).

## 0. Status of load-bearing claims (honesty ledger)

The first review caught two claims presented as "verified" that are not. They are now labelled and gated:

| Claim | Status | How resolved |
|---|---|---|
| Host→guest `MessagePort` transfer via `webview.contentWindow.postMessage(nonce,'*',[port])` | **UNVERIFIED on our Electron 39** — undocumented in Electron's webview API; media-extended ships it (hand-types `contentWindow`, `components/webview/index.tsx:17`). It is web-standard `postMessage` transferable messaging across the webview proxy, so `sandbox`/`contextIsolation` (which gate Node, not web messaging) should not block it. | **Spike gate (Task 1).** Prove a port round-trip on Electron 39 + our `secureWebPreferences` against a trivial page. **Documented fallback** if it fails: a tiny guest `preload` using `ipcRenderer` + `MessagePortMain` (`WebContents.postMessage`). |
| Screenshot capture works (non-black) | **VERIFIED for the existing mechanism** — the v0.2 thread-smoke this session captured a real 520×293 PNG of the YouTube embed via `win.webContents.capturePage(rect)`. | **Keep that mechanism unchanged.** We do NOT switch to guest `capturePage`/canvas. The `<webview>` is a DOM element composited into the host page exactly like the iframe was, so the host-window region grab still works (Task 1 also re-confirms it for the webview). This removes the schema change and the hard-gate Zod breach the first draft introduced. |
| `webview.insertCSS()` hides chrome before first paint | **Not guaranteed** by docs. | Don't rely on it. A **black loading cover** sits over the webview until the guest signals `ready` (chrome hidden + video found), then reveals — so any chrome flash is never visible (§7). `insertCSS` is still used (early), but the cover is the guarantee. |

If Task 1's port spike fails AND the documented fallback also fails, the milestone stops and we re-open ADR 0016. Everything below assumes Task 1 passes.

## 1. Context & motivation

One YouTube video per `ThreadView`, with our own `TransportBar`. The IFrame Player API **cannot remove** YouTube's chrome (title/share bar, pause "more videos", end-screen, watermark) — it is drawn by YouTube inside the cross-origin embed (ADR 0015 §1). ADR 0015 *covered* it; in daily use that is unacceptable. We escalate to a real Electron `<webview>` loading `https://www.youtube.com/watch`, hide the surrounding page chrome with CSS we control, and drive the in-page `<video>` directly over a `MessagePort` RPC. YouTube's own player plays the video, so there is no embed chrome to fight — only ordinary page DOM we hide.

## 2. Goals / Non-goals

**Goals**
- Clean surface: `#movie_player` fills the webview; YouTube's top chrome, related/end-screen, and its own control bar are hidden by CSS.
- Preserve the `Player` facade (ADR 0012): `usePlayer`, `ThreadView`, `TransportBar`, `markdown.tsx` timestamp-seek, and the duration write-back keep working with **only the renaming churn in §6**.
- Preserve screenshot-at-timestamp via the **existing** `capturePage(rect)` pipeline.
- Keep the singleton + detached-wrapper + re-parent pattern (StrictMode safety).
- Keep transport hotkeys working (they break if a focused webview eats keydown — §8).

**Non-goals (YAGNI — deferred)**
- **Ad auto-skip** (media-extended's fragile duration heuristic). v1 does NOT skip in-stream ads and does NOT hide the in-player ad UI (so the **Skip Ad** button stays clickable — see §4.4). Follow-up issue.
- Caption/transcript extraction, Picture-in-Picture, playlists.
- **Automated consent/sign-in/bot-wall handling** — manual (§8).
- Non-YouTube providers.
- **Vidstack** — removed entirely (§3 D2; this reverts the just-landed commit `7396706`).
- **In-app volume control** — not in the `Player` interface today and the v0.2 IFrame (`controls:0`) had none either, so this is **not a regression**. OS volume applies; a `setMuted` RPC is wired but unexposed.

## 3. Decisions

- **D1 — `<webview>`, not `WebContentsView`.** `WebContentsView` is a native view positioned by main-process pixel bounds; it composites *above* the DOM (our controls/overlay couldn't sit on it) and needs per-frame `setBounds` IPC synced to scroll/resize (jank). `<webview>` is a DOM element that fits the existing 16:9 box, re-parents with the wrapper, and lets our overlay/controls use normal `z-index`. Trade-off: Electron 39 discourages `<webview>`; we isolate it behind the facade + an internal surface so a future swap is localized (ADR 0016 escape hatch). (Sources §12.)
- **D2 — Drop Vidstack; drive `<video>` directly.** We own the control bar; Vidstack's UI is dead weight and its custom-provider contract is undocumented/internal and needs a DOM target. Remove the `vidstack` dep.
- **D3 — `Player` facade unchanged** (`src/shared/player.ts` untouched). Singleton extra members: `getIframeRect()` → **renamed `getMediaRect()`** (returns the `<webview>` element's rect; same `DOMRect | null` shape, same capture use); `wrapper`/`videoId` stay.
- **D4 — Singleton + detached wrapper + re-parent** (unchanged pattern; one pinned player; `destroyPlayer()` for teardown/tests only).
- **D5 — Capture unchanged** (§0): renderer passes `getMediaRect()` to the existing `youtube:capture` IPC; main does `win.webContents.capturePage(rect)`. **No schema/IPC/preload change.**
- **D6 — UA spoof + persistent partition + autoplay gesture.** Desktop-Firefox-class UA (strip `Electron`/app tokens) to dodge unsupported-browser/bot treatment; `partition="persist:yt-player"` so a one-time sign-in survives; programmatic `play()` satisfied with `await webview.executeJavaScript(code, /* userGesture */ true)` before the RPC `play` (mirrors media-extended `provider.ts:120`). (Sources §12.)
- **D7 — Inject control runtime via `executeJavaScript`, CSS via `insertCSS`; no preload, no eval, no CSP strip.** `executeJavaScript` runs in the page **main world** (it can read `window`/`<video>`/`ytInitialPlayerResponse`) and is NOT a Trusted-Types `<script>` sink, so unlike media-extended's `window.eval(plugin)` we never need `unsafe-eval` or a TT policy. CSS injection is TT-exempt. (Sources §12.)
- **D8 — `will-attach-webview` security guard** (§9) is part of this milestone, added alongside `webviewTag:true`.
- **D9 — Guest runtime is a hand-authored self-contained JS string** (a `string` constant in a `.ts` module), not a bundled sub-entry. This sidesteps the electron-vite/rolldown "bundle-an-IIFE-and-exclude-from-react-compiler-babel" subproblem the reviewer flagged. Trade-off: the guest code isn't type-checked/bundled; it is small, isolated to one file (§4.3), and covered by the smoke. (If it outgrows a string, revisit a rollup sub-entry.)
- **D10 — Attribution** (§13).

## 4. Architecture

```
ThreadView (overlay added) ── usePlayer (unchanged) ── Player facade
                                                          │
                  src/renderer/src/yt/playerSingleton.ts  (REWRITE)
                    • owns the <webview> in the detached wrapper + a black loading cover + click-catcher overlay
                    • implements Player over a MessagePort RPC
                    • caches last-pushed currentTime/duration/state (getters are SYNC reads of the cache, no RPC per poll)
                    • play/pause: await executeJavaScript('1', true) then RPC
                  ── MessageChannel (port transferred into guest; Task-1 mechanism) ──
                  src/renderer/src/yt/rpc.ts (new, hand-rolled, no dep)
                  src/renderer/src/yt/inject/youtube-guest.ts  (exports a self-contained JS STRING)
                    • find ytd-app #movie_player video; re-hook on SPA nav (MutationObserver)
                    • disable YouTube's own keyboard shortcuts; theater mode; disable autoplay-next
                    • relay play/pause/seek/rate; stream timeupdate(RAF)/state/ended/error; emit `ready`; detect consent → emit `needs-interaction`
                  src/renderer/src/yt/inject/clean-css.ts (CSS string: fill + hide chrome; KEEP ad/skip UI)
main process:
  • secureWebPreferences: webviewTag:true                         (src/main/security.ts)
  • app.on('web-contents-created') → 'will-attach-webview' guard + guest 'will-navigate'/setWindowOpenHandler   (src/main/index.ts)
  • youtube:capture pipeline UNCHANGED                            (src/main/ipc/media.ts)
```

### 4.1 Host singleton (`playerSingleton.ts`, rewrite)
- `getPlayer()` builds wrapper `<div id="yt-player-wrapper">` containing: the `<webview>` (partition, useragent, `webpreferences="autoplayPolicy=user-gesture-required"`, no `allowpopups`), a **black loading cover**, and a **transparent click-catcher** overlay (click → toggle play/pause; keeps keyboard focus in the host).
- `did-start-loading` → `webview.insertCSS(CLEAN_CSS)`.
- First `dom-ready` → `webview.executeJavaScript(GUEST_STRING.replace(NONCE))`; transfer port (Task-1 mechanism); host keeps its port end.
- Guest `ready` event → hide the loading cover. `needs-interaction` event (consent/sign-in detected) → drop the click-catcher (pointer-events through to the webview) and show a hint; restore on next `ready`.
- `load(id)`: if the video id changed, set `webview.src` and **re-run the handshake** (tear down old port + cover shown until new `ready`); never reload on identical id (§5 lifecycle).
- `play()/pause()`: `await userGesture()` then RPC.
- `seekTo/setPlaybackRate`: RPC (fire-and-forget, no UI dependency on the response).
- `getCurrentTime()/getDuration()`: return the **cached** last-pushed value (resolved Promise), **no RPC round-trip** — so usePlayer's 5 Hz poll never hits RPC latency/timeouts (resolves the double-source + unhandled-rejection findings).
- `onStateChange(cb)`: subscribe to the cached-state stream, derive `PlayerState`, dedupe, return unsubscribe.
- `getMediaRect()`: `wrapper.querySelector('webview')?.getBoundingClientRect()`.
- `destroy()` → `destroyPlayer()`.

### 4.2 RPC (`rpc.ts`, new, hand-rolled)
Minimal typed `MessagePort` RPC: `invoke(method,...args)` (per-call timeout **1 s**), `send/on(event)` streams, `ready` handshake with a **separate ~10 s handshake timeout** (cold YouTube SPA boot is slow; the first draft's single 1 s timeout was wrong). Unit-tested with both ends of a real `MessageChannel` in happy-dom.

### 4.3 Guest runtime (`inject/youtube-guest.ts` → JS string)
Self-contained, runs in the youtube.com page. Adapted from media-extended `web/userscript/youtube.ts` + `hook/*` + `lib/init-port.ts`: receive port (by nonce), find `ytd-app #movie_player video`, `MutationObserver` re-hook across SPA nav, register method handlers + event forwarders (incl. RAF `timeupdate` while playing), enter theater mode, disable autoplay-next, **disable YouTube's own keyboard shortcuts** (so they don't fight our hotkeys — §8), detect `ytd-consent-bump-v2-lightbox` → emit `needs-interaction`. **Only file with YouTube-DOM-coupled selectors**; every selector commented; the maintenance surface when YouTube's DOM shifts. Filenames use ASCII hyphens (the upstream `html–media-events.ts` has a literal en-dash — rename on adapt).

### 4.4 Cleanup CSS (`inject/clean-css.ts`, string)
`#movie_player` → fixed, 100vw×100vh, max z-index, black bg; neutralize clipping ancestors; `html,body{overflow:hidden}`; hide `.html5-endscreen`, the **YouTube control bar** (`.ytp-chrome-bottom` — we have our own), top chrome/title, related. **Do NOT hide the in-player ad module / Skip-Ad button** (`.video-ads`, `.ytp-ad-*`) — hiding them would trap the user in an unskippable ad (reviewer finding); since v1 doesn't skip ads, the user must be able to. Static promo banners (`#masthead-ad`, `ytd-ad-slot-renderer`) may be hidden (not in-player).

### 4.5 Main process
- `security.ts`: add `webviewTag:true` to `secureWebPreferences`.
- `index.ts`: on `app.on('web-contents-created')`, handle `will-attach-webview` to **clamp** the guest (`webPreferences.nodeIntegration=false`, `contextIsolation=true`, `sandbox=true`, delete any unexpected `preload`) and `event.preventDefault()` for non-`youtube.com` attaches; on the guest `WebContents`, set `will-navigate`/`setWindowOpenHandler` to keep it on `*.youtube.com` (deny external navigation/popups). (Security checklist; §9.)
- `ipc/media.ts`, `zod-schemas.ts`, `preload`, `api.ts`: **unchanged** (capture pipeline kept).

### 4.6 Untouched
`usePlayer.ts`, `TransportBar.tsx`, `ThreadComposer.tsx`, `markdown.tsx`, `src/shared/player.ts`, the IPC/Zod/preload/api capture surface. `ThreadView.tsx` changes only: `getIframeRect`→`getMediaRect` at the `onCapture` call, and it gains the loading-cover/click-catcher markup if not housed in the singleton wrapper (preferred: housed in the wrapper, so ThreadView is one-line).

## 5. Data flow & lifecycle
- **First load:** `load(id)` → `src` set → `did-start-loading`→insertCSS, cover shown → `dom-ready`→executeJavaScript(guest)+port transfer → guest finds `<video>`, hides chrome → `ready` → cover hidden.
- **Play/pause:** TransportBar → `await userGesture()` → RPC → guest `video.play()/pause()`; guest forwards events → host cache → React.
- **Seek / rate:** RPC setter → guest. **Tick:** guest RAF `timeupdate` → host cache; `getCurrentTime()` reads cache.
- **Reload (id change):** drop old port + show cover → set `src` → re-handshake → `ready`.
- **Screenshot:** `getMediaRect()` → existing `api.youtube.capture({rect,videoId,t})` → `win.webContents.capturePage(rect)` → PNG.

## 7. Loading cover & flash avoidance
A black `<div>` over the webview from creation until the guest emits `ready`. Guarantees no chrome flash regardless of `insertCSS` timing. Doubles as the load-error surface (§ error handling). Reveal = fade out on `ready`.

## 8. Input & focus model (reviewer finding — webview steals keydown)
- A transparent **click-catcher overlay** (pointer-events:auto) sits over the webview in the normal state: clicking toggles play/pause via the facade and **keeps focus in the host document**, so global hotkeys (`mod+shift+c`, `mod+k`, transport keys) keep firing. This mirrors how the IFrame approach kept YouTube from receiving input (ADR 0015 §4), but via an overlay rather than `pointer-events:none` (we still need the webview interactive for consent).
- The guest runtime **disables YouTube's own keyboard shortcuts** as defense in depth.
- **Consent/sign-in escape hatch:** when the guest emits `needs-interaction`, the overlay is dropped so the user can click into the webview and resolve the wall; the persistent partition remembers it; overlay restored on next `ready`.

## 9. Security
- Renderer gains `webviewTag:true` (our trusted loopback-origin code). **Mandatory `will-attach-webview` guard** clamps guest `webPreferences` (`nodeIntegration:false`, `contextIsolation:true`, `sandbox:true`, no rogue `preload`) and `preventDefault`s unexpected attaches — restoring the `security.ts` hardened-baseline posture before enabling the tag. Guest `will-navigate`/`setWindowOpenHandler` confine it to `*.youtube.com` and deny popups. Injected code is ours (no Node grant to the page). `partition` isolates YouTube cookies. Renderer CSP `frame-src`/`script-src` YouTube tokens (added for ADR 0015) become dead and are **removed** in this milestone (they govern `<iframe>`, not `<webview>`).

## 11. Risks & mitigations
- **Port transfer unverified** → Task-1 spike gate + documented preload/`MessagePortMain` fallback (§0).
- **`<webview>` Electron-discouraged / future-major instability** → facade isolation; ADR 0016 escape hatch.
- **YouTube DOM churn** → all coupling in §4.3/§4.4, commented; guest devtools affordance (`webview.openDevTools()` behind a dev flag) for maintenance.
- **Consent/bot wall** → manual escape hatch (§8); smoke split (§10).
- **In-stream ads play** → accepted v1 limitation; Skip button preserved (§4.4).
- **capturePage black on some HW/DRM paths** → mitigated by keeping the proven existing mechanism (already captures non-black here); Task-1 re-confirms for the webview.
- **ToS gray zone** → private/solo tool; revisit before public distribution.
- **Persistent partition growth** → minor; note; no eviction in v1.

## 12. Verified facts (sources)
- `<webview>` Electron 39: supported but discouraged; `webPreferences.webviewTag`; attrs `src/useragent/partition/preload(file://)/webpreferences`; methods `executeJavaScript(code,userGesture)` (main world), `insertCSS`, `getWebContentsId`, `setUserAgent`, `openDevTools`; events `dom-ready/did-start-loading/did-fail-load`. — https://www.electronjs.org/docs/latest/api/webview-tag . `contentWindow` is **not** in these docs (hence Task-1).
- Documented port-transfer fallback: `WebContents.postMessage` + `MessagePortMain`. — https://www.electronjs.org/docs/latest/tutorial/message-ports
- `executeJavaScript` runs in main world; isolated variant is `executeJavaScriptInIsolatedWorld`. — electron/electron#14288/#14350.
- `win.webContents.capturePage([rect])` → `NativeImage.toPNG()`, compositor-level; **proven non-black here** (this session's thread-smoke PNG). — https://www.electronjs.org/docs/latest/api/web-contents
- Trusted-Types blocks only string→`<script>` sinks; `executeJavaScript` + CSS injection exempt. — https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/require-trusted-types-for
- Autoplay: muted always; unmuted needs gesture; `executeJavaScript(code,true)` grants activation. — https://www.chromium.org/audio-video/autoplay/
- Security checklist "verify webview options before creation" (`will-attach-webview`). — https://www.electronjs.org/docs/latest/tutorial/security
- media-extended v3: webview config + `contentWindow` hand-type (`components/webview/index.tsx:17`), UA spoof (`lib/remote-player/ua.ts`), port transfer (`provider.ts:185`), userGesture (`provider.ts:120`), userscript CSS + consent detect (`web/userscript/youtube.ts:183`), canvas-screenshot CORS-taint caveat (`lib/screenshot.ts:30`), Obsidian-only preload hack (`web/preload/*`). — `/tmp/media-extended-v3`.
