# v0.4.1 canvas-edges — spec

**Branch:** `v0.4.1/canvas-edges` · **Direction doc:** `docs/canvas-vision.md` §Edge work (reviewers:
check §Future contracts below against it) · **Builds on:** v0.4 canvas-mvp (`docs/specs/v0.4-canvas-mvp.md`
— §11 read-only edges, §5 `/` picker, §3 underlay, §13 spatial undo are the surfaces this extends).

## Goal

Turn the canvas's **read-only** edge *display* (v0.4 §11) into edge *creation + interaction*: drag
card→card to draw a typed link, label it, select it, delete it. Edges are a **data operation with
canvas affordances** — drawing one writes a real `links` row, same live-reference philosophy as
cards (one row, two projections). Drawing into empty space creates-or-connects a note in one gesture.

## Non-goals (v0.4.1)

Out, all with direction in `docs/canvas-vision.md`: a fixed edge-type taxonomy (types are free-text,
opt-in) · edge labels beyond the type text · rename propagation of edges/wikilinks (issue #129; drawn
edges dangle-on-rename like wikilinks until then) · alias-tier slug resolution (#98) · fuzzy search on
the **feed cmdk / global note search** (#130 — this spec only fuzzes the canvas pickers) · formal
edge-create/delete **undo** (the layout-only §13 stack is unchanged; edge ops are reversible by hand;
real edge undo waits for vision §Full undo) · edge routing/curves/waypoints · multi-select of edges ·
edge creation from the feed (canvas-only).

## Product decisions (locked in brainstorm 2026-06-13)

1. **Drawn edges are untyped by default.** `ctrl`-drag (or the hover handle) makes a plain edge;
   `ctrl+alt`-drag opens a small free-text field to **label its type**. No built-in taxonomy.
2. **Two ways to start an edge from a card:** a hover-reveal **connect handle**, or a **`ctrl`-drag**
   from the card body. Both are unambiguous against the §8 move-drag.
3. **Target by drop:** drop on a card → edge to that note. Drop in **empty space** → a cmdk
   **target picker** (fuzzy-search existing live notes, or create a new note there); the target is
   **placed at the drop point** so the edge actually shows (§11 needs both endpoints placed), and the
   edge connects. One gesture to import/create-and-connect.
4. **Slug-based, like wikilinks.** A drawn edge stores `to_slug` = the target's current slug. Renaming
   the target dangles the edge (draws nothing) exactly as a `[[wikilink]]` does today; the planned fix
   is the rename-handling effort (#129/#98), uniform across all reference kinds. **No schema
   migration.**
5. **Fuzzy = subsequence.** The pickers match by case-insensitive **subsequence** (`cu`→`claude`),
   ranked by best match, with matched characters highlighted. Hand-rolled, reused by the new
   edge-target picker **and** the existing `/` picker (§5).
6. **Only drawn edges are editable.** Body-derived `'reference'` wikilinks and `'comment-on'` thread
   edges stay **read-only** on the canvas (you change those by editing the body / the thread).

## §1 Data model (NO migration)

Drawn edges reuse the existing `links` table from `0001_init.sql`
(`PRIMARY KEY (from_note_id, to_slug, edge_type)`, `edge_type TEXT NOT NULL DEFAULT 'reference'`).

- **`edge_type` carries the type.** A plain drawn edge uses the reserved sentinel **`edge_type =
  'link'`**; a labeled edge uses the **user's free-text label verbatim** as `edge_type`. Because
  `edge_type` is in the PK, multiple distinctly-labeled edges between the same ordered pair coexist
  (`A→B 'supports'` and `A→B 'refutes'` are different rows); two plain `A→B` edges collapse (same PK)
  — intended.
- **Reserved words.** `'reference'` and `'comment-on'` are **forbidden** as user labels (Zod refusal,
  §2). This is the load-bearing guard: `replaceLinksForNote` (`src/main/db/queries/links.ts:46`)
  deletes every `edge_type='reference'` row on **every note save** and reinserts only body-derived
  wikilinks. It runs from FOUR sites, all `'reference'`-scoped: the note-save path (`save-note.ts:228`
  — *the* "every save" trigger the §8 integration test must target), the soft-delete path
  (`save-note.ts:129`, `replaceLinksForNote(id, [])`), the canvas create-on-canvas path
  (`layouts.ts:258`), and reconcile (`reconcile.ts:150/163`). A drawn edge stored as `'reference'` would be silently wiped on the next
  save. `'comment-on'` is managed separately and must not be impersonated. Any other `edge_type` —
  `'link'` or a user label — is untouched by `replaceLinksForNote` (it is scoped to `'reference'`), so
  drawn edges survive saves. **This is the trap the vision §Edge work flagged; the new edge_type is
  the fix.**
- **Targets a slug** (decision 4). `to_slug` = the target note's current slug. No self-edges
  (`from_note_id ≠ resolved target id`, §2 guard).
- **Read side is nearly done.** `canvasEdges` (`src/main/db/queries/canvas-edges.ts`) returns every
  `links` row whose **both** endpoints are placed on the canvas, resolving `to_slug`→live note id,
  with `edgeType`. It already returns drawn-edge rows for free (any `edge_type`) — the query logic is
  unchanged. **One additive change:** it also returns the stored **`toSlug`** (the PK component
  `deleteEdge` targets — see §2/§5; the renderer has `toNoteId` for display but needs the exact
  `to_slug` to delete the right row). This widens the `CanvasEdge` type (`src/shared/canvas.ts:39`)
  and the `canvas-edges.test.ts` expectations by one field. For any **non-dangling** (displayed) edge,
  `to_slug` equals the target's current slug — a dangling edge isn't returned (its old slug resolves
  to no live note), so it's never selectable anyway.
- **Soft-delete posture (orphan rows).** When an endpoint note is soft-deleted, its drawn-edge
  `links` rows are **left in place** — the delete path (`save-note.ts:129`) runs
  `replaceLinksForNote(id, [])`, which clears only `'reference'` FROM-rows. The edge then draws
  nothing (`canvasEdges` joins `deleted_at IS NULL` on both ends), so there is **no visible orphan**,
  but a stale row persists — exactly as a `[[wikilink]]` to a deleted note does today. This is the
  **deliberate, consistent** posture (vs the layout-row cleanup v0.4 §1 performs on delete); uniform
  orphan/rename cleanup is deferred to #129.

## §2 IPC surface (Zod at the boundary, like v0.4 §2)

All channels validated main-side; renderer via `window.api.canvas.*`. Constants from
`src/shared/canvas.ts` (`ROOT_CANVAS_ID`, `MANUAL_ARRANGEMENT_ID`). Write channels re-check note
liveness (`deleted_at IS NULL`) for **both** endpoints inside their transaction.

| channel | args (+ `canvasId`, `arrangementId`) | returns | notes |
|---|---|---|---|
| `canvas:edges` | — | `[{fromNoteId, toNoteId, toSlug, edgeType}]` | **exists** (§11); now surfaces drawn edges + adds `toSlug` (the PK component `deleteEdge` needs) |
| `canvas:createEdge` | `{fromNoteId, toNoteId, edgeType}` | ok | resolve `toNoteId`→`to_slug`, `INSERT OR IGNORE INTO links`; reject if `from==to`, if either note dead, or if `edgeType ∈ {'reference','comment-on'}` or is blank |
| `canvas:deleteEdge` | `{fromNoteId, toSlug, edgeType}` | ok | `DELETE` that exact PK row (`toSlug` taken from `canvas:edges`); **reject if `edgeType ∈ {'reference','comment-on'}`** (those are read-only on the canvas — server-side guard, not just UI) |

- **Zod refinements:** `edgeType` is a non-empty string not in the reserved set; trimmed; length cap
  (e.g. ≤ 40). `createEdge` takes `toNoteId` (the picker/drop yields an id); the server stores its
  slug so the row matches the slug-based read path.
- **No new query module beyond a thin `edges.ts`** wrapper for create/delete (mirrors
  `links.ts`/`canvas-edges.ts` placement under `src/main/db/queries/`).
- **Candidate list for the picker:** the fuzzy matcher (§4) needs `{id, title}` (title via the shared
  `noteTitle` helper) for all **live** notes. **Prefer reusing `notes:list`** — it already returns
  live notes' id + body → `noteTitle` — over adding a `notes:titles` channel: a new channel is new Zod
  + IPC surface (a hard-gate item) for no new data. Note `notes:list` is **capped at 500**
  (`zod-schemas.ts:61`; pagination is #20) — fine at this milestone's scale; revisit if a vault
  exceeds it (the picker would silently miss notes past the cap). React-query cached; invalidated on
  note create/save/delete.

## §3 Creation interaction

- **Affordances (decision 2):** on card hover, a quiet **connect handle** appears (small dot at the
  card's edge, v21-quiet); dragging from it starts an edge. Alternatively **`ctrl`-drag** from the
  card body starts an edge (the handle is the discoverable path; `ctrl` is the power path). Both
  cleanly disambiguate from the §8 move-drag (move = plain drag on the card body).
- **`ctrl+alt`-drag** starts an edge in **labeled** mode: on drop, a small free-text field opens at
  the drop point to type the edge's type (`↵` commits, `esc` cancels the label → falls back to a
  plain edge or cancels, decided in plan).
- **Drag visual:** a quiet rubber-band line follows the cursor from the source card to the pointer
  (drawn on the underlay), snapping to a target card when hovered.
- **Drop on a card** → `createEdge(source→that card)`. **Drop on the source itself / off any card into
  empty space** → the §4 target picker at the drop point.
- **Esc cascade (#18):** edge-drag-in-progress cancels first (release without connecting), then the
  target picker, then the label field, then an edge selection (§5). Slots into the v0.4 §15 cascade;
  note the new consumers in #18.

## §4 Edge-target picker + fuzzy matcher

- **Trigger:** dropping an edge into empty space opens a cmdk picker **at the drop point** (same
  surface family as the v0.4 §5 `/` picker and the create composer §7).
- **Behavior:** fuzzy-search all live notes by title; `↵` on an existing row → **place that note at
  the drop point** (`canvas:placeNote`) **and** `createEdge` to it; typing new content + a "create"
  affordance → `createNoteAt` at the drop point **and** `createEdge` to the new note. Either way the
  target ends up placed at the drop point so the edge renders (§11). A `▦`-placed row that's already
  on the canvas just connects (no re-place).
- **Fuzzy matcher (decision 5):** a pure module `src/renderer/src/lib/fuzzy.ts` —
  `fuzzyMatch(query, candidates: {id,title}[]) → {id, score, matched: number[]}[]`, case-insensitive
  **subsequence** match, fzf-style scoring (consecutive-run + word-boundary bonuses), descending
  score, `matched` indices for highlight. Hand-rolled (no dep, §10). **Also rewires the `/` picker
  (§5)** to rank live-note titles through it (v0.4 used FTS there; small candidate set → in-memory
  subsequence is exact + instant). Feed/global search keeps FTS (#130).
- **Undo wrinkle (documented v1 simplification):** the drop-in-empty path does two things — a layout
  **place** (enters the §13 spatial-undo stack) and an edge **create** (a data op, NOT in the
  layout-only stack). `⌘Z` undoes the placement (target un-places → edge hides, dangling); the edge
  row is removed by selecting + `⌫` (§5). Full edge undo is deferred (vision §Full undo). The plan
  must ensure no orphaned **visible** state results (a dangling edge simply draws nothing, §11).

## §5 Edge selection + deletion

- **Hit-testing** on the underlay (edges are canvas-2D, no DOM): point-to-segment distance from the
  cursor world-point to each **drawn** edge's center-to-center segment (clipped at card bounds, §11);
  nearest within a small screen-constant threshold wins. Broad-phase may reuse the rbush wrapper over
  edge bounding rects; a linear scan over drawn edges is acceptable at v0.4.1 scale (optimize later if
  measured).
- **Interaction:** hover near a drawn edge → quiet highlight; click → select (accent treatment on the
  line); `⌫`/`⌦` → `canvas:deleteEdge` (no confirm — an edge is a lightweight row, unlike the
  note-delete confirm §8). `esc` clears the edge selection.
- **Drawn-only.** `'reference'` and `'comment-on'` edges do not hover-highlight, select, or delete
  (decision 6) — the renderer marks them non-interactive and the server guards `deleteEdge` (§2).

## §6 Rendering

- Extends the v0.4 §11 read-only edges layer (a single `UnderlayLayer` on the shared world transform,
  dirty-flagged). Drawn edges (`edge_type` not in the reserved set) are styled **distinctly** from
  `reference`/`comment-on` per v21 tokens (exact tokens at implementation), and are **directed** — a
  small arrowhead at the target end. The optional **type label** renders as a tiny mid-segment pill
  (quiet; hidden at small zoom). (The read-only layer already routes any non-`reference`/`comment-on`
  type to a generic solid line at `CanvasStage.tsx:432` — that branch is the spot to replace with the
  distinct drawn-edge styling + arrowhead.)
- **Redraw cadence:** the layer marks dirty on edge create/delete, on the live drag rubber-band, and
  on endpoint drag-frames (edges follow live, §11). Coordinate with the underlay idle-rAF fix (#112)
  — the edges layer must not force the underlay to never idle when nothing changes.

## §8 Testing (per CLAUDE.md tiers)

- **Unit (node env):** `edges.ts` create/delete wrappers — incl. reserved-word refusal, self-edge
  refusal, dead-endpoint skip, slug resolution from `toNoteId`; `fuzzyMatch` (subsequence,
  case-insensitivity, ranking order, matched-index correctness, `cu`→`claude` example); hit-test
  point-to-segment math (threshold, clipping).
- **Integration (real SQLite, tmpdir):** **the trap** — create a drawn edge from note A, save A
  (triggers `replaceLinksForNote`), assert the drawn edge **survives** while A's `'reference'` rows are
  rebuilt from body; `createEdge`/`deleteEdge` round-trip; `deleteEdge` refuses `'reference'`/
  `'comment-on'`; liveness skip; `canvasEdges` returns drawn edges when both placed; **soft-deleting
  either endpoint hides the drawn edge** (`canvasEdges` no longer returns it) **while the row
  persists** (the §1 orphan posture).
- **Component (happy-dom + RTL):** edge-target picker (fuzzy rank + highlight, place-existing vs
  create-new, `▦` already-placed connects), label field commit/cancel, `/` picker still works on the
  new matcher.
- **Harness (Playwright-Electron `--smoke`, real pointers — the gap #131 is about):** extend the v0.4
  smoke — `ctrl`-drag card→card creates an edge (count via `canvas:edges`); drag-into-empty opens the
  picker, creates+connects; select an edge + `⌫` deletes it; a `'reference'` edge is **not**
  deletable. (happy-dom can't verify the pointer-driven creation — same rationale as the v0.4 §17
  harness tier.)
