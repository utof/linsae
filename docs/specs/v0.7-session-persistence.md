# v0.7 — session-persistence — spec

**Branch:** `v0.7/session-persistence` · **Direction doc:** `docs/canvas-vision.md` (principle 2 "position
is view-state"; the §Dock-shell "all layout state is per-window view-state; no saved workspaces/presets
until layouts demonstrably hurt to reconstruct" deferral at `:112-113` — this milestone invokes that
escape hatch and **amends** the doc, see ADRs) · **Builds on:** v0.5 command-search (the `app_settings`
store + `useSetting`; ADR 0042), v0.6 pdf-slim-slice (`usePdfOpenId` — the one existing restore-on-boot
precedent), v0.6.2 dock-shell (`dockStore`), v0.6.4 notes-as-threads (`threadNoteId`, thread scroll).

## Context

linsae currently forgets everything about your working state when it closes. Reopen the app and you land
on a fresh feed at the bottom, no docks, no selection, no open thread, and any half-typed note is gone.
The **only** state that survives a restart today is the open PDF *document id* — persisted as
`pdf.openDocId` through the generic `app_settings` key/value store (`usePdfOpenId.ts`; read-on-boot →
`openPane('pdf')` effect at `App.tsx:186-195`). Everything else is ephemeral React state:

- **Dock layout** — `dockStore` (`src/renderer/src/panes/dockStore.ts`) is an in-memory zustand v5 store
  with **no `persist`**: `{ left, right }` slices (`openPaneIds: string[]`, `activeId: string | null`),
  `widths: Partial<Record<DockSide, number>>`, `collapsed: Partial<Record<DockSide, boolean>>`.
- **Selection / thread** — `App.tsx:109` `focusedId` and `App.tsx:170` `threadNoteId` (both note UUIDs).
- **Feed scroll** — the `@tanstack/react-virtual` virtualizer in `Feed.tsx` (`getScrollElement: () =>
  scrollerEl`, `getItemKey: (i) => notes[i]?.id ?? i` at `:458`). No offset saved or restored.
- **Thread scroll** — `ThreadView.tsx` `scrollRef`/`scrollerEl` (`:206`), a plain `overflowY:auto`
  container (the thread list is **not** virtualized). No restore.
- **Composer drafts** — `Composer.tsx` `{ body, mode }` (feed, `:102`; cleared on success, preserved on
  failure), `SimpleComposer.tsx` `body` (`:26`, dies on unmount), `ThreadComposer.tsx` `draft` (`:88`,
  dies on unmount).
- **PDF view** — `PdfReader.tsx` `zoom` (`:45`, resets to fit on every doc swap, `:66-68`). Page is
  **hardcoded to 1** (`:87,93` — "multi-page nav is a queued nit"), so there is no page state yet.

This milestone makes the working session durable across restarts using **one mechanism** (the existing
`app_settings` store), **hydrated once on boot** and written back **debounced**. `canvas-vision.md:112-113`
defers persistence "until layouts demonstrably hurt to reconstruct"; dogfooding has now met that bar —
rebuilding the dock, re-opening the PDF, re-finding your place in the feed, and re-typing a half-written
note on *every* launch is exactly the reconstruct-pain that line named. (This is the qualitative bar the
vision set, now judged met — not the crisp pre-registered trigger issue #96 carries; the amendment records
that judgment, §ADRs.)

## Goals

On relaunch, restore the working session exactly as it was left:

- **Dock layout** — which panes were open on each side, the active tab per side, per-side widths, and
  per-side collapse state.
- **Selection & thread** — the last-selected note, and whether a thread was open (and which one).
- **Feed scroll position** — land where you were, not at the bottom, **flash-free** (no visible jump).
- **Thread scroll position** — per open thread (plain/pdf threads; see the YouTube exception below).
- **Composer drafts** — an unsent feed draft (text + `?`/claim mode) and unsent **per-thread** drafts
  survive both app close **and** leaving/re-entering a thread.
- **PDF view-state** — restore per-document **zoom**, and lay a **page-ready** seam so multi-page nav
  (future) gets page-restore for free.

Non-functional:

- **One mechanism, no migration** — every persisted group is a new key in the generic `app_settings`
  table (value is JSON TEXT; the table schema is unchanged, `0005_app_settings.sql`).
- **Boot-hydrate + debounced write-through**, NOT zustand `persist` middleware (see §Architecture).
- **Defensive reads** — every persisted value is Zod-validated on read and falls back to its default on
  mismatch/corruption, so a schema change or a hand-edited DB never crashes boot.
- **Graceful stale-reference handling** — a persisted note/pdf/thread id that no longer exists is
  silently dropped, never a hard error.

## Non-goals (v0.7)

- **Multi-page PDF navigation.** Deferred (own feature). We persist zoom now and reserve an optional
  `page` field; when page nav lands it fills that field with zero new persistence plumbing (user
  decision: "defer but prepare pdf for the persistence feature").
- **Multi-window / per-window workspaces.** linsae is a single main window (`src/main/index.ts`);
  "per-window view-state" collapses to one global session. No named workspaces/presets (still ruled out
  by `canvas-vision.md` until proven).
- **Persisting transient/animation state** — feed entrance animations, `frozenAt`/chip state in the
  YouTube composer, marquee/placement modes, undo stacks. Only durable working state is restored.
- **Restoring YouTube-thread scroll** — a YouTube `ThreadView` has always-on playhead-follow
  (`ThreadView.tsx:199`) that would immediately override a restored `scrollTop`, so `thread.scroll` is
  scoped to plain/pdf chronological threads only (see Data model).
- **Cross-device / cloud sync.** Local SQLite only.
- **A settings UI.** Keys are internal; no user-facing toggle to clear/disable persistence in v0.7
  (a `clearSession()` dev affordance is allowed but not surfaced).

## Architecture (the one decision that shapes everything)

**Extend `app_settings`; hydrate once on boot; write back debounced. Do NOT use zustand `persist`.**

The persistence backend is an **async IPC round-trip** already in place: renderer `api.settings.get/set`
→ `settings:get`/`settings:set` (Zod-guarded, `SettingsGetInputSchema`/`SettingsSetInputSchema` with
`value: z.unknown()` — objects are fine) → `getSetting`/`setSetting` (JSON-encode into the `app_settings`
key/value row). The `useSetting`/`useSetSetting` hooks wrap this over React-Query.

Rejected: zustand `persist` with a custom async `StateStorage`. Rationale (research-backed):

1. `persist` writes on **every** `set` with no debounce — one IPC + SQLite write per width-drag pixel or
   pane toggle.
2. With an **async** storage, `persist` hydration resolves on a later microtask, so the store holds
   pre-persist defaults for a window (flash) unless every reader gates on `hasHydrated()`.
3. `createJSONStorage` swallows getter errors and its writes are fire-and-forget with no coalescing — we
   would re-implement debouncing anyway.

So two seams, mirroring the existing `usePdfOpenId` precedent:

- **Read side (boot, synchronous-at-first-render).** Some restores — the feed scroll especially — must be
  available *at first render* to be flash-free (§Feed scroll: `initialMeasurementsCache`/`initialOffset`
  are consumed only during the virtualizer's first render). So the app reads the whole persistence set in
  **one batched round-trip on boot** and **gates the first mount of the restorable surfaces on that read**:
  - New additive IPC **`settings:getMany(keys: string[]) → Record<string, unknown>`** (Zod:
    `SettingsGetManyInputSchema = z.object({ keys: z.array(z.string().min(1).max(120)).max(64) })`), a
    thin loop over `getSetting`. One round-trip instead of N. **`pdf.openDocId` joins this key set** so
    boot is a single round-trip (the existing `usePdfOpenId` `settings:get` is folded in, not run
    separately).
  - A `useSessionSnapshot()` React-Query hook reads those keys once, **Zod-safe-parses** each into a
    typed value (or its default on failure), and exposes a `SessionSnapshot`.
  - **The boot gate is load-bearing and must gate on snapshot-readiness, not on notes.** Today the feed
    placeholder swaps to `<Feed>` on `notes.length !== 0` (`App.tsx:1099`) and the boot splash lifts on
    `!notesPending` (`App.tsx:490-497`) — *neither* waits for the snapshot query. Because
    `initialMeasurementsCache`/`initialOffset` are consumed **only at the virtualizer's first render**, if
    the notes query resolves before the snapshot query the Feed mounts with `restore=undefined` and the
    scroll restore is **permanently lost**. So v0.7 changes the gate: **hold Feed's first mount (and the
    splash) until `snapshotQuery.isSuccess && !notesPending`.** Snapshot-readiness is the new load-bearing
    condition.
- **Write side (debounced).** A `usePersistedWrite<T>(key, value, { debounceMs })` hook writes `value`
  through `api.settings.set` on a trailing debounce **after** hydration, plus a **flush on
  `visibilitychange`→hidden** (the reliable last-chance in an Electron renderer; `beforeunload`/`pagehide`
  are best-effort for an async IPC — see §Risks). Debounced writes are **cancellable** so a clear (e.g. a
  sent draft) can abort a pending trailing write. For the zustand `dockStore`, the equivalent is a
  module-level debounced `subscribe` writer.

`dockStore` gains a `hydrated: boolean` flag and a `hydrate(snapshot)` action (bulk-apply
`openPaneIds`/`activeId`/`widths`/`collapsed`, **clamping each width through `clampWidth` for its dock
kind** so a restored value can't sit out-of-band). The debounced subscriber writes back only once a
*post-hydrate* change occurs (it flips a "dirty" latch on the first change after `hydrate`, so the hydrate
itself is never echoed to disk).

## Data model (no migration — new `app_settings` keys, Zod-validated on read)

Each group is one JSON value under one key. All shapes have a Zod schema in `src/shared/zod-schemas.ts`;
reads use `.safeParse` and fall back to the default on failure (defensive against schema drift / manual
edits). Versioned key suffixes (`.v1`) let us bump a shape without a migration (old key ignored → default).

| Key | Zod shape (v1) | Default | Notes |
|---|---|---|---|
| `dock.layout.v1` | `{ left:{openPaneIds:string[], activeId:string\|null}, right:{…}, widths:Partial<Record<'left'\|'right',number>>, collapsed:Partial<Record<'left'\|'right',boolean>> }` | empty docks | **only utility-kind panes are persisted/restored;** content-kind panes (`pdf`,`player`) are excluded — they re-open via their media context (§Flows), never from the registry filter, so restore never yields an empty pdf/player pane |
| `ui.session.v1` | `{ focusedNoteId:string\|null, threadNoteId:string\|null }` | both null | stale ids dropped on restore via `api.notes.get`; **thread wins** — if `threadNoteId` restores, `focusedNoteId` is ignored (they are already mutually exclusive at runtime, `App.tsx:167-169`) |
| `feed.scroll.v1` | `{ snapshot: VirtualItemLite[], offset:number, anchor:{ key:string, delta:number, atEnd:boolean } \| null }` | null | `VirtualItemLite = {key,index,start,end,size,lane}` (structurally `VirtualItem`); `offset` written only when `scrollOffset != null`; `atEnd` special-cases the chat-bottom exit; see §Feed scroll |
| `thread.scroll.v1` | `Record<string, number>` (rootNoteId → scrollTop) | `{}` | **plain/pdf threads only** (YouTube roots excluded — always-on follow, `ThreadView.tsx:199`, would override); entries for missing roots dropped on read |
| `composer.draft.feed.v1` | `{ body:string, mode:'claim'\|'question' }` | null | mirrors `Composer` `{body,mode}`; cleared (and its pending write cancelled) on successful send |
| `composer.draft.thread.v1` | `Record<string, string>` (rootNoteId → body) | `{}` | per-thread; an entry is deleted when that draft is sent or emptied |
| `pdf.view.v1` | `Record<string, { zoom:number, page?:number }>` (pdfId → view) | `{}` | zoom persisted now; `page?` is the future multi-page seam |

Notes:

- **No new table, no migration.** `app_settings` (`key TEXT PRIMARY KEY, value TEXT`) already stores
  arbitrary JSON. FTS/notes are untouched.
- **`feed.scroll` payload is bounded** — `takeSnapshot()` returns only *measured* rows (roughly the
  overscan window), not the whole list, so the JSON stays small.
- **Draft maps are bounded by cleanup**, not size caps: a thread draft entry is removed on send/empty, so
  the map tracks only threads with live unsent text. (A belt-and-suspenders cap of ~200 entries with
  oldest-eviction is a plan-level detail, not a schema constraint.)

## The dependency bump (batch 0 — gates the feed-scroll work)

The pinned `@tanstack/virtual-core` **3.16.1** (via react-virtual **3.14.1**, which exact-pins it) is
missing three post-release fixes that land on this feature's exact surfaces (verified against installed
source + release notes):

- **3.17.3 / PR #1212** — viewport drift when a **side-pane width animation re-wraps feed rows while
  scrolled up** → literally linsae's dock width/collapse animations.
- **3.17.1 / PR #1199** — "items jump while scrolling up" after a mid-list restore (the 3.16.1 default
  scroll-adjustment predicate skips compensation while scrolling backward — `index.js:846`).
- **3.17.2 / PR #1209** — end-anchored streaming resize drift.

**Decision (approved): bump to `@tanstack/react-virtual` 3.14.5 / `@tanstack/virtual-core` 3.17.3 before
building restore.** react-virtual 3.14.5 exact-pins virtual-core 3.17.3, and the root range `^3.14.1`
already permits 3.14.5 — so this is a deterministic lockfile bump. It is a dependency change (CLAUDE.md
hard-gate) and is its **own batch** with an ADR and a **real-Electron Playwright smoke** — happy-dom does
no layout, so only the smoke can confirm the feed still scrolls/anchors correctly after the bump. Batch 0
ships **no feature code**, just the bump + the smoke that proves no regression.

## Surfaces & components

- **`settings:getMany` IPC + `useSessionSnapshot()`** (new). The batched boot read (incl. `pdf.openDocId`)
  + Zod-safe-parse into a typed `SessionSnapshot`. The single source of restore values.
- **`usePersistedWrite<T>(key, value, opts)`** (new, `src/renderer/src/persistence/`). Debounced,
  **cancellable** write-through + `visibilitychange` flush. Used by the component-local surfaces.
- **`dockStore`** — add `hydrated` + `hydrate(snapshot)` (utility panes only; width-clamped); module-level
  debounced subscriber writes `dock.layout.v1` after the first post-hydrate change. Content panes are NOT
  restored here — `pdf` via `pdf.openDocId`, `player` via thread restore (§Flows).
- **`Feed.tsx`** — accept `restore?: FeedScrollRestore` (from the snapshot). Decide primary-vs-fallback
  **in the render body** (so a stale `initialMeasurementsCache` is never passed): if the persisted
  `snapshot` indices still match the current notes, pass `initialMeasurementsCache` + `initialOffset` into
  `useVirtualizer` (exact, flash-free); otherwise pass neither and run the anchor fallback. Add a throttled
  scroll listener capturing `takeSnapshot()` + `scrollOffset` (guarding the `null` pre-measure case) +
  `{key, delta, atEnd}` into `feed.scroll.v1`.
- **`App.tsx`** — hydrate `focusedId`/`threadNoteId` from the snapshot (thread wins; drop ids where
  `api.notes.get(id)` resolves null). Persist them via `usePersistedWrite`. **Suppress the
  `focusedId`→auto-open-backlinks effect (`:463-467`) for the restore-sourced initial `focusedId`** via a
  `restoredFocusRef` the effect checks-and-clears on its first run — otherwise restoring a non-null
  `focusedId` calls `openPane('backlinks')`, which steals `activeId` and clears `collapsed` (`dockStore.ts:103-104`),
  corrupting the just-hydrated dock (see Risks/Testing for the two exact failure states).
- **`ThreadView.tsx`** — restore/persist the plain `scrollTop` keyed by root note id, **plain/pdf branch
  only** (YouTube excluded).
- **Composers** — feed `Composer` reads/writes `composer.draft.feed.v1` (`{body,mode}`); `SimpleComposer`
  reads/writes `composer.draft.thread.v1[rootId]`; the YouTube `ThreadComposer` persists only its `draft`
  text (not `frozenAt`/chip state). All clear their entry **and cancel any pending debounced write** on
  successful send (the feed Composer remounts via a `successCount` key, `App.tsx:177-181`, so the pending
  write must be aborted or it resurrects the sent draft).
- **`PdfReader.tsx`** — read `pdf.view.v1[pdfId]?.zoom` as the initial zoom (**overriding the
  reset-to-fit on doc swap**, `:66-68` — a deliberate behavior change, called out for review); persist
  zoom on change.

## Key flows

### Boot hydration (order matters)
1. App mounts → `useSessionSnapshot()` fires one `settings:getMany([...keys, 'pdf.openDocId'])`; hold the
   boot gate (splash + Feed first mount) until `snapshotQuery.isSuccess && !notesPending`.
2. `dockStore.hydrate(dockLayout)` — re-open the persisted **utility** panes, set active, apply widths
   (clamped) + collapsed. Content panes are handled separately: `pdf` re-opens iff `pdf.openDocId` restored
   a live document; `player` is not restored from `dock.layout` at all — it returns when its YouTube thread
   restores (step 3).
3. Hydrate selection/thread from `ui.session` with **thread precedence**: if `threadNoteId` restores and
   `api.notes.get(threadNoteId)` is non-null, open that thread (and, for a YouTube root, its player pane +
   the derived `player.videoId`); ignore `focusedNoteId`. Else if `focusedNoteId` resolves non-null, set it
   — but mark `restoredFocusRef` so the `:463-467` backlinks effect skips its first run (the dock already
   encodes whether backlinks was open). Ids that resolve null are dropped.
4. `Feed` mounts (gate satisfied) with `initialMeasurementsCache`/`initialOffset` chosen in its render body
   → position restored during first render, **before paint**. Verified on 3.16.1 that the seeds are
   consumed in `getMeasurements()`/`getScrollOffset()` in the render body and that `anchorTo:'end'` does
   not override them (anchor recompute gated on a prior `setOptions` absent on first mount) and
   `followOnAppend` self-gates on `isAtEnd`; **this analysis is re-validated on the shipped 3.17.3 by the
   Playwright smoke** (3.17.x changed adjacent scroll-adjustment code — §ADRs).
5. Composers/PdfReader read their drafts/zoom from the snapshot as initial values.

### Write-through (all surfaces)
On change, schedule a trailing debounced `settings:set` (scroll ~150–300ms, drafts ~300–500ms, dock
~400ms). Coalesce "last value wins" per key; a clear cancels the pending write. Flush all pending writes on
`document.visibilitychange` when `document.hidden` (authoritative). `beforeunload`/`pagehide` fire a
best-effort flush; for a guaranteed final write on quit, a main-process `before-quit` hook may request one
last flush (plan decides; acceptable fallback is up to one debounce-interval of loss).

### Feed scroll: primary + fallback (fallback is the common case)
Any note added/deleted since last session shifts indices, so the exact path is the *lucky* case and the
anchor path is common — both are handled pre-paint:
- **Primary (indices still match):** pass the persisted `takeSnapshot()` as `initialMeasurementsCache` +
  `initialOffset` — exact, flash-free.
- **Fallback (indices changed but `anchor.key` still exists):** pass no seed; in a `useLayoutEffect`
  guarded by a `didRestore` ref (once, `count>0`) call `scrollToIndex(indexOf(anchor.key), {align:'start'})`.
  (`align:'start'` lands the anchor row at the top; the sub-row `delta` is dropped — acceptable; a
  `scrollToOffset(getOffsetForIndex + delta)` refinement is a plan option.)
- **`atEnd` special-case (the common chat exit):** if `anchor.atEnd` was true, restore to the **new**
  bottom (`scrollToEnd`/anchor to end) rather than the saved anchor row — the user left at the bottom and
  expects the newest, not their old last row.
- **Anchor gone too:** default (bottom) — the current behavior.
- Capture from a **throttled scroll listener**, never the virtualizer `onChange` (naive persist-from-
  `onChange` risks the "Maximum update depth exceeded" loop, issue #1076).

### Stale references (must never hard-error)
- Deleted focused/thread note (`api.notes.get` → null) → drop the id, land on the feed.
- Deleted PDF (`pdf.openDocId` resolves to nothing) → existing `usePdfOpenId` handles the absent doc; drop
  the `pdf` pane.
- `thread.scroll`/`composer.draft.thread` entries for missing roots → ignored on read, pruned lazily.

## Testing (per CLAUDE.md; node-env pins where pure)

- **Unit (Vitest):** every persisted-value Zod schema — valid round-trips, and a malformed/legacy value
  `.safeParse`s to its default. Debounce/coalesce helper: N rapid changes → one trailing write of the last
  value; a clear **cancels** a pending write; `visibilitychange` flushes immediately. Feed-scroll
  decision: indices-match → primary; indices-changed but anchor present → `scrollToIndex` target;
  `atEnd` → new-bottom; anchor gone → default. Draft-map prune: missing-root entries dropped.
- **Component (Vitest + RTL, `renderWithProviders` + `installMockApi`):** boot hydration opens the
  persisted **utility** dock panes + sets active/widths/collapsed (mock `settings:getMany`); **a content
  pane (`pdf`/`player`) is NOT re-opened empty**; **restoring a non-null `focusedId` does not steal the
  hydrated `activeId` and does not clear a hydrated `collapsed`** (the two #1 failure states — assert both
  against a `right = {openPaneIds:['pdf','backlinks'], activeId:'pdf'}` and a collapsed-right fixture);
  **thread precedence** (both persisted → thread opens, focus ignored); a stale (missing) thread/focus id
  is dropped, not thrown; feed draft `{body,mode}` and a per-thread draft restore into their composers and
  clear (with write cancelled) on send; PDF zoom restores. (happy-dom can't verify scroll geometry — assert
  the props passed into `useVirtualizer`, not pixels.)
- **Integration (Vitest, real disk + real SQLite in `mkdtempSync`):** `settings:set` a full session →
  `settings:getMany` returns it → each Zod-parses back; round-trip is idempotent; `getMany` on absent keys
  returns nulls, not errors; `getMany` includes `pdf.openDocId`.
- **Electron smoke (Playwright) — load-bearing (happy-dom is scroll-blind):** (a) batch-0 bump regression —
  the feed still scrolls, chat-anchors to end on new notes, and prepends without jump on 3.14.5/3.17.3;
  (b) restore round-trip — scroll to a mid-feed position, relaunch (persisted snapshot), land at the same
  position with **no visible jump**, and confirm the batch-3 assertion that `anchorTo:'end'` does not
  override the restore *on 3.17.3*; (c) dock width/collapse animation does not drift the feed (the #1212
  fix).

## Risks

- **Feed scroll restore fragility** — the historically fraught surface (the whole `react-virtuoso →
  @tanstack/react-virtual` migration, ADRs 0003/0004/0005). Mitigated by the batch-0 bump (fixes
  #1199/#1212 that hit our surfaces), the render-body seed decision (flash-free, never a stale cache), and
  the Playwright smoke as the gate on the *shipped* 3.17.3. happy-dom cannot verify any of it.
- **Boot gate wrong condition** — if the gate stayed on `notes.length===0` the scroll restore would be
  silently lost when notes resolve first; batch 1 must gate on `snapshotQuery.isSuccess && !notesPending`
  (called out because the current code does not).
- **`focusedId`→backlinks clobber** — restoring a non-null `focusedId` would `openPane('backlinks')` and
  steal `activeId` / clear `collapsed`; the `restoredFocusRef` suppression is load-bearing and has two
  named regression tests (activeId theft, collapse clobber).
- **`anchorTo:'end'` fighting restore** — retired by evidence on 3.16.1 (anchor recompute gated on a prior
  `setOptions`; `followOnAppend` self-gates on `isAtEnd`) **but re-verified on 3.17.3 by the smoke**;
  `suppressFollow`-for-first-tick is the belt-and-suspenders fallback.
- **Write thrash** — every surface debounces; scroll/keystroke never write per event; one in-flight write
  per key; clears cancel pending writes.
- **Last-write on quit** — `visibilitychange=hidden` is authoritative; `beforeunload` async IPC is
  best-effort (may lose up to one debounce interval). A main-process `before-quit` flush is the mitigation
  if measured loss is unacceptable.
- **dockStore hydrate echo / out-of-band width** — the writer only fires after the first post-hydrate
  change (no echo), and `hydrate` clamps widths per dock kind so a restored content-band width (with the
  content pane dropped) can't sit out-of-band.
- **Draft-map growth** — bounded by clear-on-send; optional oldest-eviction cap if dogfooding shows growth.
- **Zoom-restore changes reset-to-fit** (`PdfReader.tsx:66-68`) — an intentional behavior change; flagged
  for review, covered by a component test.
