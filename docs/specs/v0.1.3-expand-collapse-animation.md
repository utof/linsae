# v0.1.3 — animated, orientation-preserving note expand/collapse

## Context

Notes over `BODY_TRUNCATE_AT` (4096) chars render truncated with a fade-out +
an "expand (N words)" control (`NoteBubble.tsx`). Today, expanding/collapsing:

1. **Disorients on collapse** — collapsing a tall note removes
   `(expandedHeight − collapsedHeight)` px and nothing compensates, so the feed
   content below jumps *up* by potentially thousands of px. The user is
   "teleported" away from where they were reading.
2. **Has no usable animation** — a WAAPI height tween runs on the note's inner
   markdown wrapper, but the sibling notes below are positioned by the
   virtualizer with `transform: translateY(...)` and **no transition**, so they
   snap to new positions instantly. The feed-level motion reads as a jump. A
   rAF-vs-React-commit race in `handleToggleExpand` can also early-return and
   skip even the note's own tween.
3. **Jitters the scrollbar** — the height tween changes the item's height every
   frame; tanstack-virtual's `measureElement` (async ResizeObserver) re-measures
   each frame, so `getTotalSize()` / `scrollHeight` change ~14× in a row and
   `useScrollThumb`'s size-change transition (100ms coalesce vs 240ms tween)
   chases the moving target → the thumb wobbles.

All three share one root cause: a height change is treated as an instantaneous
relayout (siblings snap), the manual height tween keeps the **async**
measurement in the animation loop (jitter + race), and nothing preserves the
user's scroll anchor across the size delta.

The feed uses `@tanstack/react-virtual` with dynamic `measureElement` and
`anchorTo: 'end'` (ADR 0005); the scrollbar is custom (`useScrollThumb`,
ADR 0003).

## Goals

- Collapsing a note is **orientation-preserving**: the notes below it stay
  fixed on screen; the note rolls up under them; the scrollbar glides
  monotonically.
- Expanding keeps its current top-anchored feel (grows downward), but is now
  smoothly animated and jitter-free.
- No new runtime dependency. No layout-animation library.

## Non-goals

- Changing *what* expand/collapse shows (truncation rules, fade overlay,
  word-count affordance) — unchanged.
- Animating arbitrary feed size changes (new-note append, window resize,
  external edits) — out of scope; only the user-initiated expand/collapse.
- Visual-regression coverage of the animation (deferred to v0.2 per CLAUDE.md).

## Behavior

### Collapse — bottom-anchored ride-up
The note's height eases full → truncated over ~240ms (ease-out). The scroll
position is driven from the **same clock** so the note's **bottom edge** holds
its exact screen position throughout — therefore every note below it is
pixel-stable. The note's top descends and its body rolls up under
`overflow: hidden`. Net effect: "the note rolls up while the notes below stay
put and I keep my place."

### Expand — top-anchored grow-down (feel unchanged)
The note's top edge holds; height eases truncated → full; content below is
pushed down. Same ~240ms ease-out clock, same jitter-free mechanism — only the
anchor edge differs (top instead of bottom, i.e. no scroll compensation).

## Technical approach

One synchronous animation clock; **no async measurement inside the loop**.

`startH`/`endH` below are **item heights** (the full virtual-item height the
virtualizer tracks). The thing we actually animate is the body clip; we set the
body clip each frame so the *rendered item height equals the interpolated item
height*. Concretely, `bodyClip = h − nonBodyHeight`, where `nonBodyHeight` is
the item's fixed chrome (Feed-wrapper padding + bubble padding/border + the
expand-row) measured once at toggle and held constant for the morph.

On toggle (FLIP-style measure):
1. Record `startH` = the item's current measured height, `nonBodyHeight`, and
   the anchor edge's current screen position.
2. Flip the note's expanded state so content swaps; measure `endH` (the item's
   natural height with the new content) in a layout effect, then immediately
   clamp the body clip so the item is back at `startH` — no visual jump before
   the tween starts.
3. Run a `requestAnimationFrame` clock `t: 0→1` (ease-out, ~240ms). Each frame,
   with `h = lerp(startH, endH, ease(t))`:
   - set the body clip height to `h − nonBodyHeight` (`overflow: hidden` →
     roll-up), so the rendered item height is `h`;
   - call `virtualizer.resizeItem(index, h)` so below-items and total size
     track **synchronously** (no ResizeObserver lag);
   - **collapse only:** set `scrollEl.scrollTop` so the bottom anchor holds
     (`scrollTop = noteStart + h − bottomScreenOffset`); expand sets nothing.
4. For the morph's duration:
   - the animating item uses `resizeItem` and therefore must **not** also be
     observed by `measureElement` (docs: mixing the two on one item is
     "unpredictable"); detach `measureElement` from this one index for the
     duration, then re-attach;
   - `shouldAdjustScrollPositionOnItemSizeChange` returns `false` so the
     virtualizer's own scroll correction doesn't fight our manual anchor;
   - `useScrollThumb`'s size-change ("resizing") transition is suppressed so the
     thumb tracks the smooth `scrollTop` instead of chasing per-frame size
     changes.
5. On finish: release the clamp (natural height), re-attach `measureElement`,
   take one final measure, restore `shouldAdjustScrollPositionOnItemSizeChange`
   and the thumb transition.

### Components & wiring
The spatial animation must live where the virtualizer is — **`Feed`** (it owns
`resizeItem`, the scroll element, `shouldAdjustScrollPositionOnItemSizeChange`).
Therefore:

- **Lift expand state to `Feed`**: `Feed` holds `expandedIds: Set<string>` and
  passes `expanded={expandedIds.has(note.id)}` plus a stable id-taking
  `onToggleExpand` down to `NoteBubble` (same stable-callback shape adopted for
  the React Compiler in ADR 0006 — no per-`.map()` closures).
- **`NoteBubble` becomes presentational re: expansion**: it renders truncated
  vs full from the `expanded` prop and exposes its clip wrapper (the existing
  `markdownWrapRef` body wrapper) so `Feed` can drive its height. It loses its
  local `expanded` state and the WAAPI `handleToggleExpand`.
- **`Feed.onToggleExpand(id)`** runs the FLIP-measure + rAF morph above.
- **`useScrollThumb`** gains a way to suppress its size-change transition during
  a morph (e.g. a ref flag set by `Feed` for the morph window), so programmatic
  `scrollTop` glides read as normal scroll, not a resize.

### Edge cases
- **Toggle during an in-flight morph** (double-click): cancel the running rAF,
  snap to the in-flight target, start the new morph from the current height.
- **Collapse near the very top of the feed**: `scrollTop` can't go below 0;
  clamp. The bottom anchor then can't fully hold — accept the residual (rare,
  and the note is already near the top so disorientation is minimal).
- **Collapse/expand of an item scrolled partly off the top**: handled by the
  same bottom/top anchor math; `shouldAdjustScrollPositionOnItemSizeChange` is
  off so only our math moves scroll.
- **Component unmount mid-morph** (virtualized out): cancel rAF, re-enable
  `measureElement`, leave the virtualizer size at the last value (next mount
  re-measures).
- **`prefers-reduced-motion`**: skip the tween, apply the final size + anchored
  scroll instantly (this is the fallback path, below).

### Fallback (same code path)
If the synchronized morph is disabled (reduced-motion) or a future content type
proves fragile: instant `resizeItem(endH)` + instant anchored `scrollTop`. Still
fully orientation-preserving — just no tween.

## Testing
- **Unit (Vitest/jsdom):** the scroll-anchor math as a pure function —
  `f(noteStart, startH, endH, bottomScreenOffset, t) → scrollTop`, asserting
  the bottom edge is invariant across `t` for collapse and that expand returns
  the unchanged `scrollTop`. Plus the lerp/ease and the in-flight-cancel target.
- **Component (Vitest + RTL):** toggling `onToggleExpand` flips `expandedIds`
  and `NoteBubble` renders full vs truncated body; `prefers-reduced-motion`
  applies final state without scheduling rAF. (jsdom has no real layout, so the
  morph frames themselves aren't asserted.)
- **Manual:** `pnpm dev` + `DevFpsMeter` — collapse a long note mid-feed, confirm
  below-notes are pixel-stable, the roll-up is smooth, and the thumb doesn't
  wobble. Repeat for expand.

## ADRs to write
- **ADR 0007** — Animating item resize in a measured virtual list: `resizeItem`
  + manual scroll anchor + `measureElement` detached during the morph, vs. the
  rejected alternatives (instant relayout; keep-WAAPI). Records the
  `resizeItem`-XOR-`measureElement` constraint and the
  `shouldAdjustScrollPositionOnItemSizeChange` suppression.

## Risks
- Coupling to virtualizer internals (`resizeItem`, the scroll-adjust callback) —
  inherent to animating in a virtual list; revisit if the virtualization library
  changes.
- The detach/re-attach of `measureElement` mid-life touches React 19 ref-callback
  semantics (ADR 0004) — must be done carefully to avoid detach→reattach churn.
