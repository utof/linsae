# v0.2.5 — Screenshot annotation editor (non-destructive drawing overlays)

## Context

v0.2 (`docs/specs/v0.2-youtube-annotation.md`) shipped quick timestamp comments
and **immutable PNG** screenshot capture of the pinned YouTube player. It
**deliberately carved out** the drawing editor (spec §Scope "v0.2.x — carved
out (own design pass + own spec)"; §Non-goals "Drawing on screenshots …
deferred to v0.2.x"). That carve-out is this milestone.

The carve-out named the feature set verbatim: *"perfect-freehand strokes, text
overlay, color swatches, the `<hash>.svg` sidecar, open-editor-on-capture, and
the Esc 'discard / keep as orphan' prompt."* It also pre-provisioned the data
model so **no migration is needed**: `attachments.overlay_path TEXT` (nullable,
`NULL` until drawn, `0002_video_threads.sql:26`) and the `'clip'` kind (the
`kind` CHECK, `0002_video_threads.sql:23,34`) already exist, the `Attachment`
type already carries
`overlay_path: string | null` (`src/shared/types.ts:64`), and the loopback HTTP
shell already serves `.svg` as `image/svg+xml` (`src/main/http-shell.ts:53`).

This spec is the single authoritative contract for the **`ink` module API, the
SVG sidecar file format, the editor behavior, the IPC surface, and the render
integration**. The plan decomposes it into batches that all bind to the
contracts here.

### Strategic framing (informational — explains the module boundary; builds nothing extra)

This editor is a bounded, low-risk rehearsal of the *ink layer* from the
long-term mind-map / spatial-canvas roadmap (see `v0.2-youtube-annotation.md`
§Forward direction). The hard parts of a canvas — infinite zoom, LOD, culling,
externally-driven layout — **do not exist here**: the surface is a fixed 16:9
PNG. By writing stroke capture, `getStroke` handling, and SVG serialization as a
**context-free `ink` module** (zero imports from screenshot/attachment/thread
code), the future canvas consumes the exact same module unchanged. This is a
design constraint, not extra scope.

## Scope

**v0.2.5 — this spec.** A drawing editor over a captured frame, with **four
tools**: pen (perfect-freehand pressure strokes), text overlay, color swatches,
and a **whole-stroke eraser**. Annotations persist as a **non-destructive SVG
sidecar** (the base PNG is never modified) referenced by
`attachments.overlay_path`. The editor opens **two ways**: on capture (`⌘⇧C`,
before posting) and by **reopening an already-posted screenshot**. Two new write
IPCs (`youtube.saveOverlay` and `attachments.remove`); reads reuse the existing
`/_media` fetch path.

**Non-goals**
- **Partial / pixel eraser** — whole-stroke deletion only; partial erase is
  filed as an issue after the plan (unless the plan shows both are cheap to ship
  together).
- **Annotating non-YouTube / arbitrary images** — only `screenshot`-kind
  attachments captured from the player.
- **Shapes / arrows / fills beyond freehand + text** — not in this milestone.
- **Multi-attachment notes** — v0.2.0's 1:0..1 comment-note↔screenshot
  cardinality is unchanged (spec §Cardinality). The editor edits one frame.
- **A reopen UI in the main rolling feed** — the reopen affordance lives in the
  ThreadView Rail (the confirmed frame-render site, `Rail.tsx:117-134`). If
  screenshot comment-notes render frames elsewhere, that site reuses the same
  `AnnotatedFrame` component (so overlays appear) but grows no new editor entry.
- **Migration** — additive only; the schema was provisioned in v0.2.

## Goals

- Draw pressure-sensitive ink + place text on a captured frame, in image-pixel
  coordinates, so the overlay scales perfectly with any container.
- Persist annotations **non-destructively**: the immutable PNG is untouched; the
  overlay is a separate SVG sidecar that can be edited or removed at any time,
  reverting the frame to its original capture.
- Keep annotations **re-editable**: reopening a saved overlay restores every
  individual stroke/text element (move, recolor, erase, re-tessellate), not a
  flattened bitmap.
- Reuse the v0.2 capture/attachment/serving infrastructure with **two** new
  write IPCs and **no** migration.
- Confine all stroke/SVG logic to a **context-free `ink` module** reusable by
  the future canvas.

## Data model — no migration

`attachments` (from `0002_video_threads.sql`) is used as-is:

- `overlay_path TEXT` — absolute path to this attachment's SVG sidecar, or
  `NULL` when the frame has no annotations. Set/cleared by `saveOverlay`.
- `width_px` / `height_px` — the PNG's intrinsic physical-pixel dimensions;
  these define the overlay's coordinate space (the SVG `viewBox`).
- `base_path` / `base_sha256` — the immutable PNG; never modified by this
  milestone.

### Sidecar identity — keyed by attachment id, NOT by sha256 (correction)

The `0002` provisioning comment reads *"path to `<hash>.svg` sidecar."* That is
**wrong under content-hash dedup** and this spec supersedes it: captures of
identical bytes share **one** PNG file but get **distinct** `attachments` rows
(`v0.2-youtube-annotation.md` §Cardinality; ADR 0009 §Consequences). Two such
attachments may carry **different** annotations, so a sha-keyed sidecar would
clobber. The sidecar is therefore keyed by the **attachment `id`** (unique per
row):

```
<userData>/attachments/<yyyy>/<mm>/<attachmentId>.svg
```

placed in the **same `yyyy/mm` directory as the base PNG** (so the last-3-segment
`mediaUrlFromPath` contract, `src/renderer/src/lib/media-url.ts`, applies
unchanged). `overlay_path` stores this absolute path.

## The `ink` module — `src/renderer/src/ink/` (context-free)

**Hard rule:** files under `src/renderer/src/ink/` import only `perfect-freehand`
and DOM/React; **no import** from `thread/`, `feed/`, `lib/api`, `shared/`, or
attachment code. Verified by review (and a future canvas consumer).

### Scene model — `ink/types.ts`

A single ordered `elements` array preserves z-order (draw order = paint order);
the eraser removes by `id`.

```ts
export interface InkPoint { x: number; y: number; pressure: number } // image-pixel space
export interface Stroke {
  id: string            // minted by the editor via crypto.randomUUID(); stable, used by eraser
  kind: 'stroke'
  points: InkPoint[]    // raw input points (NOT the outline) — re-tessellatable
  color: string         // CSS color (a swatch value)
  size: number          // perfect-freehand `size` (px in image space)
  simulatePressure: boolean // false when the device reported real pressure; true for mouse/touch
}
export interface TextBlock {
  id: string            // minted by the editor via crypto.randomUUID()
  kind: 'text'
  x: number; y: number  // top-left in image-pixel space
  width: number         // wrap width (px)
  height: number        // measured rendered height (px); serialized numeric, parse ignores+remeasures
  text: string
  color: string
  fontSize: number      // px in image space
}
export type SceneElement = Stroke | TextBlock
export interface Scene {
  width: number         // = attachment.width_px  (viewBox width)
  height: number        // = attachment.height_px (viewBox height)
  elements: SceneElement[]
}
```

### Stroke geometry — `ink/stroke.ts`

`getSvgPathFromStroke` is **not** a `perfect-freehand` export — it is the ~15-line
helper from the package README (verified via context7,
`/steveruizok/perfect-freehand`). It is **vendored** into this file (with a
`@see` to the README). The only package API consumed is
`getStroke(points, options) → number[][]` (outline polygon).

```ts
import { getStroke } from 'perfect-freehand'

/** Fixed feel constants (tuned for screenshot markup). */
export const STROKE_OPTS = { thinning: 0.5, smoothing: 0.5, streamline: 0.5 } as const

/**
 * Stroke → SVG path `d` (outline). `size` and `simulatePressure` come from the
 * stroke. CRITICAL: `getStroke`'s `simulatePressure` defaults to `true`, which
 * derives pressure from velocity and IGNORES the recorded per-point pressure —
 * so a stylus's real pressure is dead data unless we pass `simulatePressure:
 * false`. The editor sets it false when the device reported real pressure.
 */
export function strokeToPath(stroke: Stroke): string {
  const outline = getStroke(
    stroke.points.map((p) => [p.x, p.y, p.pressure]),
    { size: stroke.size, simulatePressure: stroke.simulatePressure, ...STROKE_OPTS },
  )
  return getSvgPathFromStroke(outline) // vendored helper, closed=true
}

// vendored from perfect-freehand README — @see https://github.com/steveruizok/perfect-freehand#rendering
function getSvgPathFromStroke(points: number[][], closed = true): string { /* … */ }
```

### Serialize / parse — `ink/svg.ts`

```ts
export function serializeScene(scene: Scene): string
export function parseScene(svg: string): Scene
```

**Serialize** emits a standalone, raw-viewable SVG:
```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 {width} {height}">
  <path d="{strokeToPath}" fill="{color}"
        data-ink="stroke" data-id="{id}" data-size="{size}" data-sim="{simulatePressure}"
        data-points="{x},{y},{p} {x},{y},{p} …"/>
  <foreignObject x="{x}" y="{y}" width="{width}" height="{height}"
        data-ink="text" data-id="{id}" data-color="{color}" data-font="{fontSize}">
    <div xmlns="http://www.w3.org/1999/xhtml" style="…">{text}</div>
  </foreignObject>
</svg>
```
- Strokes write **both** the outline `d` (so the file renders standalone) **and**
  `data-points` (raw input, the re-editable source of truth).
- Text `height` is a **measured numeric value** (the editor measures the rendered
  div), never `auto` — `auto`/an invalid length computes to `0` on `foreignObject`
  and the text would render zero-height even in a browser, breaking the
  "standalone, raw-viewable" guarantee. On parse the stored `height` is read for
  standalone fidelity but **re-measured** when the editor reopens (like `<path d>`).
- The `viewBox` is `0 0 width height` (image-pixel space).

**Parse** is the inverse and is **defensive** (the SVG is local but
user-/hand-editable): it walks elements via `DOMParser`, reads `data-ink` /
`data-id` / `data-points` / `data-color` / `data-size` / `data-font`, and
**reconstructs the `Scene` from the `data-*` attributes only — the `<path d>`
geometry is ignored and recomputed on render**. This is the XSS boundary: stored
markup is never injected (see ADR 0026). Unknown/garbage elements are skipped.
Round-trip invariant: `parseScene(serializeScene(s))` preserves every element's
`points`/`simulatePressure`/`text`/`color`/`size`/`position` (numbers to 2-dp,
the serialized precision); `id` and z-order are preserved; text `height` is
re-measured rather than asserted.

### Presentational renderer — `ink/SceneSvg.tsx`

A pure, read-only React component shared by the editor and the Rail:

```tsx
export function SceneSvg(props: {
  scene: Scene
  /** Per-element pointer handlers (editor supplies; Rail omits → inert). */
  onElementPointerDown?: (id: string, e: React.PointerEvent) => void
  onElementPointerEnter?: (id: string, e: React.PointerEvent) => void
}): JSX.Element
```
When no handlers are supplied (the Rail's read-only mode) the root `<svg>` sets
`pointer-events: none` so the inert overlay never swallows clicks meant for the
frame beneath or the hover-pencil affordance above it.
Renders `<svg viewBox="0 0 w h" preserveAspectRatio="xMidYMid meet">` with one
`<path>` per stroke (`d = strokeToPath(stroke)`, recomputed) and one
`<foreignObject>` per text. `preserveAspectRatio="xMidYMid meet"` matches the
base image's `objectFit:'contain'`, so the overlay aligns with the letterboxed
image at any container size. The overlay is **always inline React SVG, never an
`<img>` of the sidecar** — an SVG loaded as an image is inert (its elements
cannot receive pointer events, fatal for the editor), reconstructing from
`data-*` instead of injecting stored markup is the XSS boundary, and inline
strokes re-tessellate crisply at any size instead of scaling a raster (ADR 0026).

## Surfaces & components — `src/renderer/src/annotate/`

The editor and the read-only frame wrapper live **outside** `ink/` (they know
about attachments + IPC; `ink/` does not).

### `AnnotatedFrame.tsx` — read-only base + overlay (used by the Rail)

```tsx
export function AnnotatedFrame(props: {
  attachment: Attachment
  onReopen?: () => void   // hover-pencil affordance; omit → no edit entry
}): JSX.Element
```
A positioned container: the base `<img src={mediaUrlFromPath(base_path)}>`
(unchanged from `Rail.tsx:128-132`) with, when `overlay_path != null`, an
absolutely-positioned `<SceneSvg>` on top whose scene is fetched+parsed from
`mediaUrlFromPath(overlay_path)` (a hook, below). When `onReopen` is supplied, a
**hover pencil button** (top-right) opens the editor. `Rail.tsx` swaps its inline
`<img>` block (`Rail.tsx:117-134`) for `<AnnotatedFrame>`.

### `useOverlay.ts` — fetch / parse / save hook

```ts
// read: same-origin GET of the sidecar text → parseScene (no IPC)
useOverlayScene(attachment): { scene: Scene | null; loading: boolean }
// write: serializeScene → api.youtube.saveOverlay (facade) → invalidate
saveOverlay(attachment, scene): Promise<void>
```
- **Read:** a React Query query keyed `['overlay', attachment.id, attachment.overlay_path]`
  fetches `mediaUrlFromPath(overlay_path)` as **text** (the shell returns
  `image/svg+xml`; `r.text()` is content-type-agnostic) → `parseScene`. Because
  the sidecar URL is stable across edits (`<attachmentId>.svg`) and the shell
  sends no validators (`http-shell.ts:158`), the fetch uses **`{ cache: 'no-store' }`**
  so an edited overlay is never served stale.
- **Write:** calls the IPC through the `lib/api` facade, then
  `queryClient.invalidateQueries({ queryKey: ['overlay', attachment.id] })` so the
  Rail re-renders with the new scene.

### `AnnotateEditor.tsx` — the modal editor

A modal over an enlarged 16:9 frame (base `<img>` + interactive `<SceneSvg>` +
toolbar), styled from v21 tokens (`colors_and_type.css`). Holds the working
`Scene` in local state.

- **Toolbar:** pen · text · eraser tool toggle; color swatches (from v21 accent
  palette); Done / Cancel. Active tool + active swatch use accent (the v21 "accent
  marks only what is current" rule, `v0.2-youtube-annotation.md` §Visual language).
- **Pen:** pointer down/move/up appends a `Stroke` (points captured in image
  space via the SVG CTM, below). `PointerEvent.pressure` → `InkPoint.pressure`
  (fallback `0.5`). The stroke's `simulatePressure` is set from the pointer type:
  `false` for `pointerType === 'pen'` (trust the stylus's real pressure), `true`
  for mouse/touch (no real pressure → let perfect-freehand simulate from
  velocity). See `strokeToPath`'s note on why this matters.
- **Text:** click places a `TextBlock`; an inline editable `<div>` captures text;
  drag moves it; the active swatch sets its color.
- **Eraser (whole-stroke):** while the eraser tool is active, a pointerdown/enter
  on any element removes that element from `scene.elements` by `id` (native SVG
  per-element pointer hit-testing — no geometry math).
- **Undo (`Cmd/Ctrl+Z`):** a snapshot stack of `scene.elements` is pushed before
  each mutation; undo pops it. This uniformly reverts **any** action (add-stroke,
  add-text, erase, move, recolor), not just the last drawn element — scenes are
  small (screenshot markup), so full-array snapshots are trivial. **No redo**
  (YAGNI; the eraser already covers "remove a specific element"). *Decided in
  brainstorm review: undo muscle-memory is strong and a snapshot stack is ~15
  lines.*
- **Coordinate mapping:** client → image-pixel space via
  `svg.getScreenCTM()!.inverse()` applied to the pointer, so strokes are stored
  in `viewBox` units regardless of container size or letterboxing.
- **Default stroke size** is scaled by `attachment.device_pixel_ratio` (sizes are
  in image-pixel space, and `width_px = rect × scaleFactor`, `media.ts:57`), so a
  default pen reads the same relative thickness on a DPR-2 capture as a DPR-1 one.
  Feel-only, not correctness.

### `Rail.tsx` integration

`Rail.tsx:117-134` replaces its raw `<img>` with `<AnnotatedFrame attachment=…
onReopen={openEditorFor(attachment)}>`. No other Rail logic changes.

## Key flows

### Capture-time (open-editor-on-capture)
`⌘⇧C` → existing `youtube.capture` writes the PNG + an **orphan** `attachments`
row (`note_id NULL`) and returns `{ id, … }` (unchanged) → **the editor modal
opens** on that frame → user draws (or not):
- **Done with a non-empty scene:** `saveOverlay(attachmentId, svg)` sets
  `overlay_path` → modal closes → the composer's pending-frame chip shows the
  **annotated** frame → Enter posts the comment-note and `attachToNote` sets
  `note_id` (existing v0.2 flow). **Note (contract change):**
  `ThreadComposer`'s `pendingFrame` is today `{ thumbnailUrl; t }` rendering the
  **base PNG** (`ThreadComposer.tsx:53-56`, `ThreadView.tsx:363`). To show the
  annotated frame the pending chip must carry the `Attachment` (or its id) and
  render `<AnnotatedFrame>` instead of a raw `<img>`. This prop change is part of
  batch 4 (composer wiring).
- **Done with an empty scene:** no sidecar written, `overlay_path` stays `NULL`
  (a plain frame, exactly as v0.2.0). Skipping the editor is one click.
- **Esc (never posted):** the carve-out's **"Discard / Keep as orphan"** prompt.
  *Keep as orphan* → if the scene is non-empty, `saveOverlay` first (so the
  drawing is **not** lost), then leave the orphan row for the future orphan tray.
  *Discard* → `attachments.remove({ id })` — the new write IPC over
  `softDeleteAttachment` (`src/main/db/queries/attachments.ts:132`); PNG bytes
  survive on disk, reclamation is a separate later concern, per
  `v0.2-youtube-annotation.md` §Risks (deletes do not cascade to files). If a
  sidecar was written before discard, the handler deletes it too.

### Reopen a posted screenshot
Hover pencil on an `AnnotatedFrame` in the Rail → editor opens on the parsed
scene (`overlay_path`'s sidecar, or an empty scene if `NULL`) → edit/erase/add →
- **Done:** `saveOverlay` rewrites the sidecar and `overlay_path`.
- **Done with an emptied scene (all erased):** `saveOverlay` **clears**
  `overlay_path` to `NULL` and **removes the sidecar file** — "remove all
  annotations" reverts the frame to its original capture (the Goal).
- **Esc with unsaved edits:** a **"Discard changes?"** prompt reverts to the
  saved scene (no soft-delete — the note/attachment persist).

## IPC contract (Zod-validated at the boundary, per CLAUDE.md)

Two new write handlers, mirroring `youtube:capture`'s preload/zod pattern
(`src/preload/index.ts`, `src/shared/zod-schemas.ts`). Renderer code calls them
through the **`lib/api` facade** (`src/renderer/src/lib/api.ts`, what
`installMockApi` mocks) — never `window.api` directly.

```ts
// 1. youtube namespace — write/clear the overlay sidecar
saveOverlay(args: { attachmentId: string; svg: string | null }):
  Promise<{ overlayPath: string | null }>
// 2. attachments namespace — soft-delete (used by capture-time Discard)
attachments.remove(args: { id: string }): Promise<void>
```

**`saveOverlay`**
- `svg` is the `serializeScene` output, or **`null`** to clear (empty scene).
- **Zod hardening:** `svg: z.string().startsWith('<svg').max(512_000).nullable()`
  (rejects non-SVG payloads, caps size); `attachmentId: z.string()`.
- **Handler (`src/main/ipc/media.ts`):** validates with Zod, then
  `getAttachment(db, attachmentId)` (the **newly-exported** getter, below).
  **If the row is missing or soft-deleted → throw before any file write** (no
  orphaned sidecar on disk). Otherwise derive the sidecar dir from the row's
  `base_path` + `<attachmentId>.svg`; if `svg` is a string → atomic-write
  (`src/main/media/atomic-write.ts`) + `setOverlayPath(db,{id, overlayPath})`;
  if `svg` is `null` → delete the sidecar if present + `setOverlayPath(db,{id,
  overlayPath:null})`. Returns the new `overlay_path`.
- **No `loadOverlay` IPC** — reads go through the existing same-origin `/_media`
  fetch (the sidecar is a served asset). Symmetric `loadOverlay` is intentionally
  dropped as redundant.

**`attachments.remove`** — Zod `{ id: z.string() }`; handler also deletes the
sidecar file if `overlay_path` is set, then `softDeleteAttachment(db, id)`
(`attachments.ts:132`). The single Discard entry point for a never-posted orphan.

### New DB queries — `src/main/db/queries/attachments.ts`

```ts
/** Sets (or clears, with null) an attachment's overlay sidecar path. */
export function setOverlayPath(db, args: { id: string; overlayPath: string | null }): void
//   UPDATE attachments SET overlay_path = ? WHERE id = ?   (silent no-op on unknown id, matching attachToNote)

/** Exported so the saveOverlay/remove handlers can resolve base_path + reject

export function getAttachment(db, id: string): Attachment | null
```

## Testing (TDD, per CLAUDE.md — no Playwright visual-reg)

- **Unit (Vitest):**
  - `ink/svg`: `serializeScene`→`parseScene` round-trip preserves all elements
    (points to 2-dp, text, color, size, position, z-order); parse **ignores a
    tampered `<path d>` and rebuilds from `data-points`**; parse skips
    unknown/garbage elements without throwing.
  - `ink/stroke`: `strokeToPath` returns `''` for <4 outline points, a closed
    `M…Z` path otherwise (the vendored helper's contract).
  - coordinate-mapping helper: client point + CTM → image-space point.
- **Component (Vitest + RTL, `renderWithProviders` + `installMockApi`):**
  tool switching; pen pointer sequence appends a stroke; eraser pointerdown
  removes the hit element by id; text place/edit/move; swatch sets color;
  `Cmd/Ctrl+Z` reverts the last mutation (covers both an add and an erase); both
  Esc prompts (capture-time discard/keep, reopen discard-changes); Done with
  empty scene writes no overlay; reopen loads a saved scene; `AnnotatedFrame`
  renders the overlay over the base img and shows the pencil on hover;
  `useOverlayScene` with a dangling/unparseable `overlay_path` degrades to
  no-overlay (no throw); `⌘⇧C` while the editor modal is already open is a no-op
  (re-entrancy guard). **Existing ThreadView capture tests that assert
  `⌘⇧C` → immediate pending chip must be updated** for the new open-editor step.
- **Integration (Vitest, real disk + real SQLite in `mkdtempSync`):**
  `saveOverlay` writes the sidecar atomically + sets `overlay_path` round-trip;
  `svg:null` deletes the sidecar + nulls `overlay_path`; **two attachments
  sharing one `base_sha256` get distinct `<attachmentId>.svg` sidecars** (the
  dedup-keying correctness test); **base PNG bytes are unchanged after save**
  (the non-destructive invariant).

## ADRs to write

- **0025 — Drawing overlay format: perfect-freehand + points-embedded SVG
  sidecar, keyed by attachment id.** Why SVG-with-`data-points` (re-editable +
  standalone-viewable + dumb-overlay-composable); why attachment-id keying not
  sha (dedup correctness). Alternatives: flatten-only (loses re-edit + the
  canvas-roadmap stroke model); tldraw (license key + watermark, contributions
  paused Jan 2026); Excalidraw (owns its scene, would need a second JSON
  sidecar); Konva (canvas-first, SVG becomes a conversion); Fabric (**has**
  native two-way SVG, so the shorthand "SVG is a conversion" is unfair to it —
  it lost on scene ownership, uniform-width brushes, and zero reuse on the
  canvas roadmap). **Flip condition:** if scope grows to shapes / arrows /
  transform handles, Fabric becomes the right tool for *this* editor and this
  choice should be revisited. **Portability footnote:** the sidecar is
  raw-viewable in a browser, but non-browser SVG consumers (Inkscape, Finder
  Quick Look) render strokes and may not render `foreignObject` text — do not
  promise universal rendering. Sources: perfect-freehand repo (MIT, last push
  2026-04-13, verified via gh this session), context7.
- **0026 — Overlay render: parse-to-scene → React inline SVG (never inject
  stored markup, never `<img>` the sidecar).** Rationale on three legs (the
  earlier "`foreignObject` doesn't render via `<img>`" claim is **false** in
  Chromium and is explicitly dropped — `dom-to-image` renders HTML-in-SVG via
  `<img>`; only Safari blocks it, and linsae is Chromium-only): (1) **interactivity**
  — an SVG loaded as an image is inert; its elements cannot receive input events,
  so an *editor* requires inline SVG regardless; (2) **XSS boundary** — the stored
  sidecar is user-/hand-editable, so rendering reconstructs the scene from `data-*`
  and never injects stored markup; (3) **crispness** — inline strokes re-tessellate
  via `getStroke` at the rendered size instead of scaling a fixed raster. The
  sidecar is storage only.
- **0027 — Context-free `ink` module as the canvas-roadmap seam.** A bounded
  rehearsal of the future canvas ink layer; the import boundary is the contract.

## Risks

- **perfect-freehand maintenance** — slow issue triage; the "hot elbows"
  fast-stroke artifact is open. Mitigation: it is one pure, zero-dependency
  function (~200 LoC); worst case vendor it into `ink/` (MIT). Far cheaper escape
  than the react-virtuoso burn (ADR 0005).
- **Overlay must be interactive + XSS-safe** — an SVG rendered via `<img>` is
  inert (no input events) and injecting stored markup is an XSS vector; addressed
  by always rendering inline React from a parsed scene (§SceneSvg, ADR 0026).
- **SVG XSS** — addressed by parse-to-scene (ADR 0026); never inject markup.
- **Dedup overlay-keying** — addressed by attachment-id sidecar naming + the
  integration test.
- **Coordinate drift under `objectFit:contain`** — addressed by
