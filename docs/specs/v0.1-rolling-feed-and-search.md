# linsae v0.1 — rolling feed and search

**Status:** spec (rev 2, addresses Opus review pass 1).
**Brainstorm:** 2026-05-26. **Review:** 2026-05-26.
**Owner:** utof.

## Goal

Ship a personal note-taking app the user reaches for instead of Telegram. v0.1 covers the minimal feed-and-search loop; YouTube and PDF capture land in v0.2.

Success criterion: 7 consecutive days of actual use for real notes (not test notes). Measurement: user appends a one-line entry per day to `memory/v0.1-usage.md` naming a real note created or returned-to that day. Streak resets if a day is skipped. If the user reaches for Telegram instead, v0.1 has failed and scope is revisited.

## Non-goals (v0.1)

Deferred and explicitly out of scope:

- YouTube embed, timestamp capture, `webContents.capturePage` screenshots — v0.2.
- PDF viewer, highlighting, Source-block creation — v0.2.
- Open-questions inbox as a dedicated screen — v0.2 (the data is already there).
- Tag chips, edge-type pickers, status pills, action chips, supertags — v0.3+.
- Daily-note grouping or any temporal sectioning of the feed — deliberate deviation from the v21 daily-note default.
- Left sidebar (pinned pages, saved searches, supertag explorer) — nothing to list at v0.1.
- Right-pane AI side panel — v0.2+.
- Trajectory dashboards, OLM, weekly digest, canvas, ink, mobile, sync, attachments, image paste, syntax highlighting in code blocks — v1+ unless explicitly bumped.
- Auto-update via `electron-updater`, crash reporting (Sentry / Bugsnag / LogRocket), telemetry of any kind, analytics — never at v0.1; user manually rebuilds via `pnpm run build` and runs the produced binary. The research doc explicitly anti-recommends Sentry.
- Edit history surface — v0.2 (the `note_revisions` table is pre-committed below, but the UI is deferred).
- External-file-system watcher for live changes — v0.2. v0.1 contract: **do not edit notes externally while the app is running; close the app first**. Reconciliation runs only at startup.

## User-facing surfaces

One window, three regions, all on a single screen:

1. **Topbar** — 44 px, pinned, hairline-bordered below. Left: app wordmark `linsae` (Geist 500, 14 px, `--fg-0`). Right: a `⌘K` affordance hint (`KBD` key-cap component from v21 primitives). A `≡` menu button on the right opens a small dropdown with `Reveal notes folder` (opens the OS file manager at the on-disk notes directory via `shell.openPath`). That single menu entry exists explicitly so the user can find their data on disk.
2. **Feed** — center, scrollable, single max-width 720 px column (per `v21-design-system/project/ui_kits/v21-app/feed.jsx`). Telegram-style ordering: oldest at the top, newest at the bottom. New notes append at the bottom; the scroll snaps down on send. No day separators. No `DaySeparator` component used. No `ProseBlock` distinction — every note is a `NoteBubble` regardless of type, to keep one consistent visual rhythm.
3. **Composer** — sticky bottom, per `v21-design-system/project/ui_kits/v21-app/composer.jsx` stripped to a single promotion mode (`?` → question only; `C` and `S` keystrokes from the v21 prototype are not wired). Textarea; `Enter` sends, `Shift+Enter` newlines (see `adrs/0001-enter-key-sends.md`). Placeholder: `write — or press ? for a question`. Bottom toolbar text: `↵ send · ⇧↵ newline · ⌘K search`.

Two surfaces summoned on demand, hidden by default:

4. **Command palette** — `⌘K` / `Ctrl+K`. Per `v21-design-system/project/ui_kits/v21-app/command-palette.jsx`. Full-text search over notes via SQLite FTS5. Returns top 50 matches ranked by `bm25()`, with `snippet()`-highlighted excerpts. Arrow keys navigate, `Enter` jumps the feed to the selected note, `Esc` closes. The `cmdk` `Command` component is configured with `shouldFilter={false}` so it displays FTS5's ranking rather than re-filtering client-side.
5. **Backlinks pane** — 320 px right pane per `v21-design-system/project/ui_kits/v21-app/right-pane.jsx`, only the `backlinks` tab (no `edges` tab, no `ai` tab at v0.1). Opens automatically when the user focuses a note (clicks into a bubble, or follows a `[[wikilink]]` to its target). Shows the list of notes that reference the focused note, with snippets, sorted by recency. Closes via `×` or `Esc`. The `all edges / recency` filter buttons in the v21 prototype are dropped — sorting is recency-only at v0.1.

## Focus, edit, delete, soft-delete

**Focus.** Clicking a bubble *focuses* it. Only one bubble is focused at a time; clicking another bubble moves focus. The focused bubble shows the v21 "selected" state (background `var(--bg-3)` + 2-px accent rail on the left edge, per `v21-design-system/project/README.md` §Hover/press/focus/selected). The backlinks pane content swaps to the newly focused bubble's incoming references. The composer's edit state is **independent** of focus — focusing a different bubble does not cancel an open edit on another bubble.

**Edit.** Hover a note → action bar appears → click the `edit-2` (pencil) Lucide icon → the composer enters edit mode pre-filled with the note body. `Enter` overwrites (writes new markdown to disk, updates SQLite row). `Esc` cancels (composer reverts to empty paragraph mode; the note on disk is untouched). No edit-history surface at v0.1, but the `note_revisions` sidecar table (below) is populated on every save so v0.2 can surface history without a migration.

**Delete (soft).** Hover a note → click the `trash-2` Lucide icon directly in the action bar → click again within 2 seconds to confirm (Linear-style "click again to delete" — avoids needing a dropdown menu primitive at v0.1). Soft delete sets `deleted_at = now()` and writes `deleted_at: <ms>` into the note file's YAML frontmatter — **file is not moved; trash recovery is via the same grep affordances as live notes**. The note disappears from the feed and from FTS results; the note's outbound `links` rows are also dropped (so backlink panes don't dangle on deleted sources — see "soft delete and backlinks" below for the trade-off).

**Hover action bar at v0.1.** Three icons, no menu: `edit-2` (open in composer), `link-2` (copy block link to clipboard as `linsae://note/<uuid>`), `trash-2` (delete with 2-second confirm). Drops `reply`, `hash`, `circle-check`, `more-horizontal` from the v21 prototype.

## Note model

One send = one note = one block. Stable ID: UUIDv7 (time-orderable, sortable, RFC 9562). Library choice deferred to plan-writing (candidates: `uuidv7` npm package; verify maintenance status at plan time).

A note is a markdown text body. Multi-paragraph allowed via `Shift+Enter` in the composer. Backlinks point at the whole note — block-level sub-granularity is deferred. **Known migration cost for v0.2**: when block-level granularity ships (per design-proposition's "block as primitive" model), v0.1 multi-paragraph notes will either (a) split into one block per paragraph with new block IDs and v0.1 note-level backlinks preserved as note-level edges in the v0.2 block graph, or (b) remain monolithic notes containing one block. Decision deferred to v0.2; documenting the cost here so it's visible.

## Data model

SQLite schema, committed up-front so v0.2 surfaces don't need DDL migrations:

```sql
CREATE TABLE notes (
  id         TEXT    PRIMARY KEY,                 -- UUIDv7, also the on-disk filename stem
  slug       TEXT    NOT NULL,                    -- stable wikilink target; defaults to first heading/line
                                                   -- on first save, NEVER auto-rewritten on edit
  body       TEXT    NOT NULL,                    -- markdown source
  type       TEXT    NOT NULL DEFAULT 'claim',    -- 'claim' | 'question' | 'source'
                                                   -- (long-term Q/C/S model; v0.1 UI shows only `?` promotion)
  created_at INTEGER NOT NULL,                    -- unix milliseconds
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER,                             -- soft-delete tombstone

  -- Schema-only at v0.1, populated by v0.2+ surfaces:
  status         TEXT,    -- 'wtf'|'gap'|'seedling'|'working'|'confident'|'settled'|'parked'|NULL
  source_kind    TEXT,    -- 'pdf'|'youtube'|'web'|NULL
  source_locator TEXT     -- opaque per-source-kind JSON; reader keys off source_kind and parses
                          -- accordingly. PDF: {page, rects:[{x1,y1,x2,y2}], quote}.
                          -- YouTube: {video_id, time_seconds}. Web: {url, anchor?}.
                          -- No shape is pre-committed; v0.2 surfaces write their own.
);
CREATE UNIQUE INDEX idx_notes_slug_live ON notes(slug) WHERE deleted_at IS NULL;

CREATE TABLE note_aliases (                       -- additional wikilink targets that resolve to a note
  note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  alias   TEXT NOT NULL,                          -- normalized lowercase trimmed
  PRIMARY KEY (note_id, alias)
);
CREATE INDEX idx_note_aliases_alias ON note_aliases(alias);

CREATE TABLE links (                              -- one row per [[wikilink]] occurrence
  from_note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  to_slug      TEXT NOT NULL,                     -- normalized lowercase trimmed
  edge_type    TEXT NOT NULL DEFAULT 'reference', -- 'reference' at v0.1;
                                                   -- future: 'supports'|'contradicts'|...
  PRIMARY KEY (from_note_id, to_slug, edge_type)
);
CREATE INDEX idx_links_to_slug ON links(to_slug);

CREATE TABLE note_revisions (                     -- one row per save (incl. the first), pre-committed
  id         TEXT    PRIMARY KEY,                 -- UUIDv7
  note_id    TEXT    NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  body       TEXT    NOT NULL,                    -- the body at this revision
  type       TEXT    NOT NULL,
  saved_at   INTEGER NOT NULL,
  supersedes TEXT    REFERENCES note_revisions(id)  -- previous revision of this note
);
CREATE INDEX idx_note_revisions_note ON note_revisions(note_id, saved_at);
-- v0.1 writes this on every save; v0.1 UI does NOT surface revisions; v0.2 reads them.

CREATE TABLE topic_paths (                        -- v0.2+ hierarchical topics; empty at v0.1
  note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  path    TEXT NOT NULL,                          -- e.g. 'math/algebraic-topology/spectral-sequences'
  PRIMARY KEY (note_id, path)
);

CREATE TABLE note_actions (                       -- v0.2+ action items per note; empty at v0.1
  id         TEXT    PRIMARY KEY,
  note_id    TEXT    NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  type       TEXT    NOT NULL,                    -- 'ask'|'reread'|'derive'|... extensible
  label      TEXT,                                -- freeform optional description
  status     TEXT    NOT NULL DEFAULT 'open',     -- 'open'|'done'|'parked'
  created_at INTEGER NOT NULL,
  done_at    INTEGER
);
CREATE INDEX idx_note_actions_status ON note_actions(status, note_id);

CREATE VIRTUAL TABLE notes_fts USING fts5(
  body, content='notes', content_rowid='rowid'    -- FTS5 uses SQLite implicit INTEGER rowid,
                                                   -- not notes.id (TEXT). Search results join via
                                                   -- notes.rowid = notes_fts.rowid.
);

CREATE TRIGGER notes_ai AFTER INSERT ON notes BEGIN
  INSERT INTO notes_fts(rowid, body) VALUES (new.rowid, new.body);
END;
CREATE TRIGGER notes_ad AFTER DELETE ON notes BEGIN
  INSERT INTO notes_fts(notes_fts, rowid, body) VALUES('delete', old.rowid, old.body);
END;
CREATE TRIGGER notes_au AFTER UPDATE ON notes BEGIN
  INSERT INTO notes_fts(notes_fts, rowid, body) VALUES('delete', old.rowid, old.body);
  INSERT INTO notes_fts(rowid, body) VALUES (new.rowid, new.body);
END;
```

`PRAGMA journal_mode = WAL` and `PRAGMA foreign_keys = ON` at startup.

**v0.1 UI** only reads and writes `body`, `type`, `created_at`, `updated_at`, `deleted_at`, `slug`, plus the `links`, `note_aliases`, and `note_revisions` rows. All other columns/tables are zero-row placeholders that v0.2+ surfaces fill.

**Why `type` defaults to `'claim'` and not `'note'`:** the long-term Question/Claim/Source model (per `docs/research/2026-05-25-design-propsition.md` §1.2) has no `note` type; an untyped plain note is conceptually a `Claim` with `epistemic_mode='observed'`. v0.1's UI labels both as "just a bubble" — the DB term is invisible to the user. Defaulting to `'claim'` now avoids a v0.2 `UPDATE notes SET type='claim' WHERE type='note'` migration when the three types become user-visible.

## Storage architecture

**Markdown files on disk are the source of truth.** SQLite is a derived index. Files live under `app.getPath('userData')/notes/<uuid>.md`. YAML frontmatter holds the metadata (`type`, `slug`, `aliases`, `created_at`, `updated_at`, `deleted_at`). Body is markdown.

### Write atomicity (per save)

The phrase "transactional in one IPC handler" was wrong in spec rev 1 — filesystem writes are not enrolled in SQLite transactions. The correct contract:

1. Compute new YAML frontmatter + body, serialize to a string.
2. Write the string to `notes/<uuid>.md.tmp` and `fsyncSync` the file descriptor.
3. `renameSync(notes/<uuid>.md.tmp, notes/<uuid>.md)` — atomic on POSIX, near-atomic on NTFS.
4. Only after the rename returns, open a SQLite transaction:
   - `INSERT OR REPLACE` into `notes` for the metadata.
   - Delete old `links` rows for this note; insert fresh ones from the re-parsed body.
   - Insert a row into `note_revisions` with the new body + a `supersedes` pointer to the prior most-recent revision (if any).
   - Insert/update `note_aliases` if frontmatter `aliases:` changed.
   - Commit.
5. If step 4 throws, the file is the truth; the next startup reconciliation will re-derive the SQLite row from disk.

### Reconciler algorithm (at startup, before window opens)

The reconciler is the recovery mechanism for any crash between step 3 and step 4. It runs once at startup:

1. List all `*.md` files under `notes/` into a Set keyed by UUID-from-filename.
2. Open one SQLite transaction.
3. For each file in the Set:
   - `stat()` first (cheap mtime+size check). If mtime+size match the SQLite row, skip.
   - Otherwise, read+parse YAML frontmatter and body. If frontmatter is malformed → log to `userData/logs/reconcile.log` with the file path, **skip the file**, increment a "skipped" counter. Never delete on parse error.
   - Hash the body (sha256). If different from the SQLite row's `body_hash`, upsert `notes`, regenerate `links`, append to `note_revisions`.
4. For each `notes` row whose `id` is **not** in the Set: set `deleted_at = now()`.
5. Commit.
6. If `skipped > 0`, surface a top-of-feed banner: `<n> notes had unreadable frontmatter and were skipped. View log.` Banner links to `reconcile.log`.

Wrapping in one SQLite transaction guarantees that a crash either rolls back fully or commits fully — no half-state.

### External-edit contract (v0.1)

If the user edits a note in vim/Obsidian/any other editor between app sessions, the reconciler picks up the change on next launch. **If the user edits a note externally while the app is running, the next in-app save may silently overwrite the external edit.** This is the v0.1 contract; the spec is honest about it. v0.2 adds a `chokidar` FS watcher to remove the limitation.

### Single-instance lock

The Electron main process calls `app.requestSingleInstanceLock()` on `app.whenReady`. If the lock is already held, the second-launched instance focuses the existing window via the `second-instance` event and exits. Multi-window is not in v0.1.

### Performance posture

v0.1 reconciler uses `stat()` as a first-pass cheap check and only hashes when mtime/size changed. Acceptable for v0.1 scale (target: ≤ a few thousand notes); a benchmark on the user's actual hardware at 10k synthetic notes is on the plan's task list, not asserted here. Soft target: startup-to-window ≤ 500 ms at 1k notes on the user's machine. If exceeded, revisit (FS watcher in-process or background-worker reconciler).

### Case-sensitivity

All `slug`s, `aliases`, and `links.to_slug` values are stored **lowercased + trimmed**. Lookups are equality on the normalized form. Display in the rendered markdown uses the user's original `[[...]]` text. This sidesteps macOS HFS+ vs Linux ext4 case differences for the wikilink resolver.

## Wikilinks

Syntax: `[[target]]` and `[[target|display text]]` and `[[target#section]]`.

At v0.1:
- `[[target]]` — fully supported.
- `[[target|display text]]` — supported; the visible link text is `display text`, the resolution target is `target` (lowercased, trimmed).
- `[[target#section]]` — `#section` is **parsed but ignored** at v0.1; resolution is on `target` only. The `#section` portion is preserved verbatim in the link href for v0.2 to enrich with block-anchor navigation.

### Resolution rule

A `[[target]]` resolves by:
1. Lowercase + trim `target`.
2. Match the unique non-deleted note whose `slug` equals normalized `target`. If found, return it.
3. Else match notes whose `id` appears in `note_aliases` where `alias` equals normalized `target`. If exactly one, return it; if more than one, see step 5.
4. Else render as a "dangling" link (orange — `--type-question` color); on click, open the composer pre-filled with a new note whose first line is `target`. On save, that new note's `slug` is `target`, resolving all existing dangling links to it.
5. **Multiple matches** (rare, only via aliases): the most recent non-deleted match (by `created_at DESC`) is chosen; a small one-line hint renders next to the link on hover: `<n> matches — newest shown`. A picker UX is deferred to v0.2.

### Stable slug from frontmatter

On first save of a note, the slug is computed from the first markdown heading (`# X`) or the first non-empty line, lowercased + trimmed, and written into the YAML frontmatter as `slug: <value>`. **The slug is never auto-rewritten on subsequent edits.** This is the key fix vs spec rev 1: editing the first line of a note does not silently break inbound links. If the user wants to rename a note, they update the frontmatter slug manually (or add an `aliases:` entry); a v0.2 "rename and update backlinks" affordance is deferred.

### Backlinks query

```sql
SELECT n.* FROM links l
JOIN notes n ON n.id = l.from_note_id
WHERE l.to_slug = ?
  AND n.deleted_at IS NULL
ORDER BY n.created_at DESC;
```

### Soft delete and backlinks

When a note is soft-deleted, its **outbound** `links` rows are dropped (so other notes' backlinks panes never show "(deleted) Note X linked here"). The note's **inbound** links remain in other notes' bodies as dangling links — they re-resolve if a new live note's slug or alias matches. This is the chosen trade-off: backlinks panes stay clean; the deleted note's existence is not advertised. Alternative ("show deleted sources as (deleted) pills") is deferred to v0.2 if the user asks.

## Markdown rendering

`react-markdown` v9.x with `remark-gfm` + `remark-math` + `rehype-katex` + a custom `remark-wikilinks` plugin (~80 LOC).

**KaTeX CSS import**: `import 'katex/dist/katex.min.css'` is added to `src/renderer/main.tsx`. Do **not** copy `katex.min.css` into `src/renderer/styles/` — Vite must resolve the relative font URLs from `node_modules/katex/dist/`. Same applies to the bundled KaTeX woff2 fonts.

Inline math: `$...$`. Display math: `$$...$$`. KaTeX-only (no MathJax). Pre-renders to HTML on first paint, no flicker.

Code blocks: GFM fenced, monospace (Geist Mono) in a `--bg-1`-tinted block per `v21-design-system/project/ui_kits/v21-app/feed.jsx`. No syntax highlighting at v0.1 — deferred to v0.2.

Images, attachments, image paste: deferred to v0.2.

### Rendering performance and memoization

The feed is virtualized; only mounted bubbles render. Each bubble's rendered React tree is memoized keyed by `(note.id, note.updated_at)` so re-mount on scroll re-uses the prior render. KaTeX rendering happens once per (note, revision) on first mount. Without this memoization, scrolling through 50 notes with display math each frame would exceed the 16 ms / 60 fps budget.

## Keystrokes (v0.1)

- `?` while the composer is empty and focused → promote next note to `question`.
- `Enter` → send (composer) or jump to result (palette).
- `Shift+Enter` → newline in composer.
- `⌘K` / `Ctrl+K` → open command palette.
- `↑` / `↓` → navigate palette results.
- `Esc` → see precedence below.
- No keyboard shortcut for edit at v0.1 (mouse only via pencil icon); a future `E` keystroke on the focused bubble is a candidate for v0.2.

### Esc precedence

`Esc` resolves the top-most modal state:

1. If the command palette is open → close it.
2. Else if the backlinks pane is open → close it.
3. Else if the composer is in edit mode → cancel edit, revert composer to empty paragraph mode.
4. Else if the composer is in question mode → drop back to paragraph mode (clear `?` promotion).
5. Else: no-op.

### Implementation note

The `?` keystroke uses the composer's local `onKeyDown` handler (matching `v21-design-system/project/ui_kits/v21-app/composer.jsx` line 34's approach), not `react-hotkeys-hook`. This avoids the `useKey` / shifted-key gotcha. `react-hotkeys-hook` is used only for global shortcuts (`⌘K`).

### Enter-key binding

`Enter` sends; `Shift+Enter` newlines. Rationale and reassessment gate in `adrs/0001-enter-key-sends.md`.

## Visual design

Tokens come from `v21-design-system/project/colors_and_type.css`. Import directly into the renderer (`src/renderer/styles/colors_and_type.css` is a copy of the v21 source; CI flags drift).

## Process model, IPC, and security

All database code and file I/O live in the **main process**. The renderer is sandboxed and talks to main via `ipcMain.handle` channels exposed through `contextBridge.exposeInMainWorld('api', {...})` in the preload script.

### Electron security baseline

`BrowserWindow` is created with `webPreferences: { contextIsolation: true, nodeIntegration: false, sandbox: true, preload: '<path>' }`. CSP is set in the renderer HTML's `<meta http-equiv="Content-Security-Policy">`: `default-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data:;` — note `'unsafe-inline'` for styles is required by KaTeX's inline-style usage; no remote font/script/style sources because everything is bundled.

User markdown is rendered without `rehype-sanitize` at v0.1 because v0.1 is single-user and the markdown source is the user's own content. **Decision note:** if v0.2 adds web clipping or import-from-other-apps, `rehype-sanitize` becomes required with a KaTeX-safe schema; flagged in `memory/linsae_milestones.md` v0.2 prep notes.

### IPC channels at v0.1

Each handler has a Zod schema in `src/shared/zod-schemas.ts` validated on both ends:

- `notes:list({ limit, before })` — paginated feed
- `notes:create({ body, type })` — returns the created note
- `notes:update({ id, body, type })` — upsert
- `notes:delete({ id })` — soft-delete
- `notes:get({ id })` — for the edit modal
- `search:run({ query, limit })` — FTS5 results with snippets
- `links:backlinks({ noteId })` — list of notes linking to this one
- `system:revealNotesFolder()` — opens OS file manager at the notes dir via `shell.openPath`

TanStack Query wraps each `window.api.x.y()` call on the renderer side for caching and invalidation.

## Stack

Canonical list in `memory/linsae_stack.md`. v0.1-specific deltas vs that memory:

- **`react-virtuoso` — use vanilla `Virtuoso`, NOT `VirtuosoMessageList`.** The `MessageList` package is commercially licensed (per `@virtuoso.dev/message-list` docs); the stack-research doc flagged this caveat and spec rev 1 missed it. - **`lucide-react`** added to the stack (replacing the v21 prototype's CDN approach).

## Tests

### Architecture

- **Per-test isolation.** Each test fixture creates a unique tmp dir via `fs.mkdtempSync('linsae-test-')`; the main-process code under test reads its notes-dir path from a constructor arg or env var (no globals), so the test fixture can inject. SQLite uses `:memory:` for unit tests; the file↔DB integration test uses a real on-disk SQLite file inside the tmp dir.
- **`electron-rebuild` policy.** `better-sqlite3` is rebuilt against Electron's Node ABI for `pnpm run dev` and against system Node ABI for `pnpm run test`. Two scripts handle the dance: `pnpm run rebuild:electron` and `pnpm run rebuild:node`. CI runs `rebuild:node` before tests. The plan documents the switch.

### Test surfaces

- **Unit (Vitest, jsdom).** Every IPC handler, the markdown→links extractor, the YAML-frontmatter parser, the slug normalizer, the FTS query wrapper, the wikilink resolver (including alias matches and most-recent-wins tie-break), the Esc-precedence resolver. Colocated `*.test.ts`.
- **Component (Vitest + React Testing Library).** `NoteBubble` (claim variant, question variant, focused variant), `Composer` (default, question mode, edit mode, Esc precedence), `CommandPalette` (empty, results, no-results), `BacklinksPane` (empty, populated). Render correctness and interaction; no visual assertions at this level.
- **Integration (Vitest, real disk).** One end-to-end "file↔DB round-trip" test: create a note → assert file on disk + SQLite row + `note_revisions` row + `links` rows; edit → re-assert; soft-delete → re-assert; restart simulation (re-instantiate the reconciler) → assert convergence. One "reconciler crash recovery" test: corrupt the SQLite file mid-reconcile (kill the transaction) → re-run → assert no data loss. One "external edit between sessions" test: simulate a file edit while the app is closed → restart → assert reconciler picks it up.
- **Visual regression — deferred to v0.2** (Playwright `toHaveScreenshot()` against a fixed-viewport Electron window with seed data). The user specifically called out the "AI writes black-on-black" failure mode; Playwright screenshot diff is the most reliable catch.

Coverage targets: meaningful, not line-percentage-driven. IPC handlers and parsers ≥ 80 % branches; component tests focus on user paths.

## Precommit (lefthook)

Order matters. From `lefthook.yml`:

1. `biome check --apply` (format + lint, in-place).
2. `tsc --noEmit` (typecheck).
3. `vitest run` (full unit + component + integration test pass).
4. `knip` (fail on unused exports / files).

Any step fails → commit blocked. No `--no-verify` escape hatch.

## What "done" means for v0.1

- `pnpm run dev` opens the app window. Composer focused. Empty-state copy visible.
- User can type a note, hit Enter, see it appear at the bottom of the feed.
- User can press `?` on an empty composer, type a question, hit Enter, see the amber question bubble appear.
- User can hover a note, click the `edit-2` icon, edit the body in the composer, save (Enter).
- User can hover a note, click `trash-2` twice, soft-delete it; it disappears from the feed.
- User can click a bubble to focus it; the bubble shows the selected state and the backlinks pane opens.
- User can write `[[other note]]` and click the wikilink to navigate; the target bubble becomes focused and the backlinks pane swaps to show its incoming references.
- User can press `⌘K`, type a query, see ranked snippets, hit Enter to jump.
- User can open the `≡` menu and click `Reveal notes folder`; OS file manager opens at the notes directory.
- App restart preserves all state. Notes are also legible as plain markdown files in `app.getPath('userData')/notes/`. Reconciler runs at startup; if any frontmatter is malformed, the skip-banner surfaces.
- Crash mid-save (kill the process between file write and DB upsert) leaves the file as truth; next startup reconciles cleanly with no data loss.
- Second-launch of the app focuses the existing window rather than opening a new one.
- `pnpm run lint && pnpm run typecheck && pnpm run test && pnpm run knip` all pass.
- Lefthook precommit blocks a deliberately-broken commit.
