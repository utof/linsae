**Goal:** Build the Playwright-Electron perf-gate harness the spec (§3, §17) has deferred since
v0.4 planning began. It launches the PRODUCTION build, seeds a 500-note board through the app's own
`createNoteAt` IPC (after launch — NOT direct SQLite, see below), reloads so the canvas re-reads the
committed rows, asserts the board is non-empty, drives a deterministic camera choreography through a
control bridge, records per-rAF frame intervals, computes frame stats with the spike's exact
`stats()`, and judges them against the §3 gates over a pinned 3-run protocol. After this plan the
milestone is feature-complete and ready to merge; this is where the §4–§9 pointer-event interactions
wired in Plan 3 get their pixel-level verification (the smoke flow, if free — cut-line item).

**Architecture:** Three measured phases map to the two §3 card-tier gates + the dot-tier gate. The
harness CANNOT toggle the dev LOD or drive a deterministic camera through gestures alone, so Task 1
adds a tiny **env-guarded control bridge**: the preload exposes `isHarness` (true only when launched
with `LINSAE_HARNESS=1`); when set, CanvasStage attaches `window.__canvasHarness` with
`{ setCamera, getCamera, setDevLod }`. The runner drives a known camera PATH (spike-faithful — it
measures the RENDER cost of a fixed path, the same thing the spike gated, not gesture cost) and
toggles the dot tier.

The **seed runs via IPC inside the launched app, NOT direct SQLite** (this is the load-bearing
redesign — see B1/B4 in Verified facts). The harness Node process **must not import better-sqlite3 at
all** (matching `scripts/morph-harness.mjs` / `scripts/send-harness.mjs`, which seed through the
running app): (1) launch with an empty tmp `--user-data-dir` + `LINSAE_HARNESS=1`; (2) in one
`win.evaluate`, loop 500 awaited `window.api.canvas.createNoteAt({…, body, type, x, y})` calls with
deterministic positions; (3) `win.reload()` so the canvas's `staleTime:Infinity` layout query
re-reads the now-committed rows (a raw IPC call does not invalidate the renderer cache); (4) assert
`[data-note-id]` count ≈ 500 BEFORE measuring (the safety net that catches an empty board). Because
`createNoteAt` is **file-first** (it writes `<userDataDir>/notes/<id>.md` before the DB row), the
reload's disk-driven reconciler sees the 500 files on disk and leaves them — no tombstoning.

The runner (Task 2) is a standalone `.mjs` like `scripts/morph-harness.mjs` / `scripts/send-harness.mjs`,
NOT `@playwright/test` (not installed) and NOT under xvfb (the perf gate mandates a real GPU/display —
the spike's hard rule).

**Tech Stack:** No new deps. `playwright@^1.60.0` is already a devDependency (package.json:71) — the
`_electron` API (`electron.launch({ args, env })`, `app.firstWindow()`, `app.evaluate`,
`win.evaluate`, `win.reload`, `win.locator`, `win.mouse`, `win.keyboard`, `app.close()`) is verified
against the installed `playwright-core@1.60.0` type declarations (see Verified facts). The harness
imports NO better-sqlite3 (it seeds via IPC), so there is **no node-ABI rebuild** — the only prereq is
the electron-ABI build (`pnpm rebuild:electron && pnpm exec electron-vite build`). `uuidv7` is NOT
imported by the harness (the app mints ids inside `createNoteAt`). No `playwright.config.*` is created
(the established pattern is a standalone runner).

- **Prod app DB/notes resolution (overridable):** `src/main/index.ts:159-163` —
  `userData=app.getPath('userData'); notesDir=join(userData,'notes'); dbPath=join(userData,'linsae.db')`.
  `app.getPath('userData')` honours the `--user-data-dir=` CLI flag, so launching with an empty tmp
  userData dir gives the app a clean throwaway DB + notes dir to seed into.
- **B1 — the reconciler is DISK-DRIVEN; a direct-SQLite seed would be TOMBSTONED.** `reconcile()`
  (`src/main/db/reconcile.ts:76-184`, run unconditionally at boot — `src/main/index.ts:174`) lists
  `*.md` files on disk (`nd.listNoteIds()`, `:77`) and then, in its final loop (`:178-183`),
  soft-deletes (`UPDATE notes SET deleted_at = now`) EVERY DB note whose id is not on disk — **no
  `source_kind` branch, unconditional**. So a note inserted straight into SQLite with no `.md` file is
  wiped at the next boot; `listLayouts` joins `deleted_at IS NULL` and returns 0 → empty board → the
  gate measures nothing. (The earlier draft's "reconcile only processes `source_kind='file'`" was
  FALSE — corrected here.)
- **B4 — better-sqlite3 ABI collision** (see Prereq above): a Node-process direct-SQLite seed shares
  ONE `node_modules/better-sqlite3` binding with the launched Electron app. Resolved by NOT importing
  better-sqlite3 in the harness at all (the morph/send harnesses do the same — they seed via the
  running app, never load the native module in the Node process).
- **RESOLUTION (fixes B1 + B4 together): seed via the app's `createNoteAt` IPC AFTER launch.** The
  Plan-3 channel `window.api.canvas.createNoteAt(i)` is on the preload `api`
  (`src/preload/index.ts:106-107`) and the renderer facade (`src/renderer/src/lib/api.ts:199-201`);
  input `{ canvasId, arrangementId, body, type, x, y }`. It is **file-first** (writes
  `<userDataDir>/notes/<id>.md` then the DB row + placed layout, ONE transaction, ONE timestamp — spec
  §7). So the seeded notes are never tombstoned: boot reconcile runs ONCE at launch on the EMPTY DB
  (before the seed exists), `win.reload()` reloads only the renderer (it does NOT re-run main-process
  reconcile), and the 500 `.md` files createNoteAt writes keep the notes reconcile-safe even across a
  full app relaunch → B1 solved. The seed loops 500 awaited `createNoteAt` calls inside ONE `win.evaluate`, with
  deterministic positions (mulberry32) over a ~5000×3300 world (so a wide pan crosses mount
  boundaries). ~500 sequential awaited file-first+fsync+txn IPC calls take ~2.5–5s — fine for one-time
  setup. **Its correctness rides on `createNoteAt`'s existing Plan-3 test
  (`src/main/db/queries/createNoteAt.test.ts`) + the runtime board-non-empty guard below — no new test
  file** (dissolves the earlier draft's seed-unit-test, which would have needed a node-ABI
  better-sqlite3 outside the vitest globs).
- **Reload REQUIRED after seeding:** a raw `window.api.canvas.createNoteAt` call does NOT invalidate
  the renderer's react-query cache, and the `['canvas-layouts', 'root']` query runs under a **global
  `staleTime: Infinity`** so it never auto-refetches (confirmed `CanvasStage.tsx:572` comment + the
  App-side query `App.tsx:426`). So the runner `await win.reload()` + `waitForLoadState`: a reload
  gives the page a fresh QueryClient that fetches `listLayouts` from scratch — the remounted canvas
  then reads all 500 committed rows. (`win.reload()` reloads ONLY the renderer; it does NOT re-run the
  main-process boot reconcile, which already ran once at launch on the empty DB before seeding — so the
  seeded notes are never tombstoned.)

 * dev-only LOD store, so — and ONLY when launched with LINSAE_HARNESS=1 (the
 * preload then sets `window.api.isHarness`) — CanvasStage attaches this bridge
 * to `window.__canvasHarness`. The runner uses `setCamera` to drive a known
 * camera path (measuring RENDER cost of a fixed path, spike-faithful — the same
 * thing scripts/spike-canvas gated) and `setDevLod` to force the dot tier.
 *
 * Inert in normal prod use: `installHarnessBridge` is never called unless
 * `window.api.isHarness` is true, so the global stays undefined.
 * @see docs/specs/v0.4-canvas-mvp.md §3 §17
 * @see scripts/canvas-perf-harness.mjs
 */
import type { Camera } from './camera'
import type { CanvasDevLod } from './dev-lod'

/** The methods the perf harness drives the canvas through. */
export interface CanvasHarnessBridge {
  /** Set the camera to an exact {x,y,zoom} (the runner's choreography step). */
  setCamera: (camera: Camera) => void
  /** Read the live camera (so the runner can anchor a steady oscillation). */
  getCamera: () => Camera
  /** Toggle dev-LOD (force dot tier + synthetic 10k dots + unclamp zoom). */
  setDevLod: (patch: Partial<CanvasDevLod>) => void
}

declare global {
  interface Window {
    /** Present ONLY under LINSAE_HARNESS=1; see CanvasHarnessBridge. */
    __canvasHarness?: CanvasHarnessBridge
  }
}

/** Attach the bridge so the harness can find it. Idempotent (last wins). */
export function installHarnessBridge(bridge: CanvasHarnessBridge): void {
  window.__canvasHarness = bridge
}

/** Detach the bridge (CanvasStage unmount / test cleanup). */
export function uninstallHarnessBridge(): void {
  window.__canvasHarness = undefined
}

// Playwright-Electron perf-gate harness for the v0.4 canvas (spec §3 + §17).
// Adapted from scripts/spike-canvas/run.mjs — same GPU guard + vsync probe +
// stats(), but it drives the REAL app's camera through window.__canvasHarness
// (Task 1 bridge) instead of the spike's vanilla window.Spike.
//
// SEEDING (B1/B4): this harness imports NO better-sqlite3. It launches with an
// empty tmp --user-data-dir + LINSAE_HARNESS=1, then seeds 500 notes by calling
// the app's OWN window.api.canvas.createNoteAt IPC inside the page. createNoteAt
// is file-first (writes <userDataDir>/notes/<id>.md then the DB row, ONE txn —
// spec §7). Boot reconcile (src/main/db/reconcile.ts soft-deletes any DB note NOT
// on disk) ran once at launch on the EMPTY DB before seeding, and win.reload()
// reloads only the renderer (no reconcile re-run), so the seeded notes are never
// tombstoned; the .md files keep them safe across a full relaunch too. A
// direct-SQLite seed would be tombstoned (B1) AND would ABI-collide with the
// launched Electron app over the one better-sqlite3 binding (B4). A reload is
// REQUIRED after seeding because a raw IPC call does not invalidate the renderer
// react-query cache; the remounted canvas re-reads the 500 committed rows.

//   churn  — wide pan across the board so cards mount/unmount entering the
//            viewport: gate p95 ≤ 33.4ms, mean ≥ 55fps, zero frames > 100ms.
//   steady — small oscillation inside an already-mounted region (no new mounts):
//            gate p95 ≤ 18ms.

// ---- stats(): VERBATIM from scripts/spike-canvas/page/harness.js:40-56.
// Stringified + injected into the page (win.evaluate) so the rAF timestamps are
// reduced renderer-side, exactly as the spike does it.
const STATS_FN = `
function stats(ts) {
  const ints = []
  for (let i = 1; i < ts.length; i++) ints.push(ts[i] - ts[i - 1])
  const sorted = [...ints].sort((a, b) => a - b)
  const q = (p) => sorted[Math.min(sorted.length - 1, Math.floor(p * sorted.length))]
  const total = ts[ts.length - 1] - ts[0]
  return {
    frames: ints.length,
    meanFps: +((ints.length / total) * 1000).toFixed(1),
    p50: +q(0.5).toFixed(1),
    p95: +q(0.95).toFixed(1),
    p99: +q(0.99).toFixed(1),
    max: +sorted[sorted.length - 1].toFixed(1),
    over17: ints.filter((d) => d > 17).length,
    over100: ints.filter((d) => d > 100).length,
  }
}`

// ---- seed the board via the app's createNoteAt IPC, inside the page. mulberry32
// (spike-faithful) scatters the cards deterministically over the world so a wide
// pan crosses mount boundaries. Sequential awaited calls (file-first + fsync +
// txn) — ~2.5–5s for 500, fine for one-time setup. Returns the count placed.
async function seedViaIpc(win) {
  return win.evaluate(
    async ([count, seed, world, cardW, cardH]) => {
      // mulberry32 (spike-faithful PRNG) so a fixed seed → an identical board.
      let a = seed >>> 0
      const rand = () => {
        a = (a + 0x6d2b79f5) | 0
        let t = Math.imul(a ^ (a >>> 15), 1 | a)
        t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t
        return ((t ^ (t >>> 14)) >>> 0) / 4294967296
      }
      let placed = 0
      for (let i = 0; i < count; i++) {
        const body =
          `# Seed note ${i}\n\nProse with **emphasis** and a [[wikilink]], long enough ` +
          `to wrap a few lines like a real note body. Inline math $e^{i\\pi}+1=0$.`
        await window.api.canvas.createNoteAt({
          canvasId: 'root',
          arrangementId: 'manual',
          body,
          type: 'claim',
          x: 100 + rand() * (world.w - cardW - 200),
          y: 100 + rand() * (world.h - cardH - 200),
        })
        placed++
      }
      return placed
    },
    [COUNT, SEED, WORLD, CARD_W, CARD_H],
  )
}

// ---- one phase: drive the bridge camera along a cosine path for durationMs,
// recording a rAF timestamp each frame, then reduce with stats(). `mode` picks
// the path: 'churn' = wide pan, 'steady'/'dot' = tiny oscillation about current
// cam (the runner forces the dot tier before the 'dot' phase). setCamera is the
// UNCLAMPED Dispatch (clamping lives only in the gesture helpers, which the bridge
// never touches), so {x,y,zoom} are written verbatim. Runs entirely in the page so
// the rAF clock and the setCamera writes share a frame (the spike's runChoreo).
async function runPhase(win, mode, durationMs) {
  return win.evaluate(
    async ([m, dur, statsSrc, world]) => {
      // biome-ignore lint: injected stats() (spike-verbatim)
      const stats = new Function(`${statsSrc}; return stats`)()
      const h = window.__canvasHarness
      if (!h) throw new Error('window.__canvasHarness missing — isHarness not set?')
      const base = h.getCamera()
      // churn pans clear across the world at zoom 1 (crosses mount boundaries);
      // steady/dot oscillate ±60 world px about the current camera (no new mounts).
      const start = { x: 200, y: world.h / 2, zoom: 1 }
      const end = { x: world.w - 200, y: world.h / 2, zoom: 1 }
      const ts = []
      await new Promise((resolve) => {
        let t0
        const tick = (now) => {
          if (t0 === undefined) t0 = now
          const t = (now - t0) / dur
          if (t >= 1) {
            resolve()
            return
          }
          if (m === 'churn') {
            const u = 0.5 - 0.5 * Math.cos(t * Math.PI * 2) // there-and-back
            h.setCamera({
              x: start.x + (end.x - start.x) * u,
              y: start.y,
              zoom: 1,
            })
          } else {
            const u = 0.5 - 0.5 * Math.cos(t * Math.PI * 4)
            h.setCamera({ x: base.x + 60 * u, y: base.y + 40 * u, zoom: base.zoom })
          }
          ts.push(now)
          requestAnimationFrame(tick)
        }
        requestAnimationFrame(tick)
      })
      return stats(ts)
    },
    [mode, durationMs, STATS_FN, WORLD],
  )
}

function medianByMeanFps(runs) {
  const sorted = [...runs].sort((a, b) => a.meanFps - b.meanFps)
  return sorted[Math.floor(sorted.length / 2)]
}
