## 4. ⚠️ DO THIS FIRST — ADR 0063 contains three errors

`adrs/0063-composer-clears-on-success.md` was reviewed and returned **CHANGES REQUESTED**. The fix was
never dispatched. An ADR is durable; leaving this is worse than leaving code unfinished.

**4a. The React Compiler "Consequences" bullet is FALSE AND INVERTED — highest priority.**

It claims two independent compiler bails (`try/finally` *and* refs), that removing `finally` recovers
nothing, and instructs the reader **not** to clean up the `try`/`finally` expecting memoization back.
All of that is backwards, and it would be cited to block a change that works.

Verified truth (I checked the decisive facts directly):
- `@rolldown/plugin-babel` is `enforce: "pre"` (`dist/index.mjs:336`) and injects
  `parserOpts.plugins: ["typescript","jsx"]` for `.tsx` (`:389`) — it injects them *because* it
  receives **raw TSX**. `vite:oxc` declares no `enforce`, so babel runs **first**.
- Therefore **raw TSX is the faithful measurement**; measuring against `jsx: react-jsx` produces a
  spurious `Refs: Cannot access refs during render`. That false reading is what got written down.
- There is **ONE** bail: `Todo: (BuildHIR::lowerStatement) Handle TryStatement with a finalizer`.
  Removing `finally` **does** recover `CompileSuccess`. An in-flight `useRef` read in an async handler
  compiles fine.
- The `finally` is kept **deliberately** — it is the correct place to release the in-flight guard, and
  duplicating the reset onto both exit paths is exactly #198's gap 2. A deliberate trade, not an
  inherent limit. A future compiler release that lowers `TryStatement` would restore memoization alone.

Fix the four sentences (table rows 3 & 4, the "two independent bails" paragraph, the "no way to stay
compiled" sentence) and add one line recording that **the measurement depends on the input form** —
that sensitivity is what produced the wrong table. **Issue #197 is already corrected; do not re-comment.**

**4b. `manuallyFrozen` has no stated reason**, inside a section titled *"why each deferral is
load-bearing"*. The ADR says "Two of them carry the anchor" and `ThreadComposer.tsx:241` repeats it.
But a pre-existing test pins it: `ThreadComposer.test.tsx:651` *"a rejected post keeps the MANUAL chip
time (manuallyFrozen survives)"*. Hoisting `setManuallyFrozen(false)` above the await is invisible
while `hasDraft` is true, but the moment the user deletes the failed text the freeze effect stops
early-returning and `frozenAt := livePlayhead` — the hand-picked anchor is gone. Say "Two of them carry
the **posted** anchor" and give `manuallyFrozen` its sentence.

**4c. A new factual error introduced by the consolidation.** `ThreadView.tsx:583-584` says the
invalidations plus the error reset are *"three statements"*. It is **five** (`setPostError(null)` at
`:602` + four `invalidateQueries` at `:603-606`).

Non-blocking: claim 6 "without an answer" → "without a mechanism"; claim 8 caveat (editing the body
keeps `t`, but *emptying* and retyping moves it); `^1.0.0` is not a pin; `tests/flush.ts` says "three
inline copies remain" while naming one.

## 5. Remaining work, in order

**B2+B3 — mount `TransportBar` in `PlayerPane`, `ThreadView` reads the store.** Plan §3.3.
Both A-cluster files and B touch `ThreadView.tsx`; A is done, so B is now unblocked.

- `usePlayerState(videoId)` — **takes a `videoId` argument**, which the plan's §3.1 quote omits. Returns
  `{ player, currentTime, state, duration }` and never calls `mount`/`unmount`/`load`, so ADR 0016's
  single-mount invariant is safe. No second `usePlayer`.
- Mount in `PlayerPaneInner` (has `videoId` in scope), **not** the outer `PlayerPane`, which must keep
  early-returning a black div when `videoId` is null.

  100%/100%. Adding a bar needs a flex column with the host at `flex: 1`. Shrinking is safe (the fixed
  webview tracks the host's rect per-frame), but **never** `display:none`/`visibility:hidden` on the
  host (destroys the guest WebContents, electron#7700) and never re-parent it (electron#9529).

**B1's decisions that B2/B3 must honour** (from `yt/transportState.ts`):
- `RATES` is **module-local, unexported**. Do **not** re-declare it — call `cycleRate()`, which advances

- `followOn`/`rate` are **player-scoped, never reset** — they must survive `ThreadView` unmounting while
  the docked player plays (the point of B5).

## 9. The lesson worth carrying forward

**Three times, the plan's *fix* was right and its *wiring* was inert.** `post.mutate` returning `void`
so `await` resolved unconditionally; a functional updater that couldn't gate `onDraftClear`; a `finally`
no test defended. All three would have passed a reading-based review. All three were caught by
*executing* something — a mutation, a compiler run, a probe.

And once, three agents agreed on a false claim (the compiler measurement) because one misconfigured
probe *looked like* a self-caught error. The review that killed it did so by running the real pipeline.

**Verify by execution. A green test proves nothing until you've seen it go red.**
