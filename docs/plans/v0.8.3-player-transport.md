## Ordering rationale

The dependency that shapes everything: **T2's `whenAck` must exist before T3 can publish on it, and
T1's `fakeGuest` must exist before any host test can assert anything.** So the test harness lands
first, against unchanged behaviour — which also means Task 1 is the only task whose tests are
*expected* to describe HEAD rather than the target.

Tasks 3–5 are one logical change (the handshake) split at the smallest points where the suite can be
green. Do not reorder them; a half-applied handshake is worse than none.

## Task 2 — `whenAck` on the RPC, both wire formats

**Spec:** §6.5, §6.6. **Files:** `rpc.ts`, `rpc.test.ts`, `inject/youtube-guest.ts`.

1. `Wire` (`rpc.ts:6-10`) gains `{ t: 'ack'; token: string }`.
2. `Rpc` (`:12-20`) gains `whenAck(token: string): Promise<boolean>` — resolves `true` iff an `ack`
   echoing exactly that token arrives. Never rejects, never self-times-out (§5.5 step 4 owns the
   timeout). Implement alongside the existing `readyPromise` machinery (`:35-42`); handle `t === 'ack'`
   in the `onmessage` chain (`:45-72`), which currently drops unknown `t` silently at `:69-71`.
3. Guest `buildRpc` (`youtube-guest.ts:24-70`) gains a matching `ack(token)` sender.
4. TDD: write the `rpc.test.ts` case first — ack with the right token resolves `true`; a *different*
   token leaves the promise pending (assert via `Promise.race` against a short timer).

**Done when:** both wire formats carry `ack` and the round trip is pinned in `rpc.test.ts`.
**Verify:** change the token comparison to `===` on the wrong variable → the mismatch test goes red.

**Trap:** the two wire formats are hand-duplicated by design (spec §D9) and drift is **silent**. Task
6's T9 is what pins them against each other; this task must not assume it.

## Task 3 — publish only after ack (C1, C4)

**Spec:** §5.1, §5.2, §5.5, §5.8. **Files:** `playerSingleton.ts`, its test.

The core of #213. Tests T1, T5, T6 (§8.2).

1. Add the §5.1 module state and the exported `handshakeConfig` test seam.
2. Add `teardown()` per §5.2 — including the `pendingRpc` re-check ordering note.
3. Rewrite `onDomReady` → `handshake()` per §5.5: entry check, per-attempt token `${NONCE}:${seq}`,
   build into `candidate`, transfer **inside a `try/catch`** (§5.5 step 3 — HEAD wraps this at
   `:191-195`; `handshake()` is called as `void handshake()` so a throw becomes an unhandled
   rejection), await `whenAck` **and use the result**, publish only at step 6.
4. Step 5 splits into two branches (§5.5): `seq !== handshakeSeq` ⇒ **abandon, no retry**;
   `!acked && seq === handshakeSeq` ⇒ retry with backoff.
5. `destroyPlayer()` calls `teardown()` (§5.8) — it must also clear `armWatchdog`/`coverTimer` once
   those exist in Task 4/5. Leave TODO-free: add the clears when the fields land, not before.
6. **Do not touch the cover in this task.** It stays exactly as HEAD until Task 5.

**Done when:** T1, T5, T6 green.
**Verify each:** T1 → restore `if (rpc) return` at the top of `handshake()`. T5 → drop the token
comparison in `whenAck`. T6 → assign `rpc = candidate` at step 2. Record all three.

**Trap — the one the review caught:** merging step 5's two conditions is actively harmful. A
superseded attempt that retries re-arms the guest with a new token, and Task 6's `initPort` destroys
the prior guest rpc — killing the guest end of a channel the host already published, leaving `rpc`
non-null with a dead peer. That is precisely what C1 exists to prevent.

## Task 4 — invalidate on navigation, with the paired watchdog (C2, C6)

**Spec:** §5.3. **Files:** `playerSingleton.ts`, its test. Tests T2, T3, T11.

1. `did-start-navigation` listener; on `isMainFrame && !isInPlace` → `teardown()` **and arm
   `armWatchdog`**.
2. `dom-ready` clears `armWatchdog` (§5.4).
3. On watchdog fire: re-enter `handshake()` against the current document, or emit the C6 diagnostic
   if there is no live document. **Never leave the null state unobserved.**
4. `load()` calls `teardown()` (§5.7), then raises the cover and reassigns `src` as today.

**Done when:** T2, T3, T11 green.
**Verify:** T2 → drop `resetCache()` from `teardown()` (seed the cache with `emitState({duration:213})`
first, or the test is vacuous — this is the §8.1 point). T3 → delete the `!isInPlace` term. T11 →
delete the watchdog; the assertion must time out with `rpc` null and no diagnostic.

**Record T3 as a paired test.** It passes against an empty implementation and on HEAD; it is evidence
only alongside T2.

**Why the watchdog is not optional** (§5.3): `did-start-navigation` fires unconditionally with no
commit check, while `DidFinishNavigation` early-returns on `!HasCommitted()`. Our own
`src/main/index.ts:296` `event.preventDefault()` cancels non-allowlisted guest navigations — an
ad click-through or a sign-in redirect starts a navigation that never commits, so no `dom-ready`
follows. Without the watchdog the player is silently dead where HEAD works.

## Task 5 — the cover, decoupled (N5, N6, C3)

**Spec:** §5.6. **Files:** `playerSingleton.ts`, its test. Test T10.

1. `dom-ready` arms `coverTimer` for `readyTimeoutMs`.
2. Cover drops on **whichever comes first**: the guest's `ready` event, or `coverTimer` firing —
   **regardless of handshake outcome**.
3. `refreshSpinner()` on every drop, as today.
4. `teardown()` and `destroyPlayer()` clear `coverTimer`.

**Done when:** T10 green — cover drops on `ready`, **and** drops after `readyTimeoutMs` when `ready`
never fires and the handshake *succeeded*.

**Verify:** make the drop conditional on handshake success → the timeout case stays covered → red.

**Trap — both directions are regressions, and rev 1 of the spec shipped one of them:**
- Dropping on `ack` reveals the guest seconds earlier than HEAD. That was tried at `47a05f7`,
  produced a "muted, plays 1s, then stops" flash, and was reverted (N5).
- Dropping only on `ready`-or-*failure* leaves the cover up **forever** on a consent wall: `ready`
  never fires there, and the handshake **succeeds** (ack works on a consent page, C3), so neither
  branch fires. The user gets a black screen over an unclickable wall. HEAD's `:197` 10s timeout is
  what makes the wall dismissable today (N6), and the webview is left interactive for exactly that
  reason (`:249-252`).

## Task 6 — idempotent guest, re-armable receiver (C5)

**Spec:** §6.1–§6.4. **Files:** `inject/youtube-guest.ts`, new
`src/renderer/src/yt/inject/youtube-guest.test.ts`. Test T9.

1. Sentinel-guard the IIFE: if `window.__linsaeGuest` exists → `arm(token)` and return.
2. Receiver (`:280-284`) keeps its listener for the document lifetime and re-arms the expected token
   instead of `removeEventListener`. Validate `e.ports.length === 1`.
3. `initPort` sends `ack(token)` as its **first act**, before any DOM work; `rpc.ready()` stays in
   `attachVideo()` (`:155`).
4. `initPort` destroys any prior `rpc` first.

**T9 — execute the real guest, do not assert on its source string.** `new Function(guestRuntime(t))()`
twice in happy-dom; spy `setInterval` / `addEventListener` / `MutationObserver`; assert the counts do
not double and `__linsaeGuest.arm` saw the second token. Then drive a real `createRpc` across a real
`MessageChannel` against it and assert the ack round-trips — which pins both hand-duplicated wire
formats together for the first time.

**Verify:** remove the sentinel → counts double. Change `{t:'ack'}` in *either* file → the round trip
fails.

**Why not a string assertion** (§8.2): `toContain('__linsaeGuest')` survives `if (false && …)`,
survives the sentinel being written but never read, and survives the identifier appearing only in a
comment. It cannot be falsified by any realistic implementation error.

**What duplicates without the guard** (§6.1): 11 media-event listeners (`:131-140`), a capture-phase
`keydown` stopper (`:208`), two `MutationObserver`s (`:174-183`, `:222-223`), **three** 200ms
`setInterval`s (`:241-244`, `:263-266`, `:273-275`), and a second `startRaf` rAF loop (`:96-110`).

## Task 8 — the deterministic real-Electron gate

**Spec:** §8.3, §8.4. **Files:** `scripts/thread-smoke.mjs`.

1. Under `SMOKE_FORCE_SWAP=1`: set `wv.src = 'https://www.youtube.com/'` **directly** (bypassing
   `load()`, so nothing clears `rpc`), wait for the guest runtime on that document, then set `wv.src`
   to the watch URL. The smoke already reaches the element at `:778-786`.
2. On HEAD this must **fail** — `rpc` latches to the homepage, the watch page's `dom-ready` is refused,
   the host never gets a duration, and the `walled` predicate at `:847` is false, so `transportDuration`
   fails rather than skips.
3. Replace the consent heuristic with the direct signal: the guest already emits `needs-interaction`
   (`youtube-guest.ts:216`) on every consent-lightbox transition and **nothing consumes it**. Wire it
   to a host-side flag the smoke can read. Keep the fail-vs-skip distinction exactly as is.

**Done when:** `SMOKE_FORCE_SWAP=1 pnpm smoke:thread` fails 3/3 on HEAD (stash the fix, or run against
the pre-Task-3 commit) and passes 3/3 after.

**If it does not fail on HEAD, stop and report it.** That would mean the wide-window diagnosis is
wrong and the narrow race is the real mechanism. **Do not adjust the repro until it reproduces** —
that converts a falsification into a confirmation, which is the exact failure this project has
written down twice.

**Do not attempt session interception** (§8.3): `webRequest` cannot serve a body, `data:`/`file:`
redirects are blocked for top-frame navigations, a custom scheme needs `registerSchemesAsPrivileged`
before `app.ready`, and `protocol.handle('https', …)` on a `persist:` partition is undocumented and
unverified.

## Task 9 — ADR 0065

**Spec:** §10. **Files:** `adrs/0065-guest-rpc-handshake-rearm.md`.

Skeleton per CLAUDE.md: Status · Context · Decision · Alternatives · Consequences · Sources.
`Status: accepted (v0.8.3)`.

Must record, because each is a decision a future agent would otherwise reverse:
- Why `dom-ready` alone is insufficient (fires per committed document; the first may be a consent page).
- Why `rpc` must not latch before acknowledgement, and why the ack echoes a per-attempt token.
- Why `ack` and `ready` are distinct, **and why the cover keys on `ready`-or-timeout and never on
  `ack`** — cite `47a05f7` and #65.
- Why `did-start-navigation` needs a paired watchdog — cite the uncommitted-navigation sources in
  §5.3 and our own `src/main/index.ts:296`.
- Why the preload path was rejected again (N2 — it would reverse ADR 0016 D7/D8).
- **Known residual:** a guest renderer crash replaces the document with no navigation at all — no
  `did-start-navigation`, no `dom-ready` — leaving `rpc` non-null and dead. Neither HEAD nor this
  design handles it; `render-process-gone` is the signal if ever wanted. In the ADR so it is not
  rediscovered as a new bug.

Check whether ADR 0016's D7 rationale now reads as contradicted by the re-injection design. It is
not, but a reader must not have to derive that — amend if the wording invites the misreading.
