## Ordering rationale

Two hard dependencies: **`whenAck` (Task 2) must exist before Task 4 can publish on it**, and **the
shared fake-guest harness (Task 1) must exist before any host test can assert anything**.

**The cover moves *before* the handshake rewrite (Task 3).** §5.6 is not a behaviour change — HEAD
already does `Promise.race([whenReady(), timeout(10000)])` then drops unconditionally (`:197-204`),
which *is* "ready-or-timeout". §5.6 only re-expresses it as a standalone timer so it stops being
coupled to the handshake. Doing it first means T10 is written and mutation-verified against HEAD, and
the handshake tasks never touch the cover at all. Rev 1 put it last, which left a window (Tasks 3→5)
where the cover hung off `handshake()`'s success path — on a consent wall the handshake *succeeds*
while `ready` never fires, so that window contained the exact N6 regression the spec forbids, **and
no test could see it** because T10 didn't exist yet.

## Task 1 — the shared fake-guest harness

**Spec:** §8.1. **Files:** new `tests/yt-fake-guest.ts`; `src/renderer/src/yt/playerSingleton.test.ts`.

**It must be a shared module, not test-local.** Tasks 5 and 7 both need it from *different* test
files, so follow the `tests/flush.ts` / `tests/pdf-layout.ts` precedent. Knip is fine with this: its
vitest plugin treats `src/renderer/**/*.test.{ts,tsx}` as entries, so test-only consumption counts as
usage — `Rpc.signalReady`, used only by `rpc.test.ts:50`, passes knip today and is the proof.

1. `fakeGuest(port, opts)` **built on the real `createRpc`** per the spec's §8.1 snippet — it must
   `handle('pause'|'seekTo'|'setRate')` with `vi.fn()`s and expose them. A guest that records but
   never replies leaves `invoke`'s 1000ms timer (`rpc.ts:79-82`) rejecting into `afterEach`; under
   `isolate: false` that unhandled rejection can fail a *different* file.
2. Extend `stubWebview` (`playerSingleton.test.ts:4-23`) with `contentWindow.postMessage` recording
   `{ msg, port: transfer[0] }`, **and with `getURL: vi.fn(() => 'https://www.youtube.com/watch?v=…')`**
   — C6's diagnostic calls it (spec §5.1) and without it T4/T11 throw instead of asserting.
3. `dispatchWebviewEvent(el, name, props)` using `Object.assign(new Event(name), props)`
   (`web-view-impl.ts:117-120`). Add the local
   `Event & { isMainFrame?: boolean; isInPlace?: boolean }` type — `WebviewElement` extends
   `HTMLElement` with untyped events and `tsc --strict` is a lefthook gate.
4. One characterisation test that passes on HEAD: `dom-ready` transfers exactly one port and injects
   once. **It must call `emitReady()`** — otherwise it sits through HEAD's 10s
   `Promise.race` at `:197`, leaving a dangling Node timer and a pending `onDomReady` to cross
   `afterEach → destroyPlayer()`. That shape is a flake generator in a shared-worker suite.

**Done when:** helpers exist, characterisation test green, suite green.
**Verify:** delete the `contentWindow` stub → the test errors rather than silently passing.

**Trap:** do not export `rpc` from `playerSingleton.ts`. The observable is
`expect(guest.pause).toHaveBeenCalled()` (spec §8.1) — module privacy is deliberate.

## Task 2 — `whenAck` on the RPC, both wire formats

**Spec:** §6.5, §6.6. **Files:** `rpc.ts`, `rpc.test.ts`, `inject/youtube-guest.ts`.

1. `Wire` (`rpc.ts:6-10`) gains `{ t: 'ack'; token: string }`.
2. `Rpc` (`:12-20`) gains `whenAck(token: string): Promise<boolean>` — resolves `true` iff an `ack`
   echoing exactly that token arrives. Never rejects, never self-times-out (§5.5 step 4 owns the
   timeout). Implement alongside `readyPromise` (`:35-42`); handle `t === 'ack'` in the `onmessage`
   chain (`:45-72`), which currently drops unknown `t` silently at `:69-71`.
3. Guest `buildRpc` (`youtube-guest.ts:24-70`) gains a matching `ack(token)` sender.
4. TDD: write `rpc.test.ts` first — right token resolves `true`; a *different* token leaves the
   promise pending (assert via `Promise.race` against a short timer).

**Done when:** both wire formats carry `ack`; round trip pinned in `rpc.test.ts`.
**Verify:** compare the wrong variable in the token check → the mismatch test goes red.

**Trap:** the two wire formats are hand-duplicated by design (spec §D9) and drift is **silent**. Task
6's T9 is what pins them together; this task must not assume it.

## Task 3 — decouple the cover (pure refactor, before the handshake)

**Spec:** §5.6, N5, N6. **Files:** `playerSingleton.ts`, its test. Test T10.

This is a **behaviour-preserving refactor of HEAD**. `onDomReady` still exists unchanged otherwise;
only the cover's trigger moves out of it.

1. Give the cover a handle: `cover.id = 'yt-player-cover'` (`:237-238`). It is currently an anonymous
   `<div>` appended between the webview and the spinner (`:262-264`) and a test would have to reach
   it positionally.
2. `dom-ready` arms `coverTimer` for `handshakeConfig.readyTimeoutMs` (add the config object here per
   spec §5.1, with its TSDoc — CLAUDE.md's documentation-for-trust rule applies to exported symbols).
3. Cover drops on **whichever comes first**: the guest's `ready` event, or `coverTimer` firing —
   **regardless of handshake outcome**. Remove the cover drop from the `Promise.race` at `:197-204`.
4. `refreshSpinner()` on every drop, as today. `destroyPlayer()` clears `coverTimer`.

**Done when:** T10 green — drops on `ready`, **and** drops after `readyTimeoutMs` when `ready` never
fires. **Verify:** make the drop conditional on handshake success → the timeout case stays covered.

**Observable:** initial `style.display` is `''`, and `'' !== 'none'`, so asserting `display === 'none'`
is meaningful without forcing the cover up first. Force to `'block'` only if the test wants the state
`load()` sets at `:304`.

**Trap — both directions are regressions:** dropping on `ack` reveals early (tried at `47a05f7`,
produced a "muted, plays 1s, then stops" flash, reverted — N5). Dropping only on
`ready`-or-*failure* leaves the cover up **forever** on a consent wall: `ready` never fires there and
the handshake **succeeds**, so neither branch fires (N6).

## Task 4 — publish only after ack (C1, C4, C6)

**Spec:** §5.1, §5.2, §5.4, §5.5, §5.8, §5.9. **Files:** `playerSingleton.ts`, its test.
Tests **T1, T4, T5, T6**.

The core of #213.

1. Add the §5.1 module state. Write **`resetCache()`** — it does not exist at HEAD (`rg resetCache`
   → 0 hits); extract the literal from `destroyPlayer()` (`:411`) so both callers share one
   definition. Add the inline comment explaining why it deliberately does **not** notify `stateCbs`.
2. Add `getURL(): string` to `WebviewElement` (`:34-40`) — without it `tsc` fails.
3. `teardown()` per §5.2, including the `pendingRpc` re-check ordering note. It clears `armWatchdog`
   and `coverTimer`. **This is #211's L1 fix** — the cache reset lands here, not in a separate task.
4. **`dom-ready` calls `teardown()` before `handshake()`** (§5.4). This is spec rev 3's resolution of
   the §5.4/§5.5 contradiction: a committed `dom-ready` *means* the old document is gone, so the
   entry check needs no `rpc` term.
5. `handshake()` per §5.5 — name every part, do not delegate: entry check `if (!wv) return` then
   `if (attempts++ >= handshakeConfig.maxAttempts) return void onHandshakeFailed()`; per-attempt
   token; build into `candidate`; transfer **inside a `try/catch`**; `await whenAck` **and use the
   result**; `retryLater()` (backoff `handshakeConfig.retryBackoffMs`); publish at step 6.
   `onHandshakeFailed()` emits exactly one `console.warn` carrying `webview.getURL()`.
6. Step 5 splits (§5.5): `seq !== handshakeSeq` ⇒ **abandon, no retry**;
   `!acked && seq === handshakeSeq` ⇒ `retryLater()`.
7. Invoke as `handshake().catch(e => console.warn('[player] handshake threw', e))`, **not**
   `void handshake()` — the body now has many throw sites and the suite fails on unhandled rejections.
8. `destroyPlayer()` calls `teardown()` (§5.8).
9. **§5.9:** `unmount()`'s `void rpc?.invoke('pause')` (`:296`) is a no-op whenever `rpc` is null —
   now a real window of up to `maxAttempts × ackTimeoutMs`. Add a `safeExec` pause-snippet fallback,
   or the pane closes with **audio still playing**, a regression against HEAD.

**Done when:** T1, T4, T5, T6 green.
**Verify:** T1 → ~~re-add `|| rpc` to the entry check~~ — **this mutation is inert; corrected during
execution.** Measured at `722cde1`: `if (!wv || rpc) return` passes 16/16, because `handshake()`'s
only two call sites are `dom-ready` (synchronously after `teardown()` nulls `rpc`) and `retryLater`
(reachable only when nothing published, and seq-guarded), so `rpc` is provably null at entry and the
term is dead code. The Verify line predates spec rev 3, which moved the fix from "delete the `rpc`
term" to "`dom-ready` calls `teardown()`". **The genuine falsifier is deleting `teardown()` from the
`dom-ready` handler** — i.e. restoring #213's actual design — which kills T1 alone. Both reviewers
confirmed the reachability argument independently. T4 → remove the `attempts++` check → unbounded
injects. T5 → drop the token comparison in `whenAck`. T6 → assign `rpc = candidate` at step 2.

**T4's observables:** `vi.spyOn(console, 'warn')` **filtered by message prefix** — `safeExec` (`:89`)
and `safeInsertCSS` (`:108`, `:111`) also warn, so an unfiltered spy counts the wrong calls.
**T6** needs a deferred ack: `fakeGuest(port, { ack: false })`, assert "before", then
`port.postMessage({t:'ack', token})`. The token comes from the recorded `postMessage` args — `await
vi.waitFor(...)` for the record, since `handshake()` awaits `safeExec` first.

**Trap:** merging step 5's two conditions is actively harmful. A superseded attempt that retries
re-arms the guest, and Task 6's `initPort` destroys the prior guest rpc — killing the guest end of a
channel the host already published, leaving `rpc` non-null with a dead peer. Exactly what C1 prevents.

## Task 5 — invalidate on navigation, with the paired watchdog (C2, C6)

**Spec:** §5.3, §5.7. **Files:** `playerSingleton.ts`, its test. Tests **T2, T3, T7, T11**.

1. `did-start-navigation` listener; on `isMainFrame && !isInPlace` → `teardown()` **and arm
   `armWatchdog`**.
2. On watchdog fire: re-enter `handshake()` against the current document, or emit the C6 diagnostic
   if there is no live document. **Never leave the null state unobserved.**
3. `load()` calls `teardown()` (**§5.7**), then raises the cover and reassigns `src` as today.

**Done when:** T2, T3, T7, T11 green.
**Verify:** T2 → drop `resetCache()` from `teardown()`. T3 → delete the `!isInPlace` term. T7 →
same as T2, via the `load()` path. T11 → delete the watchdog; the assertion must time out with the
channel dead and no diagnostic.

**Seeding order for T2 and T7 — get this wrong and both are vacuous:** the host attaches its `state`
listener only at publish, so the order is `dom-ready` → ack → publish → `emitState(…)` →
`did-start-navigation` (T2) or `load(B)` (T7). Emit a **full** `VideoFlags` payload;
`emitState({duration: 213})` alone leaves `currentTime` undefined, which `applyState` (`:115-117`)
writes straight into the cache.

**T7 lives in `playerSingleton.test.ts`**, not at hook level — `usePlayer.test.tsx` and
`PlayerPane.test.tsx` both `vi.mock('./playerSingleton')` wholesale, so the real cache never runs
there.

**Record T3 as a paired test** — it passes against an empty implementation and on HEAD; it is
evidence only alongside T2.

**Timers:** real timers with shrunken `handshakeConfig` values (`armWatchdogMs: 20`,
`ackTimeoutMs: 10`) plus `vi.waitFor`. **Do not use `vi.useFakeTimers()`** — `handshake()` awaits
`safeExec` (a real promise) and MessagePort delivery, and `rpc.test.ts:35-38` documents that
happy-dom groups zero-delay timeouts into one shared Node timer under `isolate: false`.
`handshakeConfig` is mutable module state: **save and restore** the fields each test changes.

**Why the watchdog is not optional** (§5.3): `did-start-navigation` fires unconditionally with no
commit check, while `DidFinishNavigation` early-returns on `!HasCommitted()`. Our own
`src/main/index.ts:296` cancels non-allowlisted guest navigations; 204/205s, `Content-Disposition`
downloads and BFCache restores are the other cases. Without the watchdog the player is silently dead
where HEAD works.

## Task 6 — idempotent guest, re-armable receiver (C5)

**Spec:** §6.1–§6.4. **Files:** `inject/youtube-guest.ts`, new `inject/youtube-guest.test.ts`. Test T9.

1. Sentinel-guard the IIFE: if `window.__linsaeGuest` exists → `arm(token)` and return.
2. Receiver (`:280-284`) keeps its listener for the document lifetime and re-arms the expected token
   instead of `removeEventListener`. Validate `e.ports.length === 1`.
3. **Do NOT add Electron's `event.source === window` check** (spec §6.2). Its recipe assumes the
   message originates from a preload in the same window; ours comes from the *host* via
   `contentWindow.postMessage`, so `e.source` will not be `window`. What it actually is under
   Electron 42 is **unverified** — copying the check could break the receiver outright.
4. `initPort` sends `ack(token)` as its **first act**, before any DOM work; `rpc.ready()` stays in
   `attachVideo()` (`:155`). `initPort` destroys any prior `rpc` first.

**T9 — execute the real guest.** Two harness facts, both measured, both fatal if missed:

- **happy-dom's `window.postMessage(data, '*', [port])` silently drops the transfer list**
  (`e.ports.length === 0`). The only working route is
  `window.dispatchEvent(new MessageEvent('message', { data: token, ports: [port2] }))`, which
  delivers a live port.
- **The counts are zero at injection time.** The IIFE registers exactly one `window` `message`
  listener; all three `setInterval`s, both `MutationObserver`s and the `keydown` stopper live inside
  `initPort` (`:186-277`), which runs only after a port arrives. So "inject twice, assert counts
  don't double" would measure nothing. The test must be: inject(token1) → deliver port → **snapshot
  counts** → inject(token2) → deliver port → assert the delta is the same, not doubled.

Then drive a real `createRpc` across a real `MessageChannel` against it and assert the ack
round-trips — pinning both hand-duplicated wire formats together for the first time. Assert the
receiver **honours** token2 by observing `initPort` run, not merely that `arm` was called with it.

**Verify:** remove the sentinel → the delta doubles. Change `{t:'ack'}` in *either* file → the round
trip fails.

**Why not a string assertion** (spec §8.2): `toContain('__linsaeGuest')` survives `if (false && …)`,
survives the sentinel being written but never read, and survives the identifier appearing only in a
comment.
