## 2. What the milestone does

Closes **#213** (the guest RPC channel latched to whichever document committed first — often a
consent wall — and never re-armed) and **#211** (the value cache outlived the guest, so video A's
duration was written to video B's `video_sources` row, **on disk**).

Contract clauses, all in spec §4: **C1** `rpc` non-null iff acked by the *currently committed*
document · **C2** every main-frame cross-document navigation invalidates channel + cache · **C3**
`ack` ≠ `ready` and neither is inferable from the other · **C4** an ack is honoured only if it
echoes the still-current attempt's token · **C6** never rest in a silent dead state.

## 3. Non-obvious facts (each cost real effort to establish)

- **The cover must key on `ready`-or-timeout, NEVER on `ack`.** Dropping on `ack` reveals YouTube's
  startup churn as a "muted, plays 1s, then stops" flash — shipped at `47a05f7`, reverted, tracked
  in #65 (spec N5). Dropping only on `ready`-or-*failure* leaves the cover up **forever** on a
  consent wall, where the handshake *succeeds* and `ready` never fires (N6). T10 has assertions that
  go red under both mutations; they were green under both until `824a7da` fixed it.
- **`load()` must call `teardown()`, not `rpc = null`.** Nulling does not bump `handshakeSeq`, so an
  in-flight attempt publishes the *outgoing* document's channel. Proven with two probes: #211's
  disk-corruption shape, and an N5 cover reveal.
- **The real §7 invariant is NOT hook order.** It is that *neither hook reads `getDuration()` during
  the effect phase* — both defer to a tick, and React flushes both effects in one commit.
  Unenforced, and T12 cannot catch its loss. **→ ADR 0065.**

  **CORRECTED during execution — the earlier rationale here was false.** This bullet used to say the
  hooks are "siblings across different docks … the side is user-assignable, so effect order flips
  with where the player sits." **The player's dock side is not assignable.** `homeDock: 'right'` is a
  static literal on the `player` entry of `PANES` (`panes/Pane.tsx`), `dockStore.ts`'s `openPane`
  only *reads* `pane.homeDock`, and the store exposes no move-between-docks action at all — its
  surface is `openPane` / `closePane` / `togglePane` / `setActive` / `setWidth` / `collapseSide` /
  `expandSide` / `toggleSide` / `hydrate` / `reset`. The sibling half is true and the ordering it
  produces is **fixed, not variable**: `ThreadView` renders inside `<main>` (`App.tsx`), which sits
  between the `side="left"` `DockHost` and the `side="right"` one, so `ThreadView`'s effects always
  flush *before* `PlayerPaneInner`'s.

  This makes the invariant matter **more**, not less. Under a variable order, a hook that read
  `getDuration()` during the effect phase would corrupt intermittently; under the real fixed order it
  would corrupt *every time*, because the reader (`ThreadView`) is deterministically ahead of the
  writer (`PlayerPaneInner` → `usePlayer` → `load()` → `resetCache()`). I originated the wrong claim
  and passed it to several task agents; it is recorded here rather than deleted so that a report
  quoting it can be recognised as inheriting the error.
- **`handshakeConfig` is exported mutable module state.** Tests must save/restore in `afterEach`.
- **Never `vi.useFakeTimers()` in these tests** — `handshake()` awaits `safeExec` and MessagePort
  delivery, and happy-dom groups zero-delay timeouts into one shared Node timer under
  `isolate: false`. Real timers + shrunken `handshakeConfig` + `vi.waitFor`.
- **`emitState` needs a FULL `VideoFlags` payload.** The spec's `emitState({duration: 213})`
  shorthand does not compile.
- **`tests/yt-fake-guest.ts` owns module-level guest state.** Any new file using
  `openGuest`/`connectGuest` must call `destroyGuests()` in `afterEach` or guests leak across files
  under `isolate: false`.
- **Citation form (#218):** prefer symbol / spec-§ references over `file.ts:123`. Six drift
  instances in this repo, three inside this milestone — including one commit that broke four
  citations the *previous* commit had just repaired.
