# v0.2 YouTube Annotation — Plan 3: Player + Thread UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the renderer UI for v0.2 — the YouTube player singleton + custom transport bar, the ThreadView (video-order rail + capture-order feed + sort toggle), the freeze-on-focus composer with ⌘⇧C screenshot capture, `remark-yt-timestamps`, scrubber markers + follow/jump-pill, `MediaFeedNote`, and URL-paste→video-note — all consuming the Plan 2 backend surface (`window.api.youtube/attachments/videoSources`, `app://` shell, source-field notes + `comment-on` edges).

**Architecture:** A module-level **player singleton** holds the YouTube `<iframe>` in a DOM node kept *outside* React's reconciliation tree (survives StrictMode double-mount). The rolling feed gains a `MediaFeedNote` variant for `type='source'` notes; opening one swaps the main view to a full **ThreadView** (player pinned at top, comment-notes below, composer pinned at bottom). All new IPC goes through new facade methods on `src/renderer/src/lib/api.ts`. Pure logic (URL parse, time format, rail clustering/gap math, the timestamp-syntax remark plugin, follow/jump-pill predicates) is extracted into unit-testable functions; React components get RTL component tests where feasible; the player/embed gets a manual + Playwright smoke (it needs a live Electron window + network).

**Tech Stack:** React 19 + TypeScript strict · `youtube-player@5.6.0` (BSD-3-Clause, **new dep** — see Decision D1) · `react-hotkeys-hook@5.3.2` (existing) · `react-markdown@10` + `unist-util-visit@5` (existing) · `lucide-react@1.16.0` (existing) · `@tanstack/react-query` (existing) · the v21 design tokens (inline `style` + CSS vars) · Vitest + RTL + jsdom · bare `playwright` `_electron` smoke.

**Scope:** This is **Plan 3 of 3** for the v0.2 milestone (spec: `docs/specs/v0.2-youtube-annotation.md`). Plan 1 (data layer) and Plan 2 (app:// shell + capture + media IPC + note-source persistence + comment-on edges) **shipped** (`184fddb`..`eb51dce`, suite 200 green). The annotation **drawing editor** (perfect-freehand strokes/text/SVG sidecar) is carved out to **v0.2.x** and is NOT in this plan.

## Decisions baked into this plan (resolved before writing)

- **D1 — Player library: `youtube-player@5.6.0` (BSD-3-Clause), prototype-gated.** It is a **new dependency** (CLAUDE.md hard gate → it is a deliberate, ADR-0008-recorded milestone dep, added in Task B1). It is ~3 years stale but wraps the IFrame Player API (stable since 2012); its methods are **Promise-based** (`await player.getCurrentTime()` etc.); its `host` option is **not in the package's TS types** (pass options via a typed wrapper / `as` assertion). The IFrame API **replaces** the target element with the `<iframe>`, so the detached singleton must hold a **stable wrapper parent** and create a disposable inner child as the YT target. **Task B1 is a prototype spike** that must confirm (a) the detached singleton survives StrictMode + the package's iframe creation, and (b) `iframe_api` loads when the document origin is `app://` — **before** the rest of the player group builds on it. If B1 fails, fall back to the **raw IFrame Player API** (zero-dep, our own thin wrapper) — the `Player` interface (B2) makes either implementation a drop-in. The vendoring fallback (if the npm package is later abandoned) copies the ~600 LoC into `src/renderer/src/yt/` **preserving the BSD-3-Clause copyright + disclaimer** (NOT relicensed MIT — the 2026-05-30 research doc's "MIT" was wrong; npm `license` field is BSD-3-Clause).
- **D2 — Hotkeys: keep `react-hotkeys-hook@5.3.2`** (existing). `⌘⇧C` = `useHotkeys('mod+shift+c', …)` with `enableOnFormTags` **omitted** so it does NOT fire while the composer textarea is focused (contrast the existing `mod+k` which opts in via `enableOnFormTags`). TanStack Hotkeys rejected (alpha 0.10.0, API unstable; its differentiators are irrelevant here).
- **D3 — Dev-mode attachment image URLs (prototype-gated, Task A2).** In prod the renderer document is `app://bundle`, so `app://bundle/_media/<…>.png` is same-origin (`img-src 'self'`). In **dev** the document is `http://localhost:<vite>`, so `app://…` images are cross-origin. **Default approach:** construct image URLs as `app://bundle/_media/<yyyy>/<mm>/<sha>.png` everywhere and add `app:` to the `<meta>` CSP `img-src` (harmless in prod — `'self'` already covers it; the `app://` handler's traversal guard confines what it serves). Task A2 **prototypes** that a dev `http://localhost` document can load an `app://` `<img>` with this CSP; **if the renderer blocks the cross-scheme load**, fall back to an IPC `readAttachmentDataUrl(path)` channel that returns a `data:image/png;base64,…` URL in dev only. The plan task picks based on the prototype.

/**
 * Playback-clock formatting for the transport bar, rail timestamps, the composer
 * chip, and MediaFeedNote durations. `m:ss` under an hour, `h:mm:ss` at/over.
 * @see docs/specs/v0.2-youtube-annotation.md §ThreadView / §Composer
 */
export function formatClock(seconds: number): string {
  const s = Math.max(0, Math.floor(seconds))
  const h = Math.floor(s / 3600)
  const m = Math.floor((s % 3600) / 60)
  const sec = s % 60
  const ss = String(sec).padStart(2, '0')
  return h > 0 ? `${h}:${String(m).padStart(2, '0')}:${ss}` : `${m}:${ss}`
}

/** Parses `m:ss` or `h:mm:ss` to seconds, or null if malformed (seconds 00-59). */
export function parseClock(text: string): number | null {
  const m = text.trim().match(/^(?:(\d+):)?(\d{1,2}):([0-5]\d)$/)
  if (!m) return null
  const [, h, mm, ss] = m
  return (h ? Number(h) * 3600 : 0) + Number(mm) * 60 + Number(ss)
}
```

/**
 * Module-level YouTube player singleton. The IFrame API REPLACES its target
 * element, so we hold a STABLE wrapper <div> at module scope and create a
 * disposable inner child as the YT target — the wrapper (and the iframe inside
 * it) survives React 19 StrictMode's double-mount because it lives outside the
 * React tree (the `instance` guard returns the existing player). usePlayer (B5)
 * re-parents the wrapper into the ThreadView DOM on mount.
 *
 * @see docs/specs/v0.2-youtube-annotation.md §Player subsystem (singleton, ADR 0008)
 */
import YouTubePlayer from 'youtube-player'
import type { Player, PlayerState } from '../../../shared/player'

let wrapper: HTMLDivElement | null = null
let raw: ReturnType<typeof YouTubePlayer> | null = null
let instance: (Player & { wrapper: HTMLDivElement; getIframeRect(): DOMRect | null; videoId: string | null }) | null = null

const STATE: Record<number, PlayerState> = { '-1': 'unstarted', 0: 'ended', 1: 'playing', 2: 'paused', 3: 'buffering', 5: 'cued' }

/** Returns the singleton, constructing the detached wrapper + player on first call. */
export function getPlayer() {
  if (instance) return instance
  wrapper = document.createElement('div')
  wrapper.id = 'yt-player-wrapper'
  wrapper.style.width = '100%'
  wrapper.style.height = '100%'
  const target = document.createElement('div') // youtube-player replaces THIS with the iframe
  wrapper.appendChild(target)
  // `host` is forwarded to YT.Player but absent from youtube-player's TS types → assert.
  raw = YouTubePlayer(target, {
    host: 'https://www.youtube-nocookie.com',
    playerVars: { enablejsapi: 1, controls: 0, rel: 0, playsinline: 1 },
  } as Parameters<typeof YouTubePlayer>[1])
  raw.getIframe().then((f) => f?.setAttribute('referrerpolicy', 'strict-origin-when-cross-origin'))
  let videoId: string | null = null
  instance = {
    wrapper,
    get videoId() { return videoId },
    async load(id) { videoId = id; await raw!.loadVideoById(id) },
    play: () => raw!.playVideo() as Promise<void>,
    pause: () => raw!.pauseVideo() as Promise<void>,
    seekTo: (s) => raw!.seekTo(s, true) as Promise<void>,
    getCurrentTime: () => raw!.getCurrentTime() as Promise<number>,
    async getDuration() { const d = (await raw!.getDuration()) as number; return d > 0 ? d : null },
    setPlaybackRate: (r) => raw!.setPlaybackRate(r) as Promise<void>,
    onStateChange(cb) {
      const handler = (e: { data: number }) => cb(STATE[e.data] ?? 'unstarted')
      raw!.on('stateChange', handler)
      return () => raw!.off(handler)
    },
    getIframeRect() {
      const f = wrapper!.querySelector('iframe')
      return f ? f.getBoundingClientRect() : null
    },
    destroy() { destroyPlayer() },
  }
  return instance
}

/** Tears down the singleton (test cleanup + app teardown). */
export function destroyPlayer(): void {
  raw?.destroy()
  wrapper?.remove()
  raw = null
  wrapper = null
  instance = null
}
```

> The `instance.videoId`/`getIframeRect` extras (beyond the `Player` interface) serve the ⌘⇧C capture + timestamp-seek flows. They live on the concrete singleton, not the cross-impl `Player` type.

```ts
import { useEffect, useRef, useState } from 'react'
import type { PlayerState } from '../../../shared/player'
import { getPlayer } from './playerSingleton'

/** Mounts the singleton into `hostRef`, loads `videoId`, exposes a coarse playhead tick. */
export function usePlayer(videoId: string, hostRef: React.RefObject<HTMLElement | null>) {
  const [currentTime, setCurrentTime] = useState(0)
  const [state, setState] = useState<PlayerState>('unstarted')
  const [duration, setDuration] = useState<number | null>(null)
  const playerRef = useRef(getPlayer())

  useEffect(() => {
    const player = playerRef.current
    hostRef.current?.appendChild(player.wrapper)
    player.load(videoId)
    player.getDuration().then(setDuration)
    const unsub = player.onStateChange(setState)
    let raf = 0
    let last = 0
    const tick = (ts: number) => {
      if (ts - last > 200) { last = ts; player.getCurrentTime().then(setCurrentTime) }
      raf = requestAnimationFrame(tick)
    }
    raf = requestAnimationFrame(tick)
    return () => { cancelAnimationFrame(raf); unsub() } // singleton persists; only this view's listeners stop
  }, [videoId, hostRef])

  return { player: playerRef.current, currentTime, state, duration }
}
```
